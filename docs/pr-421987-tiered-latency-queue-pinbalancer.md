# tiered-latency-queue-pinbalancer-adapter

Problem: Continuous-batcher workloads with mixed KV-cache and compute-heavy requests still show periodic starvation of latency-sensitive requests under sustained load in multi-tenant nodes. Previous fairness knobs reduced mean tail but regressed throughput for bursty KV-heavy traffic. Motivation: we need a scheduler layer that (1) preserves strict latency SLOs for latency-tiered requests, (2) prevents indefinite starvation of low-priority KV pin requests, and (3) minimizes end-to-end throughput loss. This PR introduces the Tiered Latency Queue Adapter (TLQA) and a complementary Pin Balancer module that cooperatively manage admission and slot allocation in the continuous-batcher runtime. TLQA creates soft priority tiers (fast, normal, background) with time-budgeted fast lanes. Fast-lane requests get preferential early admission but can be demoted after a configurable accrue-time threshold to avoid permanent starvation of background work. The Pin Balancer monitors KV-pin hot-spots and performs bounded pin-relocation and soft-eviction with hysteresis to allow prefetch/kv-cache warmup while avoiding long-lived pins monopolizing slots. Key behavior: - Fast-tier admission uses a short-lived reservation window (default 2ms) per epoch; if fast-tier requests fail to complete in that window the reservation decays exponentially to free capacity. - Demotion: requests older than demote_ms (default 40ms) in fast/normal tiers are moved to background to ensure forward progress. - Pin Balancer keeps per-key low-water marks and issues bounded unpin commands when local slot occupancy exceeds pin_occupancy_threshold (default 0.7). Unpin is cooperative: the runtime asks the KV cache manager for best-effort unpin; if the manager cannot unpin within unpin_grace_ms the slot is force-rotated and the request allowed to continue on a fallback model variant. Implementation highlights: - Scheduler: new adapter layer (tlqa_adapter.cc/h) that sits between the admission controller and the batcher. It tracks per-tier counters, reservation tokens, and decays tokens using a lightweight exponential-backoff timer wheel. - Pin Balancer: pin_balancer.{cc,h} with an async RPC to the kv-cache manager; leverages existing metrics and tracing hooks (metrics: tlqa.reservations.*, pinbalancer.unpin.*) - Kernel selection hints: the adapter surfaces hints for short sequence fast-path kernels (small_seq_kernel) when a fast-tier reservation is used; this reduces kernel invocation overhead for short responses. - Telemetry: new per-route histograms (tlqa.latency_by_tier) and alerts when pin eviction rate > 5%/minute. Tests and validation: - Microbench: synthetic mix (30% fast, 50% normal, 20% KV-pinned) across 8-node canary; result: 99th p50/p95 improvements for fast tier: p95 down 18% and p99 down 12% compared to master under same load; overall throughput loss < 2.5%. - Stress: long-run soak (72h) on perf-canary with KV hotkeys: no request starvation observed; tail spikes reduced. - Integration: added unit tests for adapter token decay, demotion and pin balancer unpin backoff; end-to-end e2e test harness added to perf-canary suite. Rollout plan: staged canary across regions (us-west-2, eu-west-1) with TLQA disabled by default on main; enable per-customer via runtime flag and smoke test on dedicated nodes. Config knobs exposed: tlqa.enabled, tlqa.fast_reservation_ms, tlqa.demote_ms, pinbalancer.enabled, pinbalancer.unpin_grace_ms, pinbalancer.occupancy_threshold. Related work: builds on prior queue fairness work (ENG-1980) and KV warmup heuristics. See Linear ENG-1982 for acceptance criteria and performance targets.
