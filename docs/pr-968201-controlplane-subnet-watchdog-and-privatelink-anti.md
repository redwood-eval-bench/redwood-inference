# Controlplane subnet watchdog and Privatelink anti-affinity allocator

Context: Customers running Redwood Private in multi-AZ VPCs observed two classes of outages: (1) controlplane pods scheduled into subnets that became partially unreachable due to transient route table/state drift and (2) Privatelink endpoint placement concentrating endpoints into a single AZ during upgrades which increased failure blast radius. This PR implements two complementary automation features to reduce operational toil and enable safer upgrades: 1) a lightweight controlplane-subnet-watchdog daemonset that monitors per-subnet L3 reachability and annotated controlplane resources with a readiness fingerprint to drive safer rollouts; 2) a Privatelink anti-affinity allocator inside the installer/terraform modules that prefers AZ-spread endpoint provisioning and annotates endpoints with placement metadata for downstream routing policies. What changed (high level): Updated Terraform modules (networking/subnet-allocator, privatelink) to expose new tags/labels for affinity and to add a placement API surface used by the installer. Added a Helm chart hook and a daemonset image for the subnet-watchdog (k8s manifests under helm/controlplane-watches). Introduced a reconciliation hook in the installer that can mark subnets as "quarantine" and trigger staged rescheduling of controlplane components; added an opt-in feature-flag and a safe rollback path. Testing and validation: unit tests for the allocator algorithms, terraform plan/validate CI job, and a new e2e suite that simulates AZ route flapping and validates that the watchdog quarantines affected subnets and the installer redistributes controlplane endpoints across remaining AZs. Rollout plan: default flags are OFF for existing installations; when enabled the allocator runs in a dry-run mode for two weeks to emit telemetry before taking action. On GKE/PKS on-prem variants the installer falls back to best-effort placement when cloud APIs are not available. Rollback: the daemonset honors a "watchdog.disable" annotation to immediately stop quarantine actions; the installer supports an immediate revert of allocation state and a staged re-attach of endpoints. Security & permissions: minimal IAM changes in Terraform to allow reading AZ/subnet attachment state and tagging endpoints; documented least-privilege policy in docs/iam/privatelink-roles.md. Migration notes: existing clusters will see no behavioral change until the feature-flag is enabled; enabling in single-AZ clusters is a no-op for anti-affinity. Why this approach: prefer small, observable automations that fail open by default and provide clear telemetry to SREs; avoid hard remediations without operator approval. Caveats: we cannot guarantee coordination with third-party cloud controllers in all edge cases — the quarantine is conservative to avoid unnecessary flapping. Related tickets: ENG-1829 (subnet heal), ENG-1975 (privatelink placement), SUP-4271 (customer incident).
