# rescue-partial-json-frames-and-sticky-delimiter-guards

Background: We continue to see production traces where streaming responses (SSE) emit JSON fragments split mid-structure and interleaved by heartbeats or auxiliary events. This leads to two classes of customer-visible failures: 1) partial JSON objects being forwarded to SDKs which then throw parse errors / discard tokens; 2) event delimiters ("\n\n"/event markers) being duplicated or stuck to the next payload and breaking client reassembly heuristics. Motivation: Previous PRs addressed chunk coalescing and delimiter ordering but did not prevent a pathological case where a delimiter byte sequence becomes 'sticky' to the following event after a retry/backpressure window, or where sequence holes allow reordering when small windows are replayed. This PR proposes a defensive sanitizer at the SSE boundary plus a lightweight reassembly index to guarantee idempotent reconstruction of JSON frames and preserve function/tool-call sentinels.

What this change does (single-string summary): Adds an SSE boundary sanitizer that normalizes trailing delimiters, a sequence-hole detector that rejects out-of-order apply windows and requests replay, a small reassembly index for ongoing streams to ensure JSON object boundaries are not emitted until complete, and targeted SDK compatibility tweaks to avoid raising parse errors for temporarily incomplete structured outputs.

Implementation highlights: - sse/parser.go: introduce boundarySanitizer that trims repeating delimiters, collapses \r/\n variants, and tags frames with a local assembly id. - sse/stream_manager.go: add per-stream reassemblyIndex and hole detection (lastSeenSeq) which triggers a gated replay path when seq mismatch detected. Replay path is conservative: re-request missing chunks from the producer, reapply cached partials. - sdk/python/openai_compat/streaming.py: tolerate "incomplete-json" interim tokens by buffering until the server emits an assembly-commit marker; previously the SDK raised JSONDecodeError. - tests/sse_fuzz_test.go + tests/integration/sse_replay_test.py: new deterministic fuzz harness and an integration test that simulates delimiters split at UTF-8 boundaries, heartbeat interleaves, and backpressure-triggered replays. - docs/sse-framing.md: new doc describing the sanitizer heuristics and runtime knobs (sanitizer.threshold, replay.window, assembly.commit-timeout).

Why this approach: Conservative server-side enforcement avoids pushing parsing complexity into every SDK and reduces noisy client errors. The reassembly index is intentionally small (per-stream, bounded by 32 partial frames) to keep memory overhead minimal. The sanitizer heuristics are tunable and guided by production traces included in the linked Linear items.

Compatibility notes: - Minted a short-lived assembly marker (\u0002ASSEMBLY_COMMIT\u0002) in the SSE stream that SDKs will ignore as a control sentinel but use to flush buffered frames. This marker is additive and does not alter existing valid streams. - Backwards-compatible: servers will not drop or mutate user payload bytes; we only reorder/emulate replays when we detect missing sequence windows.
