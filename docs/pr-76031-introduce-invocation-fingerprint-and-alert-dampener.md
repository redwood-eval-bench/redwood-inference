# Introduce invocation-level latency fingerprinting and alert dampener

Added invocation-level fingerprinting for latency attribution, a new compact span denormalizer, and an alert dampener configuration to reduce noisy SLO flaps. No API breaking changes. Requires runtime config rollout to enable by default.
Summary: Adds an invocation-level latency fingerprinting component that computes a compact 64-bit fingerprint for request patterns, a compact span denormalizer that materializes only the attributes necessary for attribution panels, and an alert dampener that suppresses short-lived SLO violations on noisy routes.
Motivation: We see repeated alert churn driven by milli-second-level variance in small routes and heavy noise from rare token-paths. This change aims to 1) pinpoint invocation cohorts that drive sustained SLO degradation, 2) reduce cardinality and storage cost of span-backed rollups, and 3) avoid noisy alert-trigger cycles for known bursty endpoints.
Changes included: - telemetry/fingerprint: new fingerprinting implementation with rationale and microbenchmarks. - telemetry/denormalizer: new compact denormalizer that converts spans->attribution records with optional field selectors. - telemetry/alert-dampener: new policy engine for dampening alerts based on cohort persistence and weighted burn rate. - console: new dashboard panels (Invocation Cohort Explorer, Dampened SLO Timeline) and documentation for activation. - integration tests and unit tests covering fingerprint collisions and dampener thresholds.
