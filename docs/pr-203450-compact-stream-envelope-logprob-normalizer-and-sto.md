# compact stream envelope + logprob normalizer and stop-token safety adapter

Motivation: Close parity gaps with OpenAI /v1/chat.completions for production streaming and structured tool outputs while avoiding protocol bloat. This PR introduces a compact stream envelope (v2) to reduce event size and negotiation overhead, a logprob normalizer to provide consistent numeric semantics across float32/float16 backends, and a stop-token safety adapter to sanitize ambiguous stop sequences coming from third-party models. Changes include API adapters, runtime parsing, docs, and tests. Checklist: [x] compact envelope wire format and version negotiation; [x] stable streaming backpressure hooks; [x] deterministic logprob normalization and rounding; [x] stop-token sanitizer with whitelist/blacklist rules; [x] telemetry to track envelope fallbacks; [x] unit and integration tests; [x] docs and migration guide. Summary of behavior: 1) Stream envelope v2 collapses repeated metadata into a single header frame and encodes structured tool outputs with a content-type tag (example: "Content-Type: application/vnd.redwood+json; version=2"). Clients negotiate using a short handshake header ("X-RW-Stream: v2") and fallback to v1 if not present. 2) Logprob normalizer: server normalizes token logprobs to float32 precision then emits a stable rounding to 6 decimal places in JSON to avoid downstream diffs from float16 quantization. If client requests raw_logprobs=true we include the original float as an extra field raw_logprob_n32 for audit. 3) Stop-token safety adapter: sanitizes multi-byte and whitespace-only stops, strips zero-width chars, collapses repeated stop arrays, and enforces a max-stop-length policy configurable by the API. Compatibility and fallbacks: default behavior preserves current outputs unless client opts-in to compact envelope or logprob_normalize=true. For older clients we still emit v1 framing and legacy stop semantics. Performance: envelope v2 reduces per-frame overhead by ~18% in internal bench; the normalizer adds ~0.2ms per-response on p3-class hardware. Tests and CI: added unit tests for envelope handshake, fuzzing tests for stop sanitizer, and replay tests to assert stable logprob serialization. Deployment plan: feature-flagged rollout for two weeks, enable telemetry, and auto-fallback if >1% of requests encounter framing parse errors. Docs: migration guide added at /docs/api/migration/streaming-v2 (see PR link), and examples in SDKs updated.
Alex Chen (reviewer): Can you explain the decision to round to 6 decimal places for logprobs instead of emitting full float? Is there an opt-out?
Sofia Alvarez (author): Rationale: 6 decimals is enough to preserve ranking decisions while eliminating noisy diffs from float16 backends. There is an opt-in raw_logprobs=true which will include raw_logprob_n32 for auditing; we avoid sending full 32-bit binary blobs in the default path to keep response sizes small.
Marcus Bell (reviewer): stop sanitizer is conservative but we saw one model produce a control character stop sequence. How do we avoid accidentally stripping intentional markers?
Sofia Alvarez (author): We whitelist ASCII punctuation and alphanumerics by default; the config allows tenant-level overrides. The sanitizer logs anonymized samples to a secure bucket for review before policy changes.
Drew Patel (reviewer): CI flakes in the bench job on GPU allocation; can we make the benchmark job non-blocking?
Sofia Alvarez (author): Marked as non-blocking in ci config and added a gating job that runs only on weekly windows.
