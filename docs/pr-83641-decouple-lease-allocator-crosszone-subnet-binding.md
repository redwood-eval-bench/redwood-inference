# Decouple lease allocator and add cross-zone subnet binding for GPU nodepools

Motivation: private installs with tightly-coupled GPU pool state were causing long terraform plans and contention during tenant onboarding. This PR splits the lease allocator (tenant GPU lease lifecycle) into an independently versioned terraform module and introduces cross-zone subnet binding so tenant leases can be satisfied across AZs without manual subnet reconfiguration. Design: 1) modules/lease-allocator becomes a standalone module exposing lease table, IAM bindings, and a small controller CRD input for the installer chart. 2) modules/gpu-nodepool gains a 'subnet_bindings' input which accepts a prioritized list of subnet ids per AZ; the module generates per-zone attachments and a lightweight routing policy. 3) We introduce scripts/tfstate-handoff.sh which orchestrates state moves (terraform state mv + backend lock handling) from the legacy combined tfstate to tenant-scoped statefiles. 4) Installer chart values updated to reference the new module outputs and the operator-facing migration toggle. Rollout and migration plan: a) Deploy the new installer chart with migration=enabled in a maintenance window. b) Run scripts/tfstate-handoff.sh in dry-run to validate moves. c) Run the handoff script to move state and reapply the new modules. d) Observe nodepool provisioning with canary tenant before full rollout. Backout: the handoff script supports a safe revert plan: it checkpoints state backups and can reverse state moves in case of issues. Testing: unit tf plan/test for modules, integration test that simulates two tenants competing for GPU leases across two AZs, and an e2e smoke test to validate subnet failover. Security: IAM reshuffle minimal and scoped to tenant roles; included policy tightening for assume-role bindings. Migration docs and checklist added. Checklist: [x] terraform module + tests, [x] handoff script, [x] installer values, [x] docs, [x] reviewer approvals. Context/related: complements ENG-1740 (gpu scheduler pressure fixes) and is preparatory work for upcoming per-tenant metrics export.
