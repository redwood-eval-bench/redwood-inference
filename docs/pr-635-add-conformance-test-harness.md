# Add SDK parity conformance harness + fixtures (retries/timeouts/stream interruptions)

Summary: This PR integrates the shared SDK parity conformance harness into redwood-sdk-go and adds the initial fixture set covering: (1) retryable HTTP responses (429/5xx) including Retry-After parsing, (2) network/transient transport failures, and (3) streaming interruptions (server FIN mid-event / partial chunk) with consistent typed error shape and request_id propagation. Motivation: During the SDK parity initiative, we’ve repeatedly found cross-language drift in edge-case behavior (esp. Retry-After handling and streaming disconnect surfacing). The goal of this harness is to make the Go SDK run the same behavioral tests as Python/TS so we can catch mismatches in CI before release. Scope/details: - Adds an internal conformance runner that spins up an httptest.Server and replays scripted responses from fixtures under testdata/conformance/fixtures/*.json. - Adds a deterministic fake clock + backoff recorder so tests assert retry timing windows (vs exact sleeps). - Adds fixtures for: * 429 with Retry-After (seconds) and Retry-After (HTTP-date) * 500/502/503 retry behavior (bounded attempts, jitter window) * transport errors (dial tcp refused, context deadline exceeded, io.ErrUnexpectedEOF) classification as retryable vs terminal * streaming disconnects: mid-event EOF, truncated JSON payload, and proxy-like half-close behavior (client sees io.EOF while parsing SSE/data lines). - Plumbs request_id capture from response headers into the harness assertions (aligns with INT-1182 request_id visibility). What this PR does NOT do: - Does not change default retry/backoff settings (handled in PR #612) - Does not change public error types (handled in PR #624); this harness simply asserts current taxonomy stays aligned with the standard - Does not add any telemetry/logging (tracked separately in ENG-5129) Implementation notes: - The harness uses a Scenario file format shared across SDKs conceptually, but implemented in Go as a small parser over JSON fixtures with strict validation. - Streaming tests use chunked transfer encoding and a controllable writer that can: flush partial frames, close mid-write, and optionally omit the final '\n\n' SSE delimiter to simulate proxy truncation. - Retry tests do not sleep; they intercept the backoff function via an injected BackoffStrategy interface in internal/testutil and record requested delays; assertions check delay grows exponentially and stays within jitter bounds, and that Retry-After overrides computed backoff when present. CI: - Adds a new GitHub Actions job 'go-conformance' that runs 'go test ./... -run Conformance' on pull requests and main. - The job is marked required for merge (per ENG-5127). Testing: - go test ./... -run Conformance - go test ./... (full suite) - Validated locally that the 429 Retry-After (HTTP-date) fixture reproduces SUP-29477’s historical bug (previous code ignored date format; now asserted in tests; implementation already fixed in #612). Follow-ups: - Extend fixture coverage to include: 409 idempotency guidance (non-retryable), 408/499 semantics, and streaming cancellation (client-initiated) vs disconnect (server/proxy). - Once Python/TS runners are fully wired, we should align fixture names/IDs 1:1 and publish a small README in the shared conformance plan repo. Screenshots/logs: Example assertion output when Retry-After is not respected: "expected first retry delay to be derived from Retry-After=2s, got 400ms" (see ConformanceRetry429RetryAfterSeconds). Example assertion output when stream disconnect does not surface request_id: "expected error.request_id != ''" (see ConformanceStreamDisconnectMidEventEOF).
Go SDK: adds cross-language conformance tests for retry/backoff (429/5xx + Retry-After), network error classification, and streaming interruption error surfaces. No customer-facing API changes; test-only + internal harness.
