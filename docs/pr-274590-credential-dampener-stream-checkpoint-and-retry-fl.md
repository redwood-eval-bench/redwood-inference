# credential-dampener-stream-checkpoint-and-retry-floor

Motivation: Multiple customers reported intermittent token churn + bursty retry storms when streaming clients reauth concurrently. This PR introduces a lightweight 'credential dampener' in the Go SDK runtime and a small set of ergonomics and parity fixes aligned with the TypeScript and Python SDK teams: 1) credential dampener: coalesces rapid credential refreshes for concurrent consumers and exposes a small backoff jitter window to reduce synchronized reauth. 2) stream checkpoint tokens: allow streaming consumers to persist small opaque checkpoint tokens for resumability across transient reconnects. 3) retry-floor policy: new default retry profile adds a minimum backoff floor and caps immediate fast-retries to avoid token-thrashing loops. 4) ergonomics: clearer client ctor options (CredentialStrategy, StreamResumeHook) and improved docstrings. 5) cross-SDK parity: bump and document canonical retry profile names ("retry-floor" / "retry-standard"), and coordinate version bumps with py/ts (see linked Linear tasks). Implementation notes: credential dampener is an in-process, per-client optional component that keeps an LRU of recent refresh requests and returns a shared pending refresh promise when thresholds are hit. Stream checkpoint is intentionally opaque (byte blob) to avoid coupling with server internals; SDK only stores/returns the token to the user on graceful shutdown/resume hooks. The retry-floor profile is conservative (min backoff 250ms, multiplicative 1.6). Backwards compatibility: off by default for existing clients but enabled for new clients created via the new option in this PR. Migration notes: users with custom retry loops can opt into the profile or leave existing behavior; stream checkpointing is additive and only used when consumer provides a resume token handler. Testing: unit tests for dampener concurrency, integration run against a local staging harness that simulates concurrent reauth and streaming reconnects. Observability: added debug metric sdk_cred_dampener_coalesced_count and trace spans around credential handoffs. Docs: inline examples included in README and CHANGELOG. Related work (Linear): ENG-1129, ENG-1180.
