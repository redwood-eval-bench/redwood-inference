# Add integration tests for tampered offline bundles (fail closed)

Context: As part of offline bundle signing + verification, we need high-signal integration tests that simulate real customer failure modes (tampering during transfer, swapped artifacts, partial copies) and ensure the installer preflight fails closed with actionable errors. This PR adds an integration test suite that generates/uses a minimal signed test bundle fixture and then applies targeted corruption steps: (1) modified manifest contents (JSON canonicalization changes + byte edits), (2) swapped artifact file while leaving manifest unchanged, (3) truncated bundle archive (simulating partial rsync/usb copy), and (4) missing signature file for detached layout. Each scenario asserts that `installer preflight` exits non-zero, emits the expected error code, and does not proceed to any install step. The suite also verifies that the error taxonomy remains stable (Support can map failures) and that logs include the verification reason without dumping sensitive bundle contents. Notes: The tests intentionally avoid any network usage and use a temporary isolated work dir to ensure they run in CI with outbound disabled. Related: ENG-4827, ENG-4823. Support context: SUP-31892 (hash mismatch after transfer) informed the truncated/corrupted archive coverage.
