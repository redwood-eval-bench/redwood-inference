# Add audit export status endpoint + health summary for Console

Context: Console needs a single, tenancy-safe API to render SIEM Audit Export health (lag, last success, last error) for the beta cohort. Exporter already emits metrics and maintains checkpoints, but Console cannot safely query Prometheus and we don’t want to expose exporter internals directly. This PR adds a control-plane endpoint that returns a per-tenant summary derived from exporter status + persisted checkpoints, with short TTL caching to protect the exporter/control plane from noisy UI refreshes. What’s in this PR: (1) New endpoint: GET /v1/audit-exports/status (feature-flagged; requires audit_exports.status:read) that returns: overall enabled/paused state, export_lag_seconds, last_success_at, last_attempt_at, last_error (normalized code + safe message), and per-destination health (adapter type + last_success/last_error). (2) Tenancy + RBAC checks: scope is derived from the caller’s workspace/tenant in auth context; optional workspace_id param is validated to belong to the tenant; rejects cross-tenant reads even for org admins; permission gate matches the new RBAC bundle work (view status but not secrets). (3) Caching: in-process cache keyed by (tenant_id, workspace_id) with TTL=15s and jitter; cache entries are invalidated on export config updates (create/update/delete/rotate) via existing config change event bus hook; adds a circuit-breaker style fallback that returns cached (stale=true) for up to 2 minutes if exporter status fetch is timing out (to keep Console responsive during downstream incidents). (4) Status aggregation logic: control plane queries exporter “/internal/status” endpoint via service auth (mTLS) and merges with checkpoint rows in control plane DB (audit_export_checkpoints) to compute lag (now - last_checkpoint_event_ts) and to avoid reporting lag=0 when exporter is down but checkpoints are old. (5) Safe error normalization: adapter error strings are mapped to a small enum set (AUTH_FAILED, DEST_RATE_LIMITED, DEST_UNREACHABLE, DEST_FORBIDDEN, CONFIG_INVALID, INTERNAL) and messages are truncated/redacted to avoid leaking tokens/URLs; destination hostnames are omitted for Splunk/Datadog adapters and only S3 bucket ARN prefix is shown. (6) Tests + docs: unit tests for tenancy/RBAC, lag computation, stale-cache fallback, and redaction; added OpenAPI schema + example response; added Console integration notes in /docs/internal/console/audit-export-status.md. API response example (shape only): {"workspace_id":"ws_...","enabled":true,"paused":false,"export_lag_seconds":42,"last_success_at":"2025-04-15T21:03:11Z","last_attempt_at":"2025-04-15T21:03:41Z","last_error":{"code":"DEST_RATE_LIMITED","message":"downstream throttling (429)"},"destinations":[{"id":"dest_...","type":"splunk_hec","health":"degraded","last_success_at":"...","last_error":{"code":"DEST_RATE_LIMITED","message":"..."}}],"stale":false}. Rollout / gating: endpoint is behind feature flag audit_export.status_endpoint (tenant allowlist continues to be managed by the existing beta allowlist). Console will use this endpoint only when audit_export.beta_enabled is true, otherwise the UI remains hidden. Observability: added metrics redwood_control_plane_audit_export_status_cache_hits_total, ..._misses_total, ..._fetch_latency_ms, ..._stale_served_total; added structured logs with request_id, tenant_id, workspace_id (hashed), and result (ok/stale/error). Notes for SRE: exporter status fetch has a 750ms timeout with 2 retries (full jitter backoff) and will not page on failure by itself; paging continues to be based on exporter lag SLO, not UI status. Security considerations: no secrets are returned; error normalization redacts known token patterns and strips querystrings from URLs; tenancy guardrails prevent enumerating destination IDs across workspaces. Follow-ups (not in this PR): (a) Console: wire status endpoint into the settings page (DES-311/ENG-5177), (b) Status history: store time series for “last 24h failures” (out of beta scope), (c) Private deployments: status fetch mechanism differs (no direct exporter endpoint) and will be handled in ENG-5202.
