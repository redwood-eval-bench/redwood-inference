# Include offline observability artifacts in air-gapped bundle + update manifest

Context: Several on-prem / air-gapped Private installs reported Grafana coming up without any Redwood dashboards after install/upgrade because the offline bundle did not include the minimum-pack dashboard JSONs and Prometheus rules (SUP-49210, Slack thread: airgap-bundle-missing-grafana-dashboards). This PR updates the air-gap bundle build so the observability artifacts are shipped as first-class, versioned bundle contents. What changed: (1) add observability artifacts to the airgap bundle payload: Grafana dashboard bundle (runtime + control plane), Prometheus alerting/recording rules, and default log collector configs; (2) update the bundle manifest schema usage to explicitly list these artifacts under the 'artifacts' section with stable filenames and SHA256s; (3) wire extraction/install into post-unpack steps so upgrades can safely rehydrate dashboards/rules without requiring outbound fetches; (4) add a lightweight validation step in the bundle build pipeline to fail if any referenced observability artifact path is missing. Notes/constraints: No customer data is embedded; artifacts are static JSON/YAML shipped with the installer. This does not enable/disable observability components by default; it only ensures the offline bundle contains the required files when customers enable the minimum pack via Helm values. Backward compatibility: Existing bundle consumers continue to work; new manifest entries are additive. Follow-ups: noise tuning and runbook links live in the observability-pack rules PRs; this PR only handles packaging and offline delivery.
Fatima Noor (review): Can we confirm the bundle build does not attempt to fetch dashboards from the internet at build time? Air-gapped customers won’t have that option and our internal build sometimes runs in restricted networks too.
Connor O'Brien (author): Yep — all files are sourced from the repo under packaging/airgap/artifacts/observability. The build script only copies local files + computes sha256. I added a CI assertion to fail if any path is missing so we don’t silently produce an incomplete bundle.
Chloe Martin (review): Dashboard filenames: please keep them stable and versioned; Grafana provisioning can be sensitive if we rename on upgrades. Suggest prefixing with private-min-pack-v1-*.json and keeping a top-level index file optional.
Connor O'Brien (author): Done. Renamed to private-min-pack-v1-runtime.json, private-min-pack-v1-control-plane.json, and private-min-pack-v1-infra.json. Also updated the manifest entries so the artifact IDs are stable even if we add more dashboards later.
Kevin Osei (review - security): Log configs: please double-check we’re not shipping example configs that encourage logging request payloads by default. Also ensure the manifest doesn’t include anything that looks like a secret (tokens, endpoints).
Connor O'Brien (author): Good catch. The shipped collector config is the baseline redaction-safe config (no body logging; includes request_id and hashed tenant_id only). No endpoints/tokens in the repo artifacts — sinks are documented as placeholders only. Updated docs to explicitly call out that secrets must be provided via Kubernetes Secrets.
Rafael Mendes (review - SRE): Can we add a simple post-unpack check that surfaces a clear error if dashboards are missing? This would have saved us time in SUP-49210.
Connor O'Brien (author): Added installer/post_install/validate_bundle_contents.sh and wired it into the airgap smoke test. It fails fast with a list of missing artifact paths and points to the on-prem runbook section.
Diego Santos (review): Upgrade behavior: we should avoid overwriting customer-modified dashboards if they’ve edited them in-cluster. Are we writing into a separate directory that Helm picks up, vs pushing directly into Grafana via API?
Connor O'Brien (author): We only extract into the installer’s shared artifacts directory (used by Helm chart provisioning). We’re not pushing to Grafana APIs. Customer customization in-cluster remains their responsibility; our extracted bundle is treated as immutable inputs to provisioning.
