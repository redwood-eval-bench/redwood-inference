# introduce-fragment-gatekeeper-and-terminal-escape-rewrite-for-sse-stability

Summary: This PR introduces a 'fragment gatekeeper' and rewrites terminal-escape handling in the SSE pipeline to eliminate cases where partial JSON objects or duplicated delimiters were emitted to clients. Motivation: Multiple production incidents (see ENG-7894) revealed two related failure modes in the SSE stream adapter: 1) when a JSON payload boundary was split across TCP/SSE fragments our previous heuristics sometimes emitted a partial JSON chunk to the client which broke downstream JSON parsers; and 2) terminal delimiter tokens (

 and event terminators) could be duplicated when the adapter retried or replayed buffered fragments during backpressure recovery, resulting in double-sentinels and malformed event sequences. Objectives: make boundary detection deterministic, ensure no partial JSON blobs are emitted, de-duplicate terminal delimiters during replay, and keep OpenAI-compatible sentinel semantics intact for function/tool-call handoffs. Implementation: - Add runtimes/sse/fragment_gatekeeper.rs: a compact state machine that classifies incoming SSE frames into guaranteed-atomic spans and non-atomic tails; it buffers up to a configurable lookahead window and only releases spans that satisfy atomicity checks (complete braces/quotes balanced, no dangling UTF-8 sequences, and not mid-escape). - Replace ad-hoc escape handling in runtimes/sse/parser.rs with a terminal-escape rewrite pass that normalizes escape sequences at span boundaries so that the downstream JSON coalescer sees consistent sentinel tokens. The rewrite is idempotent and cheap (few string ops per span) and has a guarded fast-path for single-chunk events. - OpenAI compatibility: update openai/compat/stream_adapter.ts to apply the same gatekeeping rules at boundary points and teach it to map the gatekeeper's span metadata to existing seq/ack heuristics so existing clients (and our tests) see no behavioral change except improved correctness. - Tests: added tests/sse/integration/partial_json.test.ts covering split-brace, split-utf8, split-escape, and replay-with-retry scenarios; extended unit tests for parser state transitions. - Docs: docs/sse-framing.md documents the gatekeeper rules, configuration knobs (window_size, max_buffer_bytes), and recommended rollout steps. Backwards compatibility and rollout: the gatekeeper is enabled by default for all hosted streams but can be toggled per-route via a rollout flag. The gatekeeper defaults are conservative to avoid added latency for small messages. Observability: added counters and traces for buffered_span_count, gatekeeper_release_latency_ms, and escape_rewrite_invocations so we can monitor regressions.
