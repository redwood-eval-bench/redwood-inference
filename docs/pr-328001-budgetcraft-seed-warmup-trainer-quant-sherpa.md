# Add budgetcraft seed-warmup trainer and quantization sherpa

Context: Customers frequently see unit-cost regressions when cold-starts and early-batch shapes are not tuned to tenant traffic. Existing autotuners focus on steady-state batching and quantization; early warmup (seed) behavior is under-optimized and requires manual profiles. Motivation: provide an automated, conservative warmup profile generator plus a safe quantization recommender that ties recommendations to workload signatures and unit-econ estimates. This PR introduces two cooperating pieces: (1) Budgetcraft seed-warmup trainer: a workload-driven component that ingests recent trace samples and produces tenant-scoped warmup presets (initial batch sizes, initial cache prefix heuristics, and staged batch ramps). (2) Quantization Sherpa: a service that runs lightweight evaluation of quant candidates against representative prompt sets and returns a ranked set of quant profiles annotated with expected unit-cost delta and an estimated quality delta (BLEU/ROUGE/similarity proxies + config-specific thresholds). Design summary: - Budgetcraft operates as an offline trainer (cron + on-demand) that consumes sample windows emitted by the workload-sampler component. It scores candidate warmup ramps using a cost-weighted utility function that emphasizes early latency SLOs and conservative cost improvements. Output is a namespaced preset (tenant: preset-id) stored in the defaults registry and surfaced through the Optimize API. - Quantization Sherpa is a separate binary/service with a small sandbox harness. It runs quant trials using cached model shards and feeds eval metrics into a simple calibration model that maps quality deltas to user-facing risk levels (low/medium/high). Sherpa never auto-applies anything; it returns recommendations and a deterministic fallback policy for runtime use. Key changes: - runtime/prefill/seed_trainer.py: new trainer, sampling adapters, scoring function, and presets export. - optimize/quant_sherpa/service.go: new Go service that runs quant trials and exposes a recommendation API. - console/docs/cost-automation.md: new documentation page with guidance and example presets. - api/optimize/v1/types.proto: small additions for preset metadata and risk-level annotations. - charts/helm/templates/budgetcraft.yaml: helm template to deploy the trainer and sherpa in Private/Dedicated clusters. - tests/integration/prefill_trainer_integration_test.py: integration tests validating sample ingestion and preset creation. - ci/workflows/prefill-trainer-ci.yml: new CI workflow that runs unit/integration and e2e smoke tests in parallel. Migration/compatibility: - Defaults registry format extended with optional fields (warmup_ramp/v1). Clients that read presets will ignore unknown keys. - Sherpa recommendations include a stable recommendation-id and do not change runtime routing unless an explicit rollout action is taken. Rollout plan: 1) Internal dogfood: enable Budgetcraft for a small set of internal tenants (low traffic) for 2 weeks. 2) Monitor unit-econ drift, early latency SLOs, and quality regression alerts via Redwood Console dashboards (new panels added). 3) If green, expose recommendations to customers in Optimize Console (opt-in) and allow one-click apply for tenant admins. Tests: - Unit tests for scoring function and config serialization. - Integration tests that replay sampled traces and assert preset creation. - End-to-end smoke test: deploy trainer + sherpa in a test namespace and run a small trial against a canned workload. Security & privacy: Trainer operates on anonymized traces (hashed tenant ids and prompt fingerprints). Sherpa runs only on model variants available in the cluster and does not upload prompts externally. Open items / follow-ups: - Hook recommendations into the rollout CLI (follow-up PR that implements guarded apply with canary). - Add more robust quality metrics (human eval integration) for certain tenant classes. - Consider an online lightweight trainer for very high-throughput tenants.
