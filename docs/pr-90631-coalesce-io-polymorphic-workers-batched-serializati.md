# Coalesce IO polymorphic workers and batched serialization to cut CPU tail latency

Background: production telemetry shows CPU-side tails driven by frequent short-lived IO wakeups and per-request serialization overhead (small payloads, many concurrent connections). Motivation: reduce syscall churn and cache thrash without changing existing external APIs. Change summary: introduce a configurable IO coalescer that groups pending socket/FD readiness into short (<500us) micro-batches processed by polymorphic workers, unify the per-request serialization path into a batched serializer that encodes multiple response frames in one pass, and add lightweight pacing to the worker pool so CPU pinning is optional. Design goals: (1) preserve latency SLOs for single-request fast paths, (2) reduce 95/99p CPU tail by avoiding repeated thread wake/sleep, (3) keep the change runtime-configurable and safe to roll back. What this PR does: 1) new module runner/scheduler/io_coalescer.rs that aggregates readiness events per-core and dispatches grouped events to polymorphic workers; 2) polymorphic worker pool (runner/scheduler/worker_pool.rs) that supports CPU-pinned and unpinned modes and can handle small burst windows; 3) batched serializer (runtime/serialization/batch_serializer.cpp) that takes vectorized response items and applies shared formatting/kernels once; 4) lightweight KV prefetch hints in runtime/kvcache/prefetcher.py to warm hot keys observed in batched requests; 5) a new runtime flag io.coalesce_workers (default: false for safety) and debug tracing; 6) benchmarks and perf harness changes under bench/perf/coalescer/*. Checklist: - [x] design doc linked in Linear ENG-2120 | - [x] unit + integration tests added | - [x] microbench harness and CI perf job updated | - [x] feature gated behind runtime flag | - [x] rollout plan with canary and metrics tracked Performance: end-to-end lab tests (nvme-backed VM, 32 vCPU, 8x A10 equivalent inference GPUs simulated) show: baseline 95th CPU-side request path latency 48ms -> 16-20ms with coalescer+batched-serializer enabled; p99 reduced 92ms -> 36ms; average CPU cycles/request reduced ~2.8x; observed 18% drop in token-level throughput at 1000 concurrent connections due to batching-induced micro-queueing in aggressive mode (mitigated by default conservative windows). Safety and compatibility: no external API changes, no model-serving kernel modifications; kvcache prefetch is best-effort. Rollout: staged enablement via feature flag; canary in us-west with 5% traffic for 24h, then 25%, then full. Revert: set io.coalesce_workers=false and redeploy; fallback safe-path keeps original serializer and worker semantics. Related: ENG-2187 (bench regression triage), SUP-4421 (customer report of tail CPU).
