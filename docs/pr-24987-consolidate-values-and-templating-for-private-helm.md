# consolidate-helm-values-and-template-hooks-for-private-installer

Motivation: streamline how Helm values and templating drive init/rollback hooks for the Redwood Private installer so operators have a single, well-documented surface for preflight/init tasks, graceful rollbacks, and upgrade-time migrations. This PR consolidates multiple values blocks scattered across charts into a central values.schema.yaml, introduces a small templating helper for hook annotations, and swaps the previous ad-hoc initJob to an operator-friendly initHook Job that is idempotent and respects .Values.lifecycle.preInstall.enabled. Key goals: 1) avoid behavior drift between on-prem and VPC deployments, 2) make rollback actions declarative and reversible, 3) give clear defaults while allowing site-specific overrides for network/KMS/db checks. Changes include: values schema refactor, new _helpers.tpl for hook annotations and timestamps, initHook job templated with wait semantics, a post-install hook for KV pre-warm and cache priming, and documented upgrade notes for v1.2 -> v1.3. Checklist: - [x] values.schema.yaml added and referenced by Chart.yaml - [x] templates/_helpers.tpl with hook helpers - [x] templates/init-hook-job.yaml (idempotent, retries) - [x] templates/rollback-hook-job.yaml (safeguarded) - [x] unit tests for values validation and template rendering - [x] integration smoke test in chart CI - [x] docs/PRIVATE-HELM.md updated with examples and rollbacks How to review: focus on values schema (types and required flags), hook TTL/cleanup behavior, and safety of rollback job (it must NOT delete user data). This PR is intentionally conservative: default preInstall.enabled is false for existing clusters, and migration logic in chart helpers checks for legacy values to preserve behavior. Linear: ENG-1234 implements the lifecycle contract; SUP-987 documents a support escalations case that prompted clearer hooks.
- Consolidated private Helm values into values.schema.yaml for clearer validation and backwards compatibility.
- Added templated init-hook and rollback-hook jobs (disabled by default) to support safer installs and rollbacks.
- Introduced hook helper templates to centralize annotations and cleanup behavior.
- Docs: PRIVATE-HELM.md with upgrade/rollback examples and troubleshooting steps.
Upgrade notes: After upgrading the chart operators should: 1) audit values against new values.schema.yaml (helm get values | helm diff if available), 2) set .Values.lifecycle.preInstall.enabled=false for a canary rollout, 3) if using legacy initJob, set .Values.legacyInit.enableMigration=true to run automatic conversion. Rollback behavior: rollback-hook runs only when .Values.lifecycle.rollback.enabled=true and requires annotation 'redwood.io/allow-rollback: "true"' to execute destructive cleanup. KMS & VPC note: KMS checks in init-hook are no-op unless .Values.kms.enabled=true (safe default).
Rollback and init hooks are non-destructive by default. Destructive cleanup paths require an explicit annotation and dryRun=false. Hook containers run as non-root and read-only filesystem where possible; reviewers should double-check any image updates for CVE exposure.
