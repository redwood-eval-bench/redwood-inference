# introduce-slim-event-envelope-and-retry-builder

Motivation: Consumers wanted a smaller, well-typed streaming payload envelope and a compact fluent RetryBuilder to standardize ergonomic backoff presets across TS/Python/Go. This change aims to reduce per-message wire overhead for high-throughput streams while providing an approachable builder for common retry profiles. No server-side protocol changes were required (wire-compatible). What changed: added a minimal EventEnvelope<T> (wire aliases, typed helpers, flatten/unflatten helpers), a RetryBuilder with presets (ui-fast, balanced, throughput) and options (jitter, maxRetries, baseDelayMs), parity shims for Python and Go that mirror the public surface, examples and a migration guide, and unit+integration tests plus a microbenchmark. Key tradeoffs: internal aliasing keeps messages compact (e/m fields) while public helpers preserve readability (envelope.event/envelope.meta); the ui-fast preset favors lower backoff ceilings at the cost of more retries. Testing: TS/Go/Py unit suites and integration matrix (node 16/18, go 1.20, py 3.11) passed after stabilizing a flaky e2e timing test by deterministic seeding. Microbenchmarks show ~8% average reduction in payload size for echo scenarios and <1% runtime overhead for envelope helpers. Migration notes: consumers opt-in by replacing StreamMessage with EventEnvelope and by selecting a RetryBuilder preset; examples included. Merge: squash-and-merge to main and bump TS SDK to v2.11.0.
