# Add tiered batching dashboards (latency/queue/batch size) with cardinality-safe dimensions

Summary: This PR adds/updates Grafana dashboards to support the tiered batching defaults launch (fast/standard/cost-efficient). The goal is to make it easy to answer: (1) which tier is active and why, (2) whether latency SLOs are being met per tier, (3) whether we are building unsafe queue depth / wait time under load, and (4) whether batch formation is behaving as expected (size and wait budget). Dashboards added: (A) Tiered Batching — Overview: high-level latency (p50/p95/p99), request rate, error rate, and saturation widgets with tier selector; includes a ‘canary vs control’ comparison row (for staged rollout) keyed off rollout cohort label when present. (B) Tiered Batching — Latency & Streaming: end-to-end latency and time-to-first-token panels, split by tier; includes separate panels for streaming vs non-streaming routes to avoid blending distributions. (C) Tiered Batching — Queue & Backpressure: queue depth, queue wait time, admission control rejects, shed/load-shed counts, and scheduler overload mode indicator (when enabled). (D) Tiered Batching — Batch Formation: batch_size_tokens histogram heatmap, batch_size_requests distribution, max_wait_ms utilization, and prefill/decode occupancy (when exported). (E) Tiered Batching — Regression Triage: side-by-side ‘current vs baseline’ p95/p99 deltas for top models, plus a panel for top offenders by (tier, model_family, region). Metrics and tags: This PR assumes runtime emits a tier label and reason codes per ENG-18426 / PR-28473; dashboards are built to work even when reason codes are missing (panels gracefully hide that row). Cardinality constraints are enforced by default: panels use model_family and route_group where possible; model is a template var with a safe allowlist and defaults to ‘top 10 by traffic’. Region is a template var but panels aggregate to region_group when high-cardinality environments are detected. Also adds guidance text within dashboards: “If you need per-route debugging, switch to the Route Debug dashboard and pin a single route to avoid unbounded series.” Alert readiness: No paging alerts are added in this PR (those live in alert-rules repo), but queries were shaped to be portable to PromQL recording rules. Includes draft threshold guidance in dashboard annotations (e.g., fast tier p99 regression > 10% for 15m at constant QPS) aligned with the SRE rollout checklist. Notable changes since first draft: (1) removed direct breakdown by tenant_id and full model name from the default view after review; (2) added a ‘series count’ panel to quickly spot label explosions; (3) renamed panels to match the SLO tier naming in the customer-facing docs (fast/standard/cost-efficient). Testing/validation: Exported dashboards loaded into staging Grafana; verified query performance under typical prod cardinality by replaying a 30m window in the metrics sandbox. Confirmed that all panels render with only tier labels enabled (no reason codes) and do not error when streaming labels are absent. Related: runtime metrics tier labels (redwood PR-28492), reason codes (redwood PR-28473), rollout flagging (redwood PR-28480), internal ticket INT-33012 (missing tier breakdown labels) resolved by aligning label keys used in dashboards with the runtime’s final taxonomy.
Adds tier-aware batching dashboards for runtime-1.22: latency (p50/p95/p99) by tier/model/region, queue depth + admission/backpressure signals, and batch size distribution with cardinality controls. Includes regression panels and alert-ready queries.
