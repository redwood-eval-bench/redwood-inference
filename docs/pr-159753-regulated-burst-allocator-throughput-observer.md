# regulated-burst-allocator-throughput-observer

Motivation: Dedicated fleets sometimes experience microburst behavior that makes tenant throughput guarantees brittle: short-lived spikes either consume warm-pool credits or trigger disproportionate autoscaler reactions. This PR implements a regulated burst allocator plus an observed throughput collector to smooth short spikes, make headroom decisions more conservative, and provide richer telemetry for SRE and product owners.\n\nWhat this PR does (high level):\n- Introduces a RegulatedBurstAllocator that tracks per-tenant short-term \"safeguard tokens\" and a reclaim policy to prevent long-lived token starvation.\n- Adds an ObservedThroughputCollector that computes tenant-level p50/p90/p99 (request/sec and tokens/sec) and short-window derivatives used by autoscaler heuristics.\n- Plumbs a policy: when a tenant exceeds its sustained reservation but still has safeguard tokens, allow limited burst while emitting a structured \"burst_event\" metric; once tokens exhaust, fall back to a soft-throttle pathway.\n- Provides backward-compatible config flags (fleet.policy.regulated_burst.enabled, regulated_burst.window_ms, safeguard_token_rate).\n- Adds unit and integration tests for the allocator and collector, plus a smoke test that simulates a 10s burst followed by steady load.\n\nChecklist:\n- [x] Design doc linked (Linear ENG-1842)\n- [x] Unit tests added for allocator and collector\n- [x] Integration smoke test in perf-canary harness\n- [x] Feature flag gated and default off for existing clusters\n- [x] Telemetry names documented in observability pack\n\nCommits summary (rough):\n- a1b2c3d: initial regulated burst allocator and types + unit tests\n- d4e5f6a: observed throughput collector + sliding-window estimator implementation\n- f7g8h9i: integrate collector into autoscaler decision path;
