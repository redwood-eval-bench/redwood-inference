# Refactor attribute-driven RBAC to policy-graph + audit snapshotting + KMS usage historian

Summary: Replace the legacy attribute-matcher RBAC implementation with a deterministic policy-graph evaluator, add an audit snapshotting pipeline that records RBAC decisions at the time of request evaluation, and introduce a lightweight KMS usage historian metric stream for post-hoc provenance. Motivation: attribute-matcher logic has grown brittle and hard to extend for cross-tenant, region-bound policies; policy-graphs enable explicit policy composition, easier reasoning about precedence, and deterministic evaluation order required for compliance audits. Audit snapshotting provides a compact, signed record of the decision context (policy id, inputs, fingerprint, outcome) so legal/compliance teams can replay and verify decisions without keeping raw tokens. The KMS historian records per-request KMS metadata (key id, region, operation, decision fingerprint) to correlate crypto usage with RBAC decisions and residency constraints. Changes in this PR: 1) New policy-graph evaluator implemented under rbac/graph/ with a composable node model, unit-tested against existing attribute test-suite. 2) Migration shim that accepts current attribute rules and compiles them into a policy-graph for backward compatibility. 3) Audit snapshotting service (auditor/snapper) that captures a compact decision snapshot and dispatches to audit-ingest; snapshots are HMAC-signed with a service key and include a deterministic fingerprint to enable replayability without exposing tokens. 4) KMS historian shim that emits structured telemetry to the metrics pipeline (kms.historian.*) and a new provenance-tag added to audit envelopes. 5) End-to-end integration tests and a canary rollout plan (10% route-level rollout -> 50% -> 100%) with automatic rollback on discrepancy alerts. 6) CLI tooling: 'rbac compile-graph' to help operators convert legacy rule-sets for review. Backwards compatibility and rollout: The migration shim guarantees identical decision outcomes for all existing tests; we ship feature-flag guarded rollout enabling small cohorts and a strict smoke/regression check before increasing traffic. For operators: see devops/rbac_graph_migration.md (in repo) for step-by-step checklist. Security notes: snapshots omit request payloads and tokens, contain only hashed fingerprints and policy inputs; snapshots are access-controlled and retained per retention policy tied to Linear ENG-8742. KMS historian emits no key material; it records key identifiers and operation types only. Testing and observability: added deterministic property tests, fuzz harnesses, and two new dashboards (RBAC graph evaluation latency, audit snapshot ingestion rate) plus alerting on snapshot drop rate. Risks: potential performance regression in worst-case deeply nested graphs — mitigated by memoization and an O(log n) policy index; stress testing shows <5% median latency impact on heavy rule-sets. Rollout plan and rollback: feature-gate off by default; enable via routing rules for select tenants; on discrepancy or snapshot drop alerts we will rollback to attribute-matcher and run a diagnostic job to produce diffs. Related work: follows design from SEC-118 initial spec and references prior RBAC migration spikes.
