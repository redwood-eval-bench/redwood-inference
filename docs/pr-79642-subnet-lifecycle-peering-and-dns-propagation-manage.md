# Control plane subnet lifecycle manager + automated peering cleanup and DNS propagation

Motivation: private control planes frequently suffer from stale or colliding subnet allocations and orphaned cross-account peering attachments after interrupted upgrades. This PR implements a subnet lifecycle manager and an automated peering cleanup + DNS propagation helper to make VPC provisioning and upgrades more resilient. Scope: terraform refactor + new module (controlplane/subnet-lifecycle), a small helm values change to surface the control-plane DNS config to the installer, a new reconciler job (gauntlet) run via the installer to garbage-collect stale VPC peering and push conditional Route53 delegation records for cross-account control plane discovery. Changes are backwards-compatible for existing installs; the reconciler can be enabled via helm/tf boolean and defaults to disabled in older clusters. Checklist: - [x] Terraform module and examples added - [x] End-to-end plan for safe rollout on existing customers (blue/green-style secondary subnets) - [x] Integration tests for peering cleanup in perf-canary - [x] Helm chart value + docs - [x] Smoke tested in staging with a multi-account setup Summary of behavior: - Subnet lifecycle module: provides deterministic tagging and an idempotent claim model for control plane subnets. When enabled the module will claim available subnets by tag, annotate Terraform state with claim metadata, and, when a reclaim is needed, create a replacement subnet before removing the old one to avoid downtime. - Peering cleanup reconciler: scans AWS for VPC peering connections tagged for 'redwood-controlplane', detects attachments that are in FAILED or DELETING states for >24h, and safely removes stale peering objects after validating that no active routes reference them. The reconciler also optionally reconciles route table propagation in cross-account setups via SSM-triggered cross-account lambda. - DNS propagation helper: when peering is created the installer now emits a controlled Route53 NS delegation template and can optionally create conditional forwarding via Route53 Resolver rules for cross-account lookup. The helper uses Alias records for the control-plane LB to avoid chasing IPs across peering. Rollout notes: - Default is disabled for existing installations. To enable, flip installer helm value controlPlane.subnetLifecycle.enabled or set terraform variable control_plane_subnet_lifecycle = true and run the 'subnet-claim' plan. - For CIDR rotation/upgrades, the module supports create-before-destroy with a transient attachment window. Operators should follow the included RUNBOOK for blue/green swap and DNS cutover. Related work: ties to ENG-1427 (subnet allocation hygiene) and SRE-88 (peering reliability incidents).

Added an optional subnet lifecycle manager that enables safe CIDR rotation and deterministic subnet claims. Added a reconciler that garbage-collects stale VPC peering attachments and a DNS propagation helper to automate conditional delegation for cross-account control planes. Feature is opt-in and disabled by default for existing installations.
Set helm value controlPlane.subnetLifecycle.enabled=true and run 'terraform apply' for the subnet-lifecycle module. Follow runbook to create transient secondary subnets, wait for traffic mirroring to steady-state, then perform DNS cutover. For peering cleanup enable reconciler only after confirming routes have stabilized.
Disable the reconciler and set terraform var control_plane_subnet_lifecycle=false. If a subnet was replaced, revert by runbook steps: reassign routes from the replacement back to the original and delete the replacement subnet. Contact SRE if the reconciler already cleaned up peers; we provide an audit log and reversible terraform plan in the runbook.
