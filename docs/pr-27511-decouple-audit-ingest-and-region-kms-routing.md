# Decouple audit ingestion and add region-aware KMS routing policy

Motivation: Private installer customers reported high tail latency and occasional data-path leaks when the central audit-ingest pipeline was forced through the control plane. This PR decouples the audit ingestion path so that the audit-forwarder runs as a customer-local component (in customer VPC or on-prem) while the control plane only receives signed, canonicalized envelopes. In addition, we introduce a region-aware KMS routing policy that enforces key residency constraints and selects a permitted KMS provider per-tenant region claim. The work touches installer manifests, the audit forwarder service, the KMS routing policy, RBAC v2 temporal constraints for operator sessions, and migration tooling. Checklist: 1) decouple audit-ingest into installer-local audit-forwarder and control-plane envelope-acceptor; 2) add KMS routing plugin with per-tenant region mappings and failover rules; 3) enrich audit envelopes with residency headers and provenance signature; 4) enforce RBAC v2 timebound operator roles when key-provisioning endpoints are hit; 5) add migration script to convert existing audit streams to envelope format; 6) add unit, integration and e2e tests + upgrade notes. Backwards compatibility: control plane still accepts previous audit payloads during a 30-day compatibility window; audit-envelopes are preferred and validated when present. Rollout plan: staged rollout via installer flag enable_audit_local_forwarder=false|true, test on internal staging, then gradual customer opt-in with canary metric dashboards in Console. Notes: See Linear ENG-1452 for perf spikes and SEC-78 for residency compliance details. Contact: @ashak for migration support.
