# Add signal suppression + false-positive guardrails (internal org filtering, min-volume gates)

Context: During the NA pilot we’re seeing a non-trivial number of “vanity” intent triggers and a couple of true false positives (notably Quartz Commerce) resulting in unwanted outreach (see SUP-3392). This PR adds a set of guardrails to reduce noise while keeping recall for genuinely sales-worthy signals. Summary of changes: (1) Suppression windows: prevent re-routing the same signal type for the same account within a configurable cooldown (default 14d for intent, 7d for reliability/usage) unless severity increases. We store last_routed_at by (workspace_id, signal_type) and compare against current signal_score + severity. (2) Internal/test org filtering: blocklist/allowlist logic for Redwood-owned workspaces and known test tenants; also filters “example.com” style seeded domains and sandbox workspaces tagged by billing. This is applied before scoring so we avoid polluting analytics tables and HubSpot with internal activities. (3) Minimum-volume gates: require minimum sustained volume for threshold signals (tokens/spend/429s) to reduce one-off spikes; add a separate gate for “docs intent only” that requires either (a) 2+ distinct sessions across 48h or (b) docs intent + at least one supporting product event (workspace invite spike, API key rotation, or repeated rate-limit). (4) Confidence floor: enforce a minimum confidence threshold for routing (default 0.65) with per-signal overrides, and write suppressed candidates to a side table for tuning. (5) Auditability: whenever we suppress we emit a structured log and a metric with reason codes (cooldown, internal_org, min_volume, confidence_floor). Tradeoff notes: This will reduce total routed tasks (expected 25–40% drop based on pilot cohort replay), but should materially reduce spam/false positives. We explicitly bias toward fewer tasks while we tune thresholds; suppressed events remain queryable for later adjustment. Testing: Added unit tests for suppression keying + cooldown behavior, internal org matching, and min-volume gating; added a replay test against a sanitized subset of the pilot cohort to validate volume impact. Follow-ups: (a) Add UI surfacing of “suppressed signals” for triage (see DES-412), (b) Re-evaluate doc intent heuristics once we have docs instrumentation improvements from Elliot (docs session identifiers), and (c) Consider account-level suppression when Marketing nurture is active (separate workstream with Tyler/Camila).
Key changes: services/plg_signal_router/suppression/guardrails.ts (new guardrail evaluation pipeline and reason codes); services/plg_signal_router/config/signal_guardrails.yaml (defaults for cooldown, min-volume gates, confidence floor); analytics/jobs/daily_signal_aggregator/min_volume.sql (add sustained-volume windows + distinct-day checks); services/plg_signal_router/internal_org/filter.ts (new internal org matching + explicit deny/allow lists); services/plg_signal_router/hubspot/route.ts (skip routing on suppressed results; still write suppressed to analytics); services/plg_signal_router/metrics.ts (new counters: suppressed_total{reason}, routed_total{signal_type}, candidate_total); tests/plg_signal_router/guardrails.test.ts (unit tests for cooldown/severity escalation, min-volume gates, internal matching); tools/replay/pilot_cohort_replay.ts (sanitized replay runner used for before/after counts). Illustrative snippet (guardrail evaluation): if (isInternalOrg(account) && !isExplicitlyAllowed(account)) return suppress('internal_org'); if (!passesMinVolume(signal)) return suppress('min_volume'); if (!passesCooldown(lastRoutedAt, signal)) return suppress('cooldown'); if (signal.confidence < confidenceFloor(signal.type)) return suppress('confidence_floor'); return allow();
