# Introduce invocation inventory correlation layer and invocation cost annotator

Motivation: We need a lightweight, low-cardinality way to join invocation traces with tenant/inventory metadata for better per-invocation cost attribution and fast RCA. This PR adds an "inventory correlation layer" that colocates a compact, time-windowed index of invocation metadata (route, model_variant, tenant_label, request_shape_hash) and a small annotator service that enriches sampled traces/spans and emits per-invocation cost annotations.\n\nWhat this PR does:\n- Add telemetry/inventory correlator: a memory-backed time-window index that accepts heartbeat pings from the frontdoor and model routers and exposes a fast lookup by invocation id (inv_id). The index is intentionally bounded and sharded by tenant for predictable cost.\n- Annotator agent: a lightweight gRPC service that listens to sampled trace events, performs an index lookup, computes a cost estimate (token-estimate x model-cost-profile), and attaches structured span tags (cost_cents, cost_profile, invocation_shape).\n- Dashboard updates: new panels for Invocation Inventory (compact table), Cost Attribution Sankey (per-route -> model_variant -> tenant lanes), and Annotated Latency Timeline (flame-line with cost overlays). Dashboard JSONs added under observability/dashboards/invocation-annotator-*.json.\n- Alerts/tuning: new SLO alert rule that triggers an explanatory runbook when cost-per-invocation for a route increases by >25% over 6h. Added alert dampening to avoid noisy transient spikes.\n- Tests and docs: unit tests for the index and annotator, an e2e replay test that runs sampled traces through the annotator, and a short usage/debug guide in docs/observability/invocation-annotator.md.\n\nDesign notes and constraints:\n- Index retention is short (default 2 minutes) to avoid state blowup; correlator exposes configuration knobs for shard count and retention via env vars.\n- Cost estimator uses model cost profiles (static small map) and a conservative token-estimate heuristic; we explicitly avoid exact billing logic to keep the annotator fast and non-authoritative.\n- Privacy: only non-sensitive metadata (route id, model tag, tenant_hash) is stored — no prompt or user content. KMS and PII checks validated in the PR.\n\nChecklist:\n- [x] Correlator core and index sharding\n- [x] Annotator gRPC + span tag wiring\n- [x] Dashboard panels and panel layout\n- [x] Unit tests and e2e replay test\n- [x] Docs and runbook link\n- [x] Alert damping and SLO explanation rule\n\nRisks and mitigation:\n- Potential added latency for sampled trace enrichment: annotator is async-by-design and performs non-blocking enrichment; span tags are added only for sampled traces.\n- Cardinality explosion: index enforces cardinality by eviction and tenant sharding; added metrics to monitor index size (index_entries, index_evictions).\n\nRelated: ENG-4012 (correlation infra), ENG-4120 (cost-explainer); incident SUP-982 noted noisy per-invocation cost spikes which motivated the explainer runbook.\n\nThis is a merge-ready PR after a final lint fix (addressed) and one CI rerun (passed).
