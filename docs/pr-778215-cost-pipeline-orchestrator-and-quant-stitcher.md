# cost-pipeline-orchestrator-and-quant-stitcher

Motivation: automate tenant-safe application of batching, cache and quantization defaults to improve unit economics while preserving latency and quality SLOs. This PR introduces a cost pipeline orchestrator service that profiles tenant request shapes, simulates candidate batching/cache/quant combos, and applies conservative rollout policies with fallbacks and audit events. Includes a new 'quant-stitcher' policy that stitches multiple quant profiles by sequence-length bands to avoid quality cliffs. Migration note: defaults unchanged until rollout flag enabled; operators must preview diffs with the migration CLI before applying to production tenants.
We need an automated, auditable pipeline that composes batching, cache and quantization defaults per-tenant so that unit economics improvements can be rolled out safely and observed. Manual tuning is slow and error prone; this PR implements an orchestrator that reasons about tenant workload signatures, simulates expected cost/latency tradeoffs, and applies conservative quant-stitcher presets with pinch points and fallback gates.
The orchestrator has three stages: 1) profiler - samples request shapes and token distributions; 2) synthesizer - runs a lightweight simulator to estimate unit cost and latency for candidate batching/cache/quant combos; 3) applier - writes tenant overrides to the config-store with rollout metadata and safe fallback policies. Quant-stitcher is a new policy layer that stitches multiple quant profiles across sequence length bands to avoid quality cliffs. All decisions are logged as events for replay.
Defaults remain unchanged until rollout.percentage>0. A migration CLI is added (cmd/orchestrator/migrate_profiles.go) to preview diffs and apply per-tenant; ops should preview on a staging tenant group and increment rollout by 10% per day while monitoring unit_econ_delta and quality.alerts.
No model weights or PII are moved. The orchestrator requires RBAC permission cost:write; config-store writes are audited. All telemetry uses existing encryption at rest and in transit.
Local load tests show median latency unchanged, p95 increases by ~3-7ms for heavy-gen workloads depending on quant profile; estimated cost reduction 8-18% on the benchmark lab traces included in tests.
