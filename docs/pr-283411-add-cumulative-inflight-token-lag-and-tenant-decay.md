# add-cumulative-inflight-token-lag-and-tenant-decay-trend-panels

Motivation: we observed outages and significant tail latency related to transient token build-ups during traffic spikes. Current token-level metrics show per-invocation latency and token cost but do not expose the cumulative inflight "token lag" which is a leading signal for backpressure. This PR adds a new cumulative metric (inflight_token_lag_total) that aggregates outstanding tokens per serving shard over time, exporting both gauge and rate variants, and wires a dashboard that surfaces per-tenant decay trends to help distinguish cold-cache spikes from sustained backlog. What changed: 1) telemetry: introduce metrics/telemetry/inflight_token_lag.go which computes a rolling cumulative count of not-yet-emitted tokens and exposes: redwood.inflight_token_lag.gauge, redwood.inflight_token_lag.per_second, and redwood.inflight_token_lag.tenant_percentile{p50,p95,p99}. 2) aggregation: add a short-lived rollup pipeline (metrics/pipeline/rollup_inflight.toml) to keep compact daily and hourly series. 3) dashboards: add dashboards/tenant_latency_decay.json with 3 panels (decay curve heatmap, decay half-life distribution, rank-ordered tenant backlog). 4) alerts: add alerting/alerts_inflight.yaml with tuned thresholds: warning when 10s sustained 95th percentile inflight_token_lag > 500 tokens, critical when > 2000 tokens; suppression window and automatic escalations added. 5) tests and docs: unit tests for metric calculation and a short docs page with examples for SRE runbooks. Rollout plan: feature flag controlled metric ingestion (telemetry.ingress.inflight_lag_enabled) enabled for canary namespace for 48h, then ramp to 25% tenants, validate signal fidelity and adjust alert thresholds. Signal cost: small (approx +0.2% ingestion), storage rollups configured to cap at 90 days. Backwards compatibility: consumers relying on sample-based token metrics unaffected; new metric additive. Related: ENG-1827 for alert investigation and PM-456 product request. Notes: alert thresholds were calibrated using a week of historical traces and synthetic high-load tests. The PR also includes a Grafana panel with an example quicklink for on-call to jump from an alert to the tenant decay view.
