# Declarative EdgeLayer rollout orbit with rollback escrow and staged traffic bindings

Background: complex edge and Dedicated customers require deterministic model swap semantics across heterogeneous edge nodes and mid‑deployment failover windows. This PR introduces the 'EdgeLayer Orbit' — a declarative rollout primitive that binds staged traffic slices to deterministic snapshot escrows and an automated rollback escrow reclaim protocol. Motivation: existing canary/AB flows handle traffic fractioning but lack an atomic escrow for KV cache and session affinity state; on partial failures customers saw inconsistent session continuity and difficult manual rollbacks. Proposal summary: 1) a CRD-style declarative config (edge_orbit.yaml) that describes staged bindings (fractions, cohorts, continuity hints), 2) an escrow manager that snapshots lightweight session/KV metadata to short‑lived object blobs with integrity hashes, 3) a decision graph executor that drives staged traffic transitions with safety gates and automatic rollback if escrow restore checks fail. Key behaviors: - atomic escrow checkpoint before each stage cutover - validate-then-commit: new model is exercised by mirrored traffic to canary cohort while escrow proof-of-restore runs in parallel - rollback escrow reclaim: if any stage reports divergence on fidelity metrics or restoration checksum, the executor triggers escrow restore and session rehydration path with telemetry markers - graceful drain with session affinity preservation across multi-region edges

What this PR changes (high level): - runtime/orbit: new EdgeOrbit controller (+ unit/integration tests) - runtime/escrow: escrow manager module with S3-compatible persistence and TTL policies - serving/proxy: staged-binding feature flags and lightweight session snapshot hooks - telemetry: new rollup metrics (orbit.stage_{start,commit,abort}, escrow.restore_latency_ms) and tracing spans for escrow operations - docs: rollout playbook and operator runbook in docs/rollouts/edge-orbit.md

Checklist: - [x] Design doc attached (ENG-2345) - [x] Unit tests for controller and escrow validation - [x] Integration smoke harness against localminikube and s3mock - [x] Telemetry dashboards draft - [x] Backwards-compatible: config defaults to disabled

Testing and rollout plan: staged by feature flag: start with internal Dedicated customers in us-west only; enable mirrored shadow traffic and quiet-canary for 48h, then enable staged commit with 5% cohort, watch orbit.stage_commit_success_rate and escrow.restore_latency_ms for 72h, then ramp. Emergency escape: operator can force 'orbit.abort' to immediate escrow restore (playbook linked). Related: follows patterns from ENG-2761 and borrows session snapshot format from SUP-8891. Rollbacks will emit rollback.reason tags for downstream billing and SRE postmortem aggregation.
