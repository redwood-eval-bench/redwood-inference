# Rollout saga orchestration with persistent snapshotting and resumable canaries

Summary: Introduces a saga-based rollout orchestrator that checkpoints rollout state to a persistent snapshot store so canary and A/B rollouts can be paused, resumed, and replayed deterministically. Motivation: customers requested resumable canaries after several incidents where long-running experiments were interrupted by infra maintenance. This PR provides a first-class primitive (rollout saga + snapshot store) to avoid manual replays and brittle ad-hoc recovery scripts. Design highlights: 1) Saga orchestrator manages step sequence (canary phase, ramp, smoke checks, promote) and writes compact snapshots of progress and cohort assignments to the snapshot store after each state transition. 2) Snapshot store is pluggable: default implementation uses our existing durable-metadata service (with TTL + versioning) and an optional S3-backed archival plugin for long retention. 3) Resumable canaries: when a rollout is resumed, the orchestrator rehydrates state, replays pending validation windows, and continues traffic phasing with identical cohort mapping to preserve session affinity. 4) Safety: checkpoints include deterministic pseudo-random seeds for sampling, metric anchors, and active safety gates; resumptions re-run smoke checks before increasing traffic. 5) Rollback tokens: each snapshot includes a reversible rollback token that enables fast snapshot-based rollback to any previous checkpoint. 6) Observable timeline: console UI gains a new timeline view that shows snapshots, resume points, and reasons for pause/auto-hold. Checklist: - [x] Saga state machine and persistent snapshot API - [x] Default durable-metadata adapter + S3 archiver plugin - [x] Resume/replay logic with deterministic cohort mapping - [x] Rollback token generation and replay-based rollback path - [x] E2E tests covering simulated infra interruption and resume - [x] Console timeline UI and docs runbook - [x] Load test showing snapshot write latency impact (<5ms p50) Migration notes: Existing rollouts will continue to use the legacy in-memory state unless migrated. An opt-in flag rollout.spec.resumable=true will enable persisting snapshots for new rollouts (we will provide a migration job in a follow-up PR to convert active runways). Related: ENG-2345 (resumable canaries), ENG-2380 (snapshot retention policy). Links: design doc https://linear.app/redwood/notes/ENG-2345/resumable-canaries-design; runbook draft at docs/runbooks/resumable-canaries.md. Testing: unit + integration tests included; e2e harness simulates coordinator failover; performance microbenchmarks for snapshot writes. Backwards compatibility: headless rollouts with resumable=false unaffected. Rollout failure modes and mitigations are documented in runbook.
