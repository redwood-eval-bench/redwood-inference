# Introduce span-slice telemetry bundles and adaptive-fidelity controller

Motivation: We see growing cardinality and heavy write amplification from per-span uploads for long-running invocations and large token sequences. This PR introduces two complementary features: (1) span-slice telemetry bundles: a compact on-host bundler that groups contiguous invocation spans into a single compressed bundle for downstream ingestion, and (2) an adaptive-fidelity controller: server-side policy that dynamically adjusts sampling and bundling fidelity by tenant, route, and recent cost/latency signals. Design: Bundles are created per-invocation in the runtime agent and contain metadata headers (invocation id, route hash, sequence bucket) and an index of slice offsets. Bundles are designed to be backpressure-aware: when the agent detects high network/ingest pressure, it will opportunistically switch to a reduced-fidelity mode (fewer slices, aggregated histograms). The fidelity controller lives in the observability control plane and exposes rules that map traffic signals (token cost, 95/99 latency, kv-cache miss-rate) to fidelity policies. Rollout plan: Feature gated behind the telemetry.experimental.span_bundle flag. Default behavior remains unchanged for all tenants until the flag is enabled. Canary rollout to internal production tenant, followed by opt-in for customers via Console > Observability Labs. Metrics introduced: telemetry.bundle.size_bytes, telemetry.bundle.slice_count, telemetry.bundle.compress_ratio, fidelity.policy.applied, fidelity.tenant_override. Dashboards: new "Span Slice Heatmap" panel showing bundle slice_count distribution and compress_ratio, and an updated Investigator panel that can open compressed bundle payloads inline. Alerts: reduced cardinality alert tuning replaces noisy per-span error rates with bundle-level error windows; added a new alert fidelity.policy-mismatch that warns if the controller's applied policy differs from expected (useful during rollout). Backwards compatibility: bundles are backward-compatible; ingest workers support both raw spans and bundles. Implementation details: Agent: telemetry/agent/span_bundler.go (responsible for slice grouping, compress/decompress helpers using zstd), and telemetry/agent/sender.go (batching and backpressure hooks). Control plane: observability/controller/fidelity_controller.go with a simple rule engine and rate limiting. Ingest: telemetry/ingest/bundle_decoder.go supports streaming decode into existing span processors. Console/dashboard: dashboards/span-slice-heatmap.json and console/observability/experiments_ui.tsx for opt-in. Testing: unit tests for bundler, integration tests for end-to-end ingestion, and a perf bench in perf-canary to measure CPU overhead and compress ratio across prompt shapes. Security: bundles still honor sensitive field redaction path and respect KMS/HSM for any serialized keys. Operational notes: added a debug CLI (telemetryctl bundle inspect <id>) and a temporary compatibility shim level for 30 days to allow cross-version agent/server communication. Related work: builds on prior sampling and prefix-warmup projects (ENG-2021), and ties into the warmup hints published by the batcher.
