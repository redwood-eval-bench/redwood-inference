# add-invocation-telemetry-deduper-and-token-collapse-visualizer

Introduce a lightweight Telemetry Deduper service and a Token Collapse Visualizer dashboard to reduce noisy duplicate spans and surface redundant token-level cost patterns. Motivation: during several incidents and routine SLO tuning we observed high cardinality and alert fatigue caused by duplicated spans emitted from the serving runtime (frontend retries, duplicate instrumentation points, and batched replays). This PR implements a deterministic fingerprinting pipeline that collapses semantically-identical spans early in the observability ingestion path and a dashboard that helps engineers understand when token costs are dominated by collapsed/duplicate traffic. The change includes a TTL-backed fingerprint cache, session-aware collapse heuristics, an orthogonal latency decomposition helper ("orthogonalizer") that attributes latency to queue/io/model phases for collapsed invocations, alert tuning rules to avoid duplicate alert storms, end-to-end tests with synthetic replay, and a Grafana dashboard with an interactive token-collapse Sankey and cost-savings calculator. Backwards compatibility: original spans are still retained in sampled snapshots; deduped counts are emitted as both raw_count and deduped_count so downstream consumers can opt-in. This description includes: design rationale, implementation summary, QA notes, rollout plan, and linked Linear/Jira items.
