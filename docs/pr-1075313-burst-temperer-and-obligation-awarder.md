# Burst Temperer and Obligation Awarder: decoupled surge allocation + tenant obligation accounting

Context: We have recurring incidents where short-lived multi-tenant microbursts cause transient latency spikes and unfair capacity drain. Previous fixes tightened global headroom but hurt utilization. This PR implements a two-part approach: 1) BurstTemperer, a decision layer that tempers burst grants based on observed burst distribution (p95/p99) and current cluster slack, and 2) Obligation Awarder, a lightweight tenant accounting service that records 'earned' reservation credits and applies a decaying obligation balance used by the Temperer to favor tenants that honored previous reservations. Goals: (a) limit dangerous instantaneous spike grants without rigid hard quotas, (b) reward tenants that consume responsibly over time, (c) provide telemetry to iterate policies. Design summary: - BurstTemperer sits between the admission/gateway and the lease allocator. It computes a soft grant = min(request, policy_headroom * adapt_factor), where adapt_factor is derived from recent burstiness and tenant obligation score. - Obligation Awarder increments a tenant's obligation credit when they return unused reservation capacity or maintain steady utilization; credits decay with half-life configured per org. Credits lower the penalty applied by BurstTemperer. - Both components expose metrics: temperer.grant_ratio, temperer.rejections, obligation.balance, obligation.decay_rate, plus per-tenant histograms. - Fallback: If the allocator rejects due to real capacity constraints, the system falls back to existing soft-failure path (queue or fallback model). Why different from existing 'reservation' work: instead of reallocating cold reservations or changing commit windows, this focuses on tempering transient grants and adding a long-lived accounting signal to guide future decisions.
