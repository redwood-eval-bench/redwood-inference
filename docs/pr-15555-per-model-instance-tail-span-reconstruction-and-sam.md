# per-model-instance-tail-span-reconstruction-and-sampled-request-dump

Motivation: Debugging long-tail latency/cost incidents is currently hard because traces often drop context for large requests and we have no compact way to reconstruct the original request token stream tied to the sampled spans. This PR introduces a lightweight, per-model-instance tail-span sampler plus a request-reconstructor that stores compressed, TTL-backed request snapshots (token offsets + prompt metadata) in object storage for post-mortem. The system is conservative by default (sample rate 0.01% for normal traffic) and exposes policy knobs for SLO-driven sampling (e.g. sample all requests that exceed p99 latency or cross a cost threshold). The change set includes: 1) a tail-span sampler in the serving runtime that marks traces with a tail_reason tag (latency/cost/cache_miss), 2) a request snapshotter that deduplicates and compresses payloads (LZ4 + shared-prefix dedupe on repeated system prompts), 3) a reconstructor service that can rehydrate a sampled request for local replay and full-token timing breakdowns, 4) new Grafana dashboard panels and an alert rule showing reconstructed-request cluster counts and the most common tail reasons per model instance, and 5) an automated retention/cleanup workflow to limit storage and PII exposure. Backwards compatibility: tracing spans keep the existing service/name conventions; the sampler only adds an opt-in config block in the cluster spec. Migration notes: enabling the feature requires an object-store bucket and the telemetry-agent sidecar to have write access. Security/privacy: snapshots are redaction-aware (PII scrub hooks) and default to 7-day TTL. Config defaults remain conservative.
