# Fix long-context regression: adjust prefill regime thresholds to avoid tail-latency spikes

Context: During perf characterization + Hosted canary for runtime 1.21, we saw a p99 regression on long-context workloads (>=16k prompt tokens) on L40S and some A100 pools when kernel auto-selection v2 classified certain requests into the “mid” prefill bucket and chose FA3 prefill variants that are great for short/mid contexts but showed allocator/workspace churn at long context (and worse tail when batch composition is mixed). This PR tightens the v2 rules to prevent mis-selection in the long-context regime while keeping determinism guarantees and preserving the gains on short/mid prompts. Changes: (1) Adjust prefill-length bucket boundaries and add a small hysteresis band to reduce flip-flopping around thresholds when scheduler-provided distribution hints are noisy. (2) Add an explicit long-context guard: for ctx >= LONG_CTX_TOKENS (default 12288), prefer the “lc_prefill” kernels when available, otherwise fall back to the known-stable v1-equivalent prefill path. (3) Add SKU-aware exception for L40S where the problematic kernel variant was disproportionately impacting tail; we now require a stricter threshold before selecting it and we prefer the stable alternative when decode_len is small (prefill-dominant requests). (4) Add unit tests covering boundary conditions + replay determinism around bucket edges, including cases with mixed scheduler hints. Bench results: See attached before/after plots from perf suite run 2026-02-14 and canary replay slice. Summary on L40S (long-context summarization profile, 16k/256): p95 1.38s -> 1.11s (-19.6%), p99 2.74s -> 1.63s (-40.5%). On A100 (same profile): p95 1.02s -> 0.98s (-3.9%), p99 1.88s -> 1.61s (-14.4%). No correctness diffs observed (golden outputs match within expected nondeterminism bounds; selection remains deterministic for fixed inputs). Notes: This is intended as a targeted rule tweak; no changes to telemetry schema. Rollout: safe to land in release/1.21 behind existing gates; recommended to promote to Hosted canary first, then Dedicated pools after 24h with the rollout dashboard guardrails.
