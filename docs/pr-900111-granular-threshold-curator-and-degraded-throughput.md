# Granular threshold curator and degraded-throughput limiter

Motivation: Dedicated fleets have heterogeneous tenancy and workload skew; a single global autoscaler threshold leads to either wasted headroom or recurrent SLA blips. This PR introduces a lightweight per-pool 'threshold curator' that synthesizes guardrails from short-term percentile windows and a 'degraded-throughput limiter' which imposes a temporary throttling cap when pools show sustained latency regressions. Goals: (1) reduce SLA violations during transient load spikes while avoiding long-term over-provisioning, (2) provide clear telemetry for pool health, (3) allow safe rollout via feature flag and canary. What changed (high level): - New curator subsystem that computes conservative min/max concurrency and burst thresholds per pool using a configurable window of p50/p95/p99 utilization and latency percentiles. - Degraded-throughput limiter that activates with hysteresis when latency or error-rate thresholds are breached; it reduces allowed oversubscription and fast-fails opportunistic allocations to preserve core throughput. - Pool aging detector: marks pools as 'stale' when lacking fresh scoring signals and backs off aggressive scaling decisions. - Telemetry: adds pool_age, curated_threshold_{min,max}, degraded_throttle_count, degraded_throttle_duration metrics and tags so SLO dashboards can surface regressions. - Helm/operator: new values to opt-in and tune thresholds and rolling behavior. - Tests: unit coverage for curator logic, integration e2e that replays a 30-min tail-of-day traffic spike. Rollout plan: enable behind feature flag (autoscaler.curator.enabled=false by default), run on 10% of dedicated clusters for 48 hours, validate p99 token latency and degraded_throttle_count, then increase to 50% and finally global. Safety knobs: curator will never reduce below configured absolute minima, limiter has a max-duration and exponential backoff to avoid persistent throttling.
