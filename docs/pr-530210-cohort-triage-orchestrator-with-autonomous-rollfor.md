# Cohort triage orchestrator with autonomous rollforward and gated-eval

Motivation: enable more autonomous, telemetry-driven promotions and rapid containment for cohorts during model rollouts. This PR introduces a Cohort Triage Orchestrator that classifies traffic cohorts into healthy/quarantine/monitor lanes, runs gated A/B evaluations (gated-eval) with checkpointed baselines, and supports autonomous rollforward when safety budgets are satisfied. Key user stories: 1) platform teams get low-touch canary promotion when cohort-level metrics meet objective windows; 2) problematic cohorts are automatically attenuated/shadowed rather than fully disabling traffic; 3) operators can define per-cohort policies and handshake windows via declarative config. What this changes: new controller (cohort_triage_controller) that consumes telemetry streams and rollout intents, a lightweight policy DSL for triage rules, integrations to the console for cohort dashboards, and end-to-end tests and benchmarks. Design notes: the controller keeps a moving safety budget per cohort, computes delta metrics against pinned baselines, and triggers autonomous rollforward only after ensemble checks (latency P95, error rate, semantic regression score) remain stable for an observation window. For borderline cases the controller will initiate a gated-eval: a short-lived A/B experiment with deterministic seeding, enriched sampling, and automatic snapshot checkpoints to allow deterministic rollback and repro playback. Safety features: attenuation rules to reduce shadow weight gradually, quarantined shadow lanes with compact KV cache isolation to avoid cross-cohort cache pollution, manual latches for human-in-the-loop intervention, and audit logging for every automatic action. Backwards compatibility: default behavior is opt-in via rollout policy annotations; existing rollouts are unaffected until a policy is attached. Related work: follows ENG-3245 and ties into the rollout telemetry work from ENG-3301. Operators can opt into per-cohort automated promotions and attenuation policies. See docs/rollouts/cohort-triage.md for configuration and examples.
Performance: decision path latency median 12ms in our bench environment; worst-case when computing semantic delta for long observation windows is ~85ms. Safety: initial rollout tested on internal beta with two Canary runs and no regressions observed. Telemetry retention for triage windows set to 72 hours by default to bound memory.
