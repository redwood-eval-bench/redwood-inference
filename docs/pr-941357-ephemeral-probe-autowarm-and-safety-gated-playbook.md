# Ephemeral probe autowarm and safety-gated playbook queue

Context: We see frequent cold-starts for ephemeral probes during bursts of alerts which delays evidence collection and increases oncall noise. This PR adds a lightweight prewarm/autowarm subsystem for ephemeral probes plus a safety gate for automatic playbook enqueueing so we don't escalate noisy transient alerts to oncall without a short stabilization window. Design: 1) prewarm worker that maintains a small pool of 'warmed' probe runners for high-burst windows; the worker observes recent probe arrival rate, warms runners proactively, and evicts idle runners. 2) safety-gated playbook queue: automated playbook enqueue is now conditional on a short stabilization policy (configurable thresholds: consecutive failures, duration, and confidence score). 3) opt-in tenant-level config for both behaviors; default remains off for older installations. Checklist: - [x] core prewarm worker + eviction loop - [x] stabilization policy and queue gate - [x] metrics + tracing hooks - [x] feature flag + tenant config - [x] unit and integration tests - [x] docs + config examples Rollout plan: behind feature flag by default, enable in staging for 72h smoke, enable in a small set of production tenants (canary) for 48h, monitor metrics and alerts (cold-start latency, playbook enqueue rate, oncall paging rate). Backout: disable feature flag or set max_prewarm_workers=0. Testing: unit tests for worker logic and gate heuristics, integration tests with ephemeral probe simulator to validate warm hit rate and queue gating. Measured in staging: 18% median reduction in cold-start latency during a synthetic burst and 25% fewer auto-enqueues for transient signals. Related: ENG-4921 for probe autoscaling, SUP-842 customer incident that motivated the gate. Documentation: updated incident-bot/operator-guide.md with config examples and recommended canary steps.
