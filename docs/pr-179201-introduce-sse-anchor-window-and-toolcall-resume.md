# Introduce SSE anchor window and tool-call resume handshake to mitigate partial-JSON replay and delimiter drift

Motivation: Streaming clients have sporadic partial-JSON replay and delimiter drift when network interruptions interleave with server-side tool-call handoffs. This causes downstream parsers to see duplicate delimiters or truncated JSON chunks that are hard to recover without application-level heuristics. This PR introduces two coordinated mechanisms: 1) an in-stream 'anchor window' that marks a recent stable byte offset snapshot for boundary resynchronization, and 2) a lightweight 'resume handshake' between server and client when resuming mid-stream (used only for OpenAI-compat streaming paths). Design summary: - Anchor window: server emits periodic anchor frames (sse:type:anchor) containing a short stable fingerprint and monotonic offset window. Clients use the last valid anchor to fast-resync when encountering partial JSON (instead of replaying from the start of the message or invoking expensive reassembly). - Resume handshake: when a client reconnects and provides the last-received-offset+fingerprint, the server validates and emits a concise resume-ack event with a tool-call lease marker if necessary; this lets in-flight tool/function call handoffs continue without duplicating sentinel delimiters. - Hedging & safety: If anchor validation fails, server falls back to existing seq-checkpoint reassembly; anchors are advisory only. No change to user-facing API surface for non-streaming endpoints. Implementation highlights: - service/sse/stream_reassembler.go: new AnchorWindow struct, anchor emitter, checksum-friendly fingerprint algorithm. - openai-compat/streaming_adapter.go: resume handshake integration with OpenAI-compatible SSE framing; retain backward compatibility when head_branch flag is unset. - sdk/typescript/streaming.ts: client-side resync path, anchor-aware parser, resume handshake helper. - tests/integration/streaming_resume_test.ts: end-to-end test exercising abrupt disconnect + resume with tool-call in progress. - docs/streams/anchor-window.md: protocol and client guidance. Rollout and compatibility: - Feature gate: default enabled on main for OpenAI-compatible streaming only. Non-compat clients ignore anchor frames (treat as comments). - Backward compatible: older clients continue to function; they simply ignore the anchor event. - Metrics: new counters (sse.anchor_emitted, sse.resume_success, sse.resume_fallback) added to Redwood Console. Testing and CI: - Added unit/integration tests. CI initially reported a flaky streaming-integration test (timeout under heavy load); re-ran the job after increasing test harness timeouts and added a deterministic reconnect schedule to eliminate nondeterminism. All checks green on final run. Security: Anchor fingerprints are non-secret, short (base64-encoded 8 bytes) and do not contain user payload. No changes to auth or token model. Risk and mitigation: - Risk: premature adoption by non-compat clients could create parser churn; mitigated by explicit feature gate and clear client guidance in docs. - Risk: slight CPU overhead for computing fingerprints; benchmarked and shows <0.5% added CPU at p95 under realistic workloads. Related work: builds on ENG-1129 (seq-checkpointing) and complements ENG-1184 (tool-call handoff stability).
