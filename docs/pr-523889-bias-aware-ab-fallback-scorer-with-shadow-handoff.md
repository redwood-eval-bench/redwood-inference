# bias-aware-ab-fallback-scorer-with-shadow-handoff

Context: We needed a safer A/B fallback for model promotes when cohort-level distribution shifts or demographic skews surface during staged rollouts. This change introduces a bias-aware fallback scorer that augments existing metric gates (latency, error-rate, quality) with an orthogonal causal-smoke signal and per-cohort fairness delta. Design: 1) Decision pipeline extension: a bias scorer runs after metric gates and produces an explainable fallback score (0-1) per cohort. 2) Shadow handoff: when score exceeds threshold, traffic is shifted to a shadow lane with enforced isolation and synthetic causal-smoke tests enabled for deeper evaluation. 3) Rollback credits: automatic limited rollbacks are issued based on score magnitude and risk budget. 4) Playbook and UI: rollout playbook and dashboard indicators to show causal-smoke trends and cohort fairness deltas. Implementation summary: - New module rollout/safety/bias_scorer.go implements a configurable ensemble (KL, wasserstein, covariate-shift heuristics + fairness deltas) with human-readable rationale strings. - Orchestrator pipeline updated to call BiasScorer after primary SLO checks and before promote/abort decisions. - Shadow lanes now support a temporary synthetic-smoke runner that generates deterministic stimuli for counterfactual checks. - Telemetry: new metrics rollout.bias_score, rollout.cohort_fairness_delta and tracing tags rollout.shadow_handoff. - Tests: end-to-end integration tests that simulate cohort skews and verify rollback credit accounting. Checklist: [x] Design doc linked (Linear ENG-2048) [x] Unit tests for scorer logic [x] Integration synthetic smoke harness [x] Playbook and dashboard changes [x] Backward compatible config (defaults off) How to validate locally: run ./hack/run-smoke --cohort=geo-eu --seed=42 then watch rollout.bias_score; expected: >0.6 triggers shadow handoff. Rollout plan: feature flag gated, initial rollout to internal ring followed by staged canary (1%, 5%, 20%) with automated shadow handoff enabled in 5% stage only. Related: builds on earlier shadow-promote work; see SUP-768 for customer incident context. Risks and mitigations: false positives from scorer - mitigated with hysteresis and minimum sample size; performance - scorer is optimized and offloaded to worker pool; observability - added dashboards and alert thresholds. Migration: no DB migrations. Config knobs: rollout.safety.bias_threshold, rollout.safety.hysteresis_window, rollout.safety.min_cohort_samples. This PR is a bundled change (runtime + orchestrator + telemetry + docs) to enable safer A/B promotes with automated fallback and explainability.
