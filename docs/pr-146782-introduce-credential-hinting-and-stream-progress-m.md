# Introduce credential hinting + stream progress helpers across Python/TS/Go; SDK version bumps

Context and motivation: Production services have edge cases where transient auth refresh costs and retry aggressiveness interact poorly with batching/streaming workloads. This PR introduces a compact credential-hinting surface across the three SDKs so the runtime and client can better align retry heuristics, prefetch windows, and stream reconnect strategies. The change also adds a small 'stream progress' helper that surfaces token-level progress and a stable checkpoint marker for resumable consumers. Goals: 1) Reduce unnecessary reauth/retries in high-throughput scenarios, 2) provide ergonomics that make stream consumers easier to implement (pause/resume/cancel), 3) keep cross-language parity and bump SDK versions with clear migration notes. Summary of what changed: - New public API: CredentialHint (opt-in) and StreamProgress hooks implemented for Python, TypeScript, and Go SDKs. - Backwards-compatible adapters: existing token providers still work; hint APIs are additive. - Retry policy integration: SDKs now surface hint metadata in retry telemetry and use it to moderate short-circuit retries. - Tests and examples: added integration tests that simulate token refresh storms and a new example app (examples/credential-hint-demo) showing best practices. - Changelog and version bumps for each SDK package.   Notes on design tradeoffs: - Opt-in: the hint surface intentionally does not change default retry semantics; users must opt in to supply hints or use the higher-level session wrappers. This reduces risk for existing consumers. - Conservative telemetry: SDKs tag hints in telemetry but do not expose them in server APIs; server-side routing can consume hints later when enabled. - Backwards compatibility: adapters allow old token providers to be wrapped without code changes; the migration guide includes recipes.

  Testing: - Added unit tests for each SDK that validate the hint is forwarded into the retry decision path and that stream progress markers are emitted at expected thresholds. - End-to-end integration tests simulate a burst of token expirations and verify reduced reauth churn when hinting is enabled. - Go tests updated to use deterministic clocks to avoid flakiness.

  Rollout plan: - Feature is behind an opt-in flag in hosted runtime and disabled by default in Redwood Dedicated. - Release SDK versions 1.8.0 (python), 2.4.0 (typescript), 1.5.0 (go) in a coordinated fashion; announcements include migration notes and example snippets.
