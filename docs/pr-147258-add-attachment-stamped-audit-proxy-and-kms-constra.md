# Add attachment-stamped audit proxy and KMS constraint optimizer

Motivation: Customers operating in regulated zones requested stronger, append-only audit artifacts that carry compact, verifiable sealing information per request attachment (payloads, model outputs, and routing metadata). At the same time, repeated KMS selector calls across region boundaries were a measurable contributor to latency and billing spikes for multi-tenant workloads. This PR implements two coordinated features: 1) an attachment-stamped audit proxy that signs a compact attachment fingerprint using tenant-scoped KMS keys and emits a sealed audit envelope with provenance headers; 2) a KMS constraint optimizer service that pre-computes region-aware key candidate sets and caches selection decisions for short TTLs, falling back to strict validation when constraints change. Changes include server-side runtime hooks, a small client-side SDK helper for generating attachment fingerprints, policy updates for RBAC v2 to allow temporal sealer grants, and migration steps for audit ingesters. Scope: - runtime/service: new attachment sealer middleware and audit-envelope composer - kms service: constraint optimizer + metrics and decision cache - authz: RBAC v2 role template for 'sealer.grant' with timebound allowance - sdk: helper function in redwood-sdk-go and redwood-sdk-python to compute attachment stamps - infra: migration task that backfills audit index entries with new headers Backwards compatibility: Audit messages without attachment stamps are accepted; when stamped messages are present ingesters verify stamp signatures if the tenant flag is enabled. Rollout plan: 1) Feature flag off by default. 2) Canary deploy proxy in us-west-2 with a single high-volume tenant. 3) Monitor audit verification error rates and KMS constraint cache hit ratio. 4) Gradual enablement per-tenant via Console.
