# Add rollback dashboard panels + annotations for Optimization Config apply/promote/rollback events

Summary: This PR updates the "Optimization Rollout Health" Grafana dashboard in observability-pack to make safe apply + rollback operations visible and diagnosable during canaries and incident response. It adds (1) dashboard annotations for Optimization Config lifecycle events (apply, promote, rollback, gate pause/fail) and (2) panels that slice the core health signals by optimization_config_version to quickly confirm whether the rollout is causing elevated error/latency or saturation. Motivation: During the gameday drill and a recent customer escalation (SUP-18421) we spent too long correlating p95 regressions with the exact config version + rollback timestamp because charts weren’t consistently annotated and most panels lacked config_version breakdown. This is a prerequisite for GA readiness (PM-904) and supports the auditability story for enterprise (SUP-18544 follow-up: 'prove rollback happened at X time and the metrics recovered'). What’s included: - Annotations: Adds an annotation query that pulls Optimization Config events from the control plane event stream (exported into Loki) and renders vertical markers for apply/promote/rollback, scoped by tenant/model/region. Events are labeled with config_name, config_version, actor, and rollout_id. - Panels (new): (a) Error rate (5xx) by config_version, (b) p95/p99 latency by config_version, (c) Throughput + queue depth, (d) GPU utilization + KV cache hit rate, all with templated variables tenant/model/region and a new variable optimization_config_version. - Panels (updated): Existing "Overall health" panels now include legend formatting to surface config_version when present and fall back gracefully for older workers that don’t emit the tag yet. - Templating: Adds variables for rollout_id and config_version with sensible defaults; when unset, panels aggregate across versions as before. - Documentation: Updates dashboard README to document required metric tags (tenant, model, region, optimization_config_version) and the minimum versions of runtime/control-plane exporters required for annotations to populate. Compatibility/rollout notes: - Metrics: Panels use the new tag name "optimization_config_version" (per the metrics spec agreed with platform/runtime). If a cluster is still on older exporters, those series simply won’t appear in the by-version panels; the aggregate panels remain usable. - Logs/annotations: Annotation query relies on control-plane events being shipped to Loki under stream {app="control-plane", component="opt-config"}. Private deployments can wire the same annotation by shipping audit/event logs, but it’s optional; doc notes included. Testing: - Verified dashboards render locally in grafana-dev with the sample Prometheus/Loki datasets. - Ran jsonnet compilation + grafana-lint in CI. - Smoke-checked templating and annotation query performance (kept to 24h default with user-controlled range). Screenshots: Attached in the PR UI: 1) Annotated latency chart showing apply->promote->rollback markers, 2) Error rate panel split by optimization_config_version, 3) Variable dropdowns for config_version/rollout_id. Follow-ups (not in scope): - Add a "gate decision" panel that displays the evaluated gate status over time (pending signal from slo-toolkit integration). - Add a compact "Rollback summary" row for on-call (MTTD/MTTR inputs) once incident-bot emits incident_id tags.
