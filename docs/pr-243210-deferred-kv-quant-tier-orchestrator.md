# Introduce deferred-KV-eviction + quant-tier orchestrator and tenant econ profiles

Motivation: long-tail conversational traffic and multi-tenant variability mean the KV cache is frequently evicted from mini-batches even though reusing older KV fragments would save tokens and improve unit economics. Separately, tenant-facing quantization defaults are too coarse: some tenants can accept int8 for background low-SLO routes while others require fp16 for latency-sensitive chat. This PR adds two coordinated pieces: 1) a deferred-KV-eviction policy in the serving runtime that postpones eager KV eviction for low-probability prefix reuse and exposes eviction scoring for per-tenant policies; 2) a quant-tier-orchestrator service + CLI that evaluates unit-econ vs latency tradeoffs and dynamically routes tenants to quantization tiers (fp16, int8, int4-probative) with safety fallbacks. Changes include a lightweight controller that ingests tenant cost/latency targets and historical token shapes, an offline candidate generator to produce per-tenant compact quant profiles, runtime hooks to switch quant mode per-route, telemetry to record econ delta per rollout, and a CLI command (redwood econ profile apply --dry-run) for safe dry runs. Safety: automated rollback if P95 latency increases > 20ms or hallucination regressions detected via evaluation hooks; default fallthrough to fp16 for tenants without profiles. Backwards compatibility: config flags default to off to avoid surprise behavior; operator opt-in required for private/dedicated installs.
