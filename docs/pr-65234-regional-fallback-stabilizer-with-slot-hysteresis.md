# regional-fallback-stabilizer-with-slot-hysteresis

Motivation: recent incidents showed oscillation during geo failovers where the regional fallback policy would rapidly flip routes and trigger downstream cache churn, increasing 95th latency and exhausting error budgets. This PR introduces a stabilizer that: 1) converts the fallback decision into slot-scored windows so that a region must hold a score threshold for a minimum hysteresis window before traffic is moved, and 2) couples the decision to a telemetry-weighted SLO smoother that discounts transient spikes and only triggers emergency fallback when sustained error-budget drain is observed. This is a small hotfix aimed at reducing failover flapping while preserving fast failover in true outage cases. Changes: - Add slot-based hysteresis scoring and cooldown for regional fallback decisions. - Introduce session-aware eviction: requests in a session keep KV-cache affinity unless an aggressive outage threshold is crossed. - Telemetry-weighted SLO smoother: blend of recent error-rate and longer-window error-budget consumption to avoid reacting to noise. - Expose two new runtime knobs: fallback.hysteresis_window_ms and fallback.slot_threshold and a debug metric fallback.stabilizer_score. - Hotfix fallback: when stabilizer detects persistent high error-budget drain for >2 minutes, it lowers slot threshold and triggers an emergency fallback path (configurable). Rollout plan: staged canary 5% EU -> 25% EU -> 10% NA -> global after 24h monitoring. Rollback: immediate rollback if canary sees >1.5x baseline 95th latency or any SLO regressions in alerting groups. Checklist: - [x] Unit tests for scorer logic - [x] Integration tests for canary policy - [x] Perf bench with synthetic failover - [x] Dashboard panels for fallback.stabilizer_score and hysteresis windows - [x] Linear/SUP links in PR body Related: ENG-4219 for long-term routing rewrite; SUP-8843 incident that triggered this hotfix. Notes: This is intentionally conservative: default hysteresis_window_ms is 1500ms and slot_threshold 3 (three consistent slots within window). Emergency fallback path is more permissive but gated by sustained telemetry. See release notes for behavior and knobs.
