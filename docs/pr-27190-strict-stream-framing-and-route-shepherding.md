# Strict stream framing and route shepherding: stabilize function-calls and enforce route-level payload guards

Motivation: intermittent corruption and dropped frames in the streaming proxy were causing tool/function-calling handshakes to fail for a subset of routes and large payloads. This PR introduces a strict stream framing protocol in the gateway proxy, a route-level shepherding policy that enforces payload size and framing invariants, and an OpenAI-compat shim update to make function_call/structured-output recoverable after partial frames. The change is gated behind a feature flag and rolled out as a canary; it also tightens per-route payload enforcement to prevent unbounded memory growth from malformed clients. Key changes include: 1) framing layer: add explicit 4-byte length prefix for framed proto/JSON chunks at the proxy boundary with CRC-8 validation; 2) backpressure metadata: attach per-chunk high-water signals to avoid excessive buffer accumulation while preserving low-latency streaming for small messages; 3) shepherd policy: route config additions to declare "shepherding" mode, max_payload_bytes, and strict_fncall_handshake; 4) OpenAI-compat shim: tolerate mid-stream JSON token boundaries by emitting incremental JSON-patch events and a final reconciled function_call object; 5) graceful fallback: when shepherding detects repeated malformed frames, requests are downgraded to non-streaming mode with an observability event and metric. Rollout is canary-scheduled and default-off for Dedicated/Private customers until helm values are available. This PR bundles proxy, gateway config schema, small changes to the openai-compat adapter, tests for race/partial-frame handling, and migration docs.
Improves streaming stability and function-calling reliability by adding strict framing and per-route shepherding. Introduces a new route config (shepherding + max_payload_bytes) and a feature flag gateway.strict_streaming. Notable behavior: malformed or repeated partial frames will now cause an automatic downgrade to non-streaming response and increment a metric gateway.stream.downgrades.
Private/Dedicated operators: upgrade gateway image and set helm value gateway.strict_streaming.enabled=false to retain previous behavior until you are ready to opt-in
If using ingress sidecars that terminate streaming connections, ensure they support length-prefixed frames or disable strict_streaming on the gateway
If you rely on unbounded route payloads, set route-level max_payload_bytes in gateway config to a suitable high value to avoid early truncation
OpenAI-compat adapter emits incremental json-patch events so clients that expect chunked function_call tokens will still reconstruct the final object. Legacy clients that assume raw token stream may see a change in framing; the gateway will fallback to non-stream mode for malformed frames to preserve correctness.
