# Helm: values-driven tenant RBAC automation with safe rollback hooks

Motivation: private installer deployments require an idempotent, auditable way to seed tenant-scoped RBAC without granting cluster-admin to the installer process. This PR adds a values-driven approach to enable tenant RBAC automation from Helm installs/upgrades and introduces a safe, cluster-side reconciliation job to pick up and apply curated policy bundles. Summary of changes: 1) New Helm values: "tenantRbac.enabled" (bool), "tenantRbac.bootstrapServiceAccount" (string), "tenantRbac.policyBundleConfigMap" (name) and a "tenantRbac.rollbackStrategy" option. Values can be toggled per-release or per-environment so operators can opt into automation. 2) Template: charts/redwood-private/templates/tenant-rbac-cronjob.yaml — a controllerless, namespaced CronJob that reads the configured ConfigMap with policy bundles and applies roles/rolebindings for tenants in a guarded/limited way (uses a dedicated SA with narrowly scoped permissions). 3) Hook templates: charts/redwood-private/templates/hooks/tenant-rbac-post-upgrade-hook.yaml and pre-upgrade validation job; these enable graceful rollouts and automatic idempotent reconciliation during upgrades. 4) Helper: charts/redwood-private/templates/_rbac-helpers.tpl — templated role manifests and a checksum annotation to trigger canary reconcilers only when policy changes. 5) Integration: small connector that exports a TenantPolicy CR name to a Secret so private-installer can drive tenant creation without cluster-admin. 6) Docs: expanded README values table and operator migration guide for private installs. Safety and rollout: the cronjob runs with a configurable schedule and supports a "dryRun" flag and a "maxConcurrentApplies" limiter. All cluster-facing actions are scoped to tenant namespaces and use least-privilege SAs created by the chart. There's a guarded rollback strategy: when "rollbackStrategy: conservative" the hook will remove only resources it created and leave tenant data untouched. Backwards compatibility: defaults are off — installing older helm releases will behave unchanged. Test plan and verification: - unit: helm template checks and kube-linting added to CI. - integration: e2e run in CI using kind with simulated multi-tenant namespace injection; verified idempotency by running the cronjob loop 5x and asserting no duplicate bindings. - manual: private-installer QA validated migration path in a staging VPC cluster. Related items: ENG-1921 (tenant onboarding automation), ENG-1983 (rbac least-privilege audit). Checklist: [x] Helm values docs updated, [x] unit tests added, [x] integration e2e, [x] safety flags and dry-run, [x] reviewer approvals. Rollout notes: enable tenantRbac.enabled=false initially; flip to true for staging and monitor the "redwood.rbac.apply_success_total" metric and audit logs. If any unexpected failures occur, use the post-upgrade-hook annotation "redwood.io/skip-rbac-reconcile=true" to freeze automation and follow the manual remediation doc.
