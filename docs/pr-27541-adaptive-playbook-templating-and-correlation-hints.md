# Adaptive playbook templating and incident-correlation hints

Motivation: On-call playbooks are frequently copied/edited per-service; we want parameterized, audit-friendly runbooks that can be rendered from alert context to reduce human error and speed MTTR. This PR adds a safe templating layer for SLO Toolkit playbooks and a lightweight incident-correlation hinter that surfaces nearby incidents likely related to the current alert. High-level changes: 1) playbooks/schema v2 with templating placeholders and conditional steps; 2) a sandboxed renderer using a limited templating DSL (subset of Jinja-like syntax, no arbitrary code); 3) an incident-correlation hints engine that computes three candidate correlated incidents per alert based on service/trace overlap, metric fingerprint similarity, and time-window heuristics; 4) CLI and web UI preview commands for rendered playbooks; 5) a migration helper (slo playbook migrate) to convert v1 playbooks to v2 automatically where possible. Backwards compatibility: v1 playbooks still supported; new renderer only activates for playbooks with "template_version: 2". Feature gated behind 'playbook_templates' flag and rollout plan described below. Implementation notes: - Template engine implemented in slo_toolkit/playbooks/renderer.py with a strict AST parser and whitelist for filter functions (date, truncate, split, join, lower, upper). No eval or import allowed. - Context keys: alert (metadata), telemetry (topN metrics snapshot), traces (sparse trace ids), recent_incidents (IDs and metadata). - Correlation hints implemented in slo_toolkit/correlation/hinter.py using a small ensemble: service overlap weight, metric fingerprint cosine similarity, and temporal proximity score. Candidates returned with explanation snippets for the UI. - Web UI: added preview pane and correlation hint panel to alert details (webui/alert_preview/*). - CLI: "slo playbook render --alert-id <id>" and "slo playbook migrate --dry-run" added. - Migration: slo_toolkit/migrations/migrate_v1_to_v2.py attempts safe substitution with warnings for manual review. Tests and validation: extensive unit tests for renderer and hinter; an integration test harness simulates incident-bot alerts and validates rendered output contains expected substitutions and no disallowed constructs. Security: initial security scan detected a potential template-injection vector in early impl; replaced the engine with the AST whitelisting approach and added fuzz tests. Rollout and operational plan: - Feature gate by default OFF. - Canary to 3 small teams for 2 weeks with manual opt-in. - Monitor renderer latency (p95 < 50ms) and correlation hint recall/precision via labelled incidents. - Auto-rollback if error-rate for alert pages increases by >1% or if rendering latency crosses 200ms for more than 5 minutes.
