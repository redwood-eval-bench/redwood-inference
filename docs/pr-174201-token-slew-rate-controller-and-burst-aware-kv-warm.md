# Introduce token slew-rate controller and burst-aware KV warmup to reduce streaming TTFB variability

Introduces a token slew-rate controller to smooth token emission and a burst-aware KV warmup heuristic which together reduce TTFB variance for streaming workloads. Backwards compatible with existing runtime configs; opt-in via config flags.
Motivation: customers reported high tail TTFB variance in low-latency streaming under mixed workloads where short interactive requests were interleaved with occasional long generation bursts. Existing credit/burst controllers either clamped too aggressively (hurting throughput) or allowed micro-bursts that caused KV cache thrash and long tails. This PR adds two coordinated mechanisms: a token slew-rate controller that enforces a bounded emission acceleration/deceleration profile per stream, and a burst-aware KV warmup heuristic that opportunistically prefetches KV slots for streams predicted to enter a burst phase. The design goal is to reduce first-byte latency variance without regressing throughput or increasing p50 latency. Implementation summary: 1) Token slew-rate controller: new per-stream state machine that tracks recent token emission velocity and applies a configurable slew-rate (tokens/sec^2) limiter; integrates with the existing emitter tick so flush cadence respects both credit buckets and slew constraints. 2) Burst prediction: lightweight heuristic based on prompt metadata, user-specified max_tokens hints, and recent stream length history to decide a burst-likely window; predicted bursts trigger a short, bounded KV prefill where we issue non-blocking KV fetches for upcoming key ranges. 3) Coordination: controller exposes a short-lived 'prefetch hint' which the KV prefetch subsystem uses to prioritize warmups; the emitter will avoid large immediate flushes if a prefetch is in flight. 4) Config and ops: new runtime flags (token_slew_enabled, token_slew_rate, kv_burst_prefill_enabled, kv_prefill_window, kv_prefill_budget) and operator metrics for slew headroom, prefill successes/fails, and prefill-induced stalls. Benchmarks: microbench harness (continuous-batch mixed-short-long) shows 95p TTFB improvement of 18-23% across N=3 hardware profiles (A100, H100, T4) with p50 change within ±2%. End-to-end production-like traces show fewer KV eviction spikes during bursts. Safety and fallbacks: if prefill hits a rate limiter or the kernel scheduler cannot honor prefill IO, prefill requests are aborted and we fall back to standard on-demand KV lookups; slew limiter can be disabled per-route. Rollout plan: gated feature flag rollout to dedicated clusters for one week, extended smoke tests, metrics dashboard to track TTFB p50/95/99, KV miss rate, and throughput. Follow-ups: add ML-based burst predictor, expose per-tenant defaults, and improve prefill budget auto-tuning.
