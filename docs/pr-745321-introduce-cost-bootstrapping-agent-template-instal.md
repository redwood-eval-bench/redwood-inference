# introduce-cost-bootstrapping-agent-and-template-installer

Motivation: Onboarding tenants and creating sane defaults for batching, caching, and quantization profiles remains manual and error-prone, causing inefficient unit economics for new customers and repeated operations work. This PR adds a Cost Bootstrapping Agent (CBA) that generates tenant-aware defaults and a Template Installer CLI to apply/validate presets across Hosted/Dedicated/Private deployments. Goals: 1) provide deterministic, conservative defaults at tenant onboarding that can be adjusted by the optimizer later; 2) validate quantization profiles against unit-econ safety thresholds to avoid quality/cost regressions; 3) offer a dry-run mode and synthetic workload simulator for safe rollouts; 4) emit telemetry for decision tracing and rollback audit. What this PR does: - Adds a new long-running service pkg/econ/cost_bootstrap_agent with heuristics that combine tenant traffic signals, recent model selection, and region hardware costs to create a default profile including batch size hints, cache TTLs, and quantization candidate ranks. - Implements a CLI (cmd/cost-template-installer) which will accept a preset bundle (templates as JSON) and apply them to the tenant config store with a validation step that runs the new unit-econ validator. The CLI supports --dry-run, --simulate-traffic, and --canary-percent. - Introduces internal/quant/profile_linter that scores quant profiles by predicted quality delta vs cost savings using recent eval embeddings; profiles that exceed the configured loss budget are rejected or demoted. - Adds a lightweight synthetic-workload runner under tests/e2e/bootstrap_integration_test.go used by CI to exercise the generation and install path. - Adds observability hooks to Redwood Console: events/cost_bootstrap.created, .applied, .rejected and metrics econ.bootstrap.duration_ms, econ.bootstrap.quality_risk. - Implements a conservative fallback that ensures any automated profile cannot reduce per-request quality score more than the tenant safety delta (default 0.02). Rollout plan: merge -> gradual rollout behind feature-flag econ.bootstrap.enabled default=false -> enable for 10 internal tenants -> expand to new self-serve onboardings and opt-in for existing tenants. Backwards compatibility: the installer does not mutate existing tenant profiles unless --force is passed; default behavior writes a 'suggested' entry in tenant metadata. Security/permissions: installer requires the cost-template:write RBAC permission; agent runs on control-plane with limited IAM scope. Checklist: [x] new agent code and tests [x] CLI for templates and validation [x] unit-econ validator and quant linter [x] e2e CI synthetic run [x] telemetry/events [x] docs and runbook. Related: ENG-2432 outlines the tenant onboarding pain points, SUP-789 is a customer report where quantization rollout caused a user-visible quality regression. Known limitations: current heuristics assume steady-state traffic shape; very bursty short-lived tenants may get overly conservative defaults. Future work: tie into Optimize suggestions engine for automated profile upgrades and a feedback loop for active learning on quality predictions.
