# session-fenced-rolling-cutover-with-telemetry-lock-and-rewind

Motivation: production canary cutovers occasionally expose session-affinity regressions when a model swap drains existing sessions. This PR introduces a session-fenced rolling cutover executor that: 1) acquires a short-lived telemetry lock for a cohort during each step so metrics observed during a step cannot be overwritten by concurrent rollouts, 2) enforces session-fencing on swap so in-flight sessions are either pinned to the old model until completion or moved atomically to a warmed instance depending on policy, and 3) exposes a rewind handle for operator-driven fast revert (replayable snapshot of routing state). This reduces noisy telemetry and avoids mixing signals across overlapping rollouts. Changes included: - new orchestration executor (CutoverExecutor) that sequences cohort-level cutover with lock leases - session fencing mode (pin | migrate) with safe drain heuristics and KV-cache-aware handoff - telemetry lock on the metrics pipeline with lease and ownership tags - lightweight rewind journal that captures routing state + snapshot pointer for immediate revert - integration test harness for simulated multi-cohort traffic and smoke replay Checklist: - [x] CutoverExecutor implementation - [x] Session fence mechanics + migration path - [x] Telemetry lock integration and lease renewal - [x] Rewind journal and revert API - [x] Unit and integration tests - [x] Docs: rollout-runbook and operational playbook Notes: this is targeted at the hosted/dedicated control plane and is intentionally backwards-compatible by default; existing rollouts continue to use the previous executor unless customers opt-in via rollout.policy.cutover_strategy. Related linear: ENG-4321 (session fencing design), ENG-4380 (telemetry lock prototype). Rollout impact: opt-in only, no mandatory migration.
