# Add fractional RAG session replay wizard and interactive docs playground

Add a fractional session replay wizard to docs: interactive playground + example sessions. Enables engineers to replay segments of RAG conversations for deterministic debugging, reproduce model/tool interactions, and attach telemetry slices. No breaking changes; opt-in feature behind docs playground flag.
Motivation: debugging RAG flows is often noisy — developers asked for a way to replay narrow time windows of an agent/session (a few turns, or a particular tool call) without rerunning upstream index/ingest or exposing full production traces. This PR introduces a fractional session replay wizard in the docs playground: a small web UI + backend helper that can load a saved session, let users select a fractional time range or token window, and step through generation + tool calls with deterministic inputs.\n\nWhat this PR contains (high-level):\n- docs/playground guide: new page explaining the replay wizard UX and best practices, with screenshots and annotated flow.\n- interactive playground: embeds a JS replay player that fetches trimmed session JSON and drives a stepper UI.\n- examples: three sample RAG sessions (simple Q/A, multi-tool booking flow, and a failure reproduction).\n- SDK integration example (TypeScript): shows how to produce a session envelope that the replay player consumes.\n- telemetry hooks: small metrics emitted for replay start/stop, fraction selected, and tool-call replayed counts.\n- tests: headless puppeteer test that runs the player in CI and asserts deterministic outputs for the provided sample session.\n\nChecklist:\n- [x] Add docs page and frontmatter with redirect to playground\n- [x] Add replay player JS + minimal CSS and accessibility labels\n- [x] Add three example session JSON files\n- [x] Add TS SDK example + README snippet\n- [x] Add telemetry config for replay metrics\n- [x] Add integration test and CI job entry\n- [x] Add release note entry in changelog\n\nHow it works (short):\n1) A session JSON is a simple envelope: metadata, turn list, tools invoked (with deterministic tool inputs/outputs), and model seeds.\n2) The replay wizard accepts a fractional range (e.g., 0.22-0.37 of the session timeline) or absolute turn indices.\n3) The replay player trims the envelope server-side (so we only transfer the slice) and then replays deterministically in the browser by feeding each step to the local stepper runtime. For tool calls, the player can either show recorded outputs or re-invoke them via a sandboxed stub if the developer opts-in.\n\nBackward compatibility / rollout:\n- The feature is opt-in in the docs playground via a "replayEnabled" flag. No runtime changes required for hosted inference. The SDK example shows how to annotate sessions but does not modify existing production telemetry.\n\nTesting & QA notes:\n- Added puppeteer integration test that loads the player, selects the fractional slice for the multi-tool sample, and asserts the UI step output matches expected recorded outputs.\n- Manual QA: cross-browser smoke for Chrome/Edge and keyboard-only navigation for accessibility.\n\nLinks and references:\n- Example sessions stored under examples/rag/replays/\n- Docs preview: https://docs.redwood.com/rag/playground/replay-wizard (internal preview)\n- Linear: ENG-2149 (design + prototype), PM-1884 (product acceptance)\n\nKnown limitations:\n- Replay currently supports only sessions produced by the new session envelope schema (SDK example included). Older session formats will require a lightweight migration script (tracked in follow-up).\n- Tool re-invocation in sandbox mode is limited to stubbed adapters (do not use with live production tool endpoints).\n\nMerge notes: squash-merged to main. The feature is gated behind the docs playground flag; marketing will be notified before public posts.
