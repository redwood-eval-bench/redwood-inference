# Phase-gated A/B traffic orchestrator with consensus-fallback

Context: Teams running multi-variant A/B experiments and gradual canaries have asked for a lightweight controller that can enforce phase gates (time + metric window) across heterogenous cohorts, allow a consensus-driven automatic rollback, and provide a replayable failover path for shadow traffic. This PR introduces a Phase-Gated A/B Traffic Orchestrator: a runtime controller and small API surface that sequences traffic phases, enforces metric-based acceptance gates, and escalates to a consensus-fallback when automated thresholds disagree. Motivation: simplify safe promotes across multi-arm experiments without requiring bespoke orchestration in product code. Design summary: - Phase model: phases are timeboxed windows with an explicit acceptance policy (primary metric, min-sample, direction). - Consensus fallback: if arms disagree (e.g., two arms pass, one fails), the controller computes a weighted consensus from predefined anchors (slo, canary-priority, safety-debt) and either HOLD, PROMOTE, or ROLLBACK. - Shadow rehearse: traffic snapshots are storable and replayable against a candidate model for rapid triage and deterministic rollback. - Replayable rollback playbook: a small ledger that records phase events, metric deltas, and snapshot pointers for forensic replay and human-in-the-loop correction. Changes included (high-level): - pkg/orchestrator/controller.go: new orchestrator loop, phase state machine, gating logic. - api/v1/rollouts.yaml: CRD additions for PhaseGateSpec and ConsensusPolicy. - cmd/rolloutctl: CLI for creating phases, snapshotting traffic, and initiating manual rollbacks. - webapp/src/components/RolloutTimeline.tsx: dashboard controls to visualize phases and consensus decisions. - tests/integration/phase_gated_e2e_test.go: integration harness simulating A/B traffic. - docs/runbooks/phase-gated-orchestrator.md: runbook and playbook for SRE/responders.
