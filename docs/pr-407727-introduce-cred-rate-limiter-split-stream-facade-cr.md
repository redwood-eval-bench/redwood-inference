# Introduce credential rate-limiter and split-stream facade across SDKs (Python/TS/Go)

Context and motivation: A recurring customer pattern and internal benchmarks showed that short-lived auth token churn plus high-concurrency streaming clients could cause transient auth failures and noisy retries across SDKs. This PR addresses two cross-cutting problems: 1) a lightweight, configurable credential rate-limiter/pacing adapter that prevents aggressive token refresh storms and provides an opt-in global throttle; 2) a split-stream facade that separates control-plane (heartbeat/lease) events from data-plane chunk streams to improve ergonomics for consumers and reduce accidental reauthentication races. Summary of changes: - Python: add CredRateLimiter utility (redwood_sdk.auth.rate_limiter), integrate into SessionManager; introduce SplitStream class in streaming.facade with clear async iteration semantics; bump package to 2.8.0-rc. - TypeScript: add credential-pacer utility (packages/ts-sdk/src/cred/pacer.ts), expose through ClientOptions. Introduce SplitStream<T> typed facade and migrate chunked-stream internals to new factory. Bump SDK to 1.27.0-rc. - Go: add cred/pacer package and a non-blocking leaky-bucket limiter used by session refresher; introduce splitstream facade in stream/facade to provide a typed channel for control messages and a data channel for tokenized chunks; bump go-sdk to v1.5.0-rc. Cross-cutting: unified retry preset updated to include a small jitter when rate-limiter is active; docs and examples updated to show migration path; unit and integration tests added across SDKs. Design notes and rationale: - The rate-limiter is intentionally conservative: default disabled, opt-in via client config; when enabled it applies only to refresh/reauth flows not to regular request tokens. - SplitStream separates event and payload concerns (control vs data) to avoid race conditions where a reauth heartbeat would be consumed by a data consumer. - Backwards compatibility: the existing streaming APIs are preserved; SplitStream is exposed as an additional ergonomic facade and old factories still available. Checklist: - [x] Cross-SDK API surface defined and reviewed - [x] Unit tests for Python/TS/Go - [x] Integration tests (streaming + auth churn) - [x] Docs/examples updated - [x] Release notes drafted Testing and CI: several flaky integration matrix runs were required to validate interplay of pacing + retry windows; one flaky test (ts://integration/stream/reconnect) required a targeted sleep jitter fix. Risks and roll-out: rate-limiter is opt-in and feature-gated; recommended roll-out path is to enable in non-critical environments for 72 hours and monitor cred-prefetch metrics. Related work: builds on ENG-4871 (session prefetch) and ENG-4920 (stream ergonomics).
