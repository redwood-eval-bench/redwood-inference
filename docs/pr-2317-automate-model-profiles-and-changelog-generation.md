# add automation for onboarding model performance profiles and changelog generation

Motivation: reduce manual friction when adding new models to the registry by automatically producing a standardized performance profile and an entry in the release changelog. This PR wires together the benchmark-lab harness, the model metadata schema, and a changelog generator so that onboarding engineers and CI produce deterministic profiles and human-friendly release notes. Summary of changes: 1) New onboarding flow: registry/handlers/onboard_model.py calls benchmark-lab job to produce latency/throughput/quantization profiles and stores results under model_meta.performance_profiles. 2) Metadata validation: registry/schemas/model_metadata.yaml gains required fields (profile_id, benchmark_commit, measured_inputs) and a validator that rejects incomplete profiles during PR checks. 3) Versioning policy: model_version follows semver-like rules documented in docs/registry/versioning.md; automation bumps patch automatically for non-breaking metadata fixes. 4) Changelog automation: tools/changelog/generate_changelog.py parses merged PRs that touch registry/* and emits entries grouped by model and tag (release, hotfix, profile_update). 5) CI: added ci/workflows/registry-ci.yml job that runs a lightweight benchmark (mini-bench) in a flamegraph sandbox to validate profiles. 6) Console: small UI props updated so the console shows generated profile summaries and a changelog preview on model pages. Checklist: - [x] benchmark integration wired and mocked for local dev - [x] metadata schema updated and unit-tested - [x] changelog generator produces deterministic entries - [x] CI job added and green - [x] docs updated for maintainers (performance-profiles.md) Backwards compatibility: profiles are optional for older models; the validator only requires profile_id for models onboarded after this change. Rollout plan: merge to main, let CI produce initial profiles for models in the onboarding queue, monitor registry metrics for profile generation errors. If an issue appears, ops can disable the registry-bench step via feature-flag: REGISTRY_AUTO_PROFILE=false. Testing notes: unit tests cover schema and generator logic; integration run executed in staging with 6 sample models (small/medium/large) using the mini-bench harness; one flaky e2e (model-fetch-timeout) caused a rerun but passed afterwards. Related: ENG-4421 (profile automation), ENG-4470 (changelog UX), PM-884 (onboarding sprint).
