# Introduce compact manifest fingerprint and evaluative delta teasers for release notes

This PR adds two complementary features to the model registry: (1) a compact manifest fingerprint (a canonical, stable hash plus lightweight provenance tag) that makes it cheap to detect content- and metadata-level identity across uploads, and (2) an evaluative delta teaser generator that summarizes the practical impact of profile or metadata changes in a concise, human-friendly sentence used by release notes and the onboarding UI. Motivation: customers and reviewers often need a one-line summary and a stable identifier to decide whether to pin, rollback, or promote a model version; current changelogs are noisy and require manual triage. What I changed: implemented manifest_fingerprint module (Rust), added CLI hook `redwood-model-registry manifest:hash` and server-side endpoint to compute and store fingerprints during onboarding, implemented delta-scorer that combines token-level diffs, latency delta, memory delta, and a weighted importance table to produce a score and a teaser string, and wired an autodraft release teaser generator into the release assembler pipeline. Backwards compatibility: existing manifests still accepted; fingerprint is optional metadata until the rollout flag is enabled for a tenant. Rollout plan: feature-flag gated on `manifest_fp` with gradual enable by percentage, initial harvest for 50 recent onboardings to build importance weights, runtime toggles in Console. Checklist: [x] unit tests for fingerprint and delta scoring [x] integration tests for CLI hook and web hook [x] API docs for new endpoints [x] linear ticket linked and acceptance criteria added. How to validate locally: run `bin/registry --dev manifest:hash path/to/manifest.json` to get fingerprint; run `scripts/teaser_demo.sh` to generate teaser output from two profile snapshots. Related: ENG-7794 for model-onboard ergonomics and PM-1209 for release UX improvements.
