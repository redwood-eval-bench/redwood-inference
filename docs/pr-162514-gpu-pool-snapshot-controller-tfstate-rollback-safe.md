# Introduce GPU pool snapshot controller and TF state rollback safeguard

Adds an automated TF state snapshot controller and a safe rollback mechanism for GPU node pool upgrades. Administrators can take atomic snapshots before disruptive changes; automated rollback uses snapshots and verifies nodepool health. No breaking API changes. Recommended for Private installs with GPU pools.
Context: Private deployment upgrades affecting GPU node pools occasionally led to orphaned TF state or partially-applied changes during cloud-provider interruptions. This PR introduces a controller and Terraform module that take atomic snapshots of TF state and cloud resources prior to nodepool-affecting operations and provide an automated, auditable rollback path. Motivation: reduce mean time to recovery for upgrade failures, eliminate manual state surgery, and integrate snapshots into the installer upgrade flow. What this PR does: 1) Adds a new Terraform module 'tfstate-snapshots' that manages S3/GCS-backed snapshots and KMS-encrypted snapshot metadata; 2) Implements an installer controller 'gpu_snapshot_controller' that triggers pre-upgrade snapshots, records checksums, and publishes snapshot markers to the control plane; 3) Adds a rollback operator that can restore TF state and re-run Terraform apply in a safe, fenced mode; 4) Helm chart changes to include a post-upgrade hook manifest that calls the snapshot controller; 5) Small IAM role update to allow snapshot uploads and ephemeral key usage for restore operations. Migration notes: - Existing installs opt-in by enabling 'snapshotController.enabled=true' in private values.yaml. - When enabled, the controller will take a snapshot before any managed nodepool change. - A one-time role binding is required; the PR includes an automated upgrade job to apply it. Testing and validation: - e2e tests added to tests/e2e/gpu-snapshot-e2e.yaml that simulate provider API flakiness during nodepool update and assert successful rollback to last snapshot; - Local scripts in examples/private provide a reproducible demo; - CI runs terraform validate and an integration e2e pipeline. Checklist: - [x] Terraform module and docs - [x] Controller and unit tests - [x] Helm hook and chart values - [x] e2e test simulating failure and rollback - [x] CI green on merge Notes for reviewers: please focus on the upgrade/rollback race window handling in gpu_snapshot_controller.go, and the IAM scope of the ephemeral restore role. Related tasks: ENG-1432, OPS-88, SUP-9901. Documentation: docs/private/upgrade-rollback.md contains step-by-step enablement. Rollback safety: the controller performs pre-checks (state lock, checksum validation) and will refuse an automated restore if the target snapshot is older than the cluster's last known healthy timestamp. If manual intervention is required, the operator prints an audit-friendly restore plan.
