# Progressive degradation: token-bucket budgeting, cross-region circuit harmonizer, and cache-warm hotfix

Motivation: production incidents showed synchronized regional circuit trips during multi-region overload tests, and a secondary bug where prefix-cache warmups immediately pushed nodes into full-shed. This PR introduces a conservative progressive-degradation policy based on token-bucket budgeting per-customer and a small cross-region 'circuit harmonizer' that staggers circuit breaker backoffs to avoid simultaneous window alignment. It also includes a tight hotfix for the KV-prefix-cache warmup path that incorrectly charged bucket tokens on cache warm events. Changes: 1) SLO enforcer: token-bucket per-tenant with decay and reclaimed tokens on successful responses; budget thresholds map to degrade levels (full, partial, idle). 2) Circuit harmonizer: lightweight coordinator that exchanges small heartbeat metadata via existing routing control-plane to offset breaker reset timers across regions when a global event is detected. 3) Cache-warm hotfix: prevent double-dipping token charges during prefix load; add idempotency marker to cache-warm RPC. 4) Metrics/alerts: new per-tenant budget_utilization metric and harmonizer_stagger_tag to debug correlated trips. 5) Tests: integration test that simulates burst across three regions and asserts no >50% synchronized breaker trips; unit coverage for token decay and reclaim. 6) Docs: operational runbook for progressive degradation and recommended thresholds. Deployment details: feature gated behind runtime.config.degradation.v2 and harmonizer=false by default; harmonizer enabled via cluster rollout for safety. Risk: harmonizer adds small control-plane chatter (configurable TTL) and could delay recovery by up to 2s if misconfigured; default tolerances chosen conservatively. Rollout: staged across capacity pools with canary in eu-west-1 then us-west-2 then global.

Introduces v2 progressive degradation with per-tenant token-bucket budgeting and an optional cross-region circuit harmonizer to reduce correlated breaker trips. Includes hotfix to prefix cache warmup token accounting. Feature gated and rolled out gradually. Admins should review new budget_utilization metric and the operational runbook before enabling globally.
To enable: set runtime.config.degradation.v2=true and optionally runtime.config.degradation.harmonizer=true. Default thresholds are conservative; start with canary region. If harmonizer causes unexpected delay recoveries, disable via config flag. Runbook located at docs/operational/degradation-v2.md.
Backport to release/2026-02 if running older default config and experiencing correlated breaker incidents; hotfix patch for prefix cache warm should be cherry-picked to the nearest current release branch.
