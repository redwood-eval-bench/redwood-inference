# structured-output-token-aware-error-reporting

Context: Customers using structured output (response_format) reported difficult-to-debug schema validation failures when streaming partial chunks and when tool calls interleaved with streaming events. This PR introduces a token-aware error reporting layer plus a lightweight breadcrumbing payload so clients can surface the approximate token offsets and schema path where validation failed. Motivation: Improve developer debugging experience for streaming + strict-schema workflows and reduce support noise from ambiguous schema rejections. Approach: 1) Add an optional tokenDiagnostics object emitted alongside schema validation errors in both streaming and non-streaming flows. Token diagnostics contain: model_token_index_hint (best-effort integer), byte_offset_hint, and schema_path_breadcrumb (dot-separated path into the schema). 2) Implement a streaming-aware validator that keeps a compact checkpoint of the last valid object boundary so we can map validation failures back to the last checkpointed token range. 3) Provide a compatibility shim for OpenAI-compat mode: when the client requests openai_compatible:true we emit diagnostics in a thin, predictable shape and map Redwood error codes to OpenAI-like error strings. 4) Expose a server-side toggle enforce_schema_strictness (default: false) which controls whether streaming schema failures trigger an immediate stream abort (strict) or a best-effort error event with recovery hints (permissive). This PR focuses on the reporting surface and does not change default permissive behavior. Changes: core: src/api/response_format.go - new diagnostics envelope and strictness flag hook streaming: src/streaming/error_mapper.go - streaming validator and checkpointing logic telemetry: src/observability/schema_telemetry.go - new metrics for validation_failures_by_path and diagnostics_emitted docs: docs/openai_compat.md - describes tokenDiagnostics shape and OpenAI mapping SDK: sdk/python/openai_compat_adapter.py - client-side helper to parse diagnostics and correlate token ranges tests: tests/unit/response_format_test.go and tests/integration/stream_schema_diagnostics_test.go - unit and integration coverage for both permissive and strict modes Backwards compatibility: default behavior unchanged; diagnostics are opt-in via response_format v3 and a new query param emit_schema_diagnostics=true. For OpenAI compatibility we add a top-level error field code mapping but keep the original schema_error message for clients that parse human-readable messages. Rollout plan: staged rollout behind feature flag; telemetry on diagnostics_emitted and schema_rejections to monitor noise; notify Android/iOS SDK teams before enabling emit_schema_diagnostics by default. Security/privacy: the diagnostics payload contains byte offsets and schema paths only — no model tokens or PII are captured. Review notes: focused on small footprint in runtime hot path; checkpointing is compact (<=2KB state per stream) and GC'd frequently. See performance notes below.

Benchmarks: permissive mode (diagnostics off) shows negligible overhead; diagnostics-on adds ~0.8ms median per-stream when a validation path is exercised; checkpoint memory per active stream <=2KB; scoped behind feature flag for safe rollout
Example client flow: request with response_format=v3&emit_schema_diagnostics=true; on validation error stream emits: {type:"schema_error", message:"Schema mismatch", tokenDiagnostics:{model_token_index_hint:123, byte_offset_hint:456, schema_path_breadcrumb:"choices.0.content.payload.user.email"}}; SDK helper parse_diagnostics() returns (token_index, byte_offset, schema_path) for UI highlighting
