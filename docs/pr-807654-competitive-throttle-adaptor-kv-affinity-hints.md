# Competitive Throttle Adaptor with KV-Affinity Hints for Continuous Batcher

Context and motivation: Continuous batching at high contention can lead to unfair admission that either starves low-affinity (cache-cold) requests or forces expensive kernel paths that degrade QoS. This PR implements a competitive throttle adaptor that factors a lightweight KV-affinity hint into admission and scheduling decisions. The goal is to reduce tail latency and prevent long-running KV-heavy bursts from monopolizing batch slots while preserving throughput for high-affinity steady traffic.

What this PR does (single continuous description): Adds a new adaptor (pkg/batcher/competitive_adaptor.go) that maintains per-cohort soft credits and an exponentially decaying affinity score per request sourced from the KV layer. Requests surface a SuggestedKVAffinity (0-1) in the admission envelope. The adaptor computes a competitive weight = base_priority * (1 + alpha * affinity_score) and uses a percentile-aware admission threshold so that high-affinity (cache-hot) requests get slight priority for small-latency slots while the soft-credit pool prevents long affinity-heavy sequences from starving other cohorts. The design favors small, low-cost kernels for high-affinity requests via a tight integration point in the kernel selector (pkg/runtime/kernel_selector.go) so that admitted requests have a preferred kernel hint, improving p50 and p90.

Engineering notes and important tweaks made: - Affinity scoring: implemented as a bounded EWMA in pkg/kv/affinity_scoring.go with a short half-life to reflect recent KV hits. The store (pkg/kv/affinity_store.go) uses sharded maps with read-copy-on-write to minimize admission path latency. - Admission policy: new admission_policy.go extracts request hints and maps them to dynamic thresholds; thresholds adapt to occupancy using a capped multiplicative increase / additive decrease loop to stabilize under bursts. - Soft credits: cohorts (route-level) accumulate soft credits; when credits exceed a cap, they enter a cooldown window. Credits decay exponentially to allow recovery. - Kernel selection hints: kernel_selector.go accepts a PreferredKernel hint emitted by the adaptor; tested heuristics that prefer int8 quantized kernels for affinity>0.8 when sequence length < 512. - Observability: metrics/registry.go adds per-cohort admitted_by_affinity counters, cooldown_events_total, affinity_score_distribution histogram and a new tracing tag admission.affinity. These are surfaced in the console dashboard (docs/rfc includes suggested panel layouts).

Performance summary (benchmarks & results): Microbenchmarks on a representative 32-GPU Dedicated pool with mixed workloads (60% short chat requests, 30% long KV lookups, 10% embeddings) show: - p50 generation latency: ~3% improvement - p90 generation latency: ~8% improvement - 99th percentile improved on mixed bursts by ~12% (measured on synthetic KV-heavy bursts) - Overall throughput preserved within 2% of baseline. The largest gains were when affinity signals were reasonably accurate; safeguards added for noisy signals (alpha ramp-down). Full benchmark scripts are under tests/e2e and examples/tuning.

Test plan: Unit tests for EWMA math and soft-credit boundaries; concurrency stress test for the affinity store; e2e test kv_affinity_burst_test simulates sustained KV-heavy bursts against a mixed consumer and asserts no cohort starvation and p99 tail improvement. CI also runs perf smoke tests in the perf-lab job.

Backward compatibility and safety: No customer-facing API changes. Feature gated by runtime flag enable_competitive_throttle=false by default in config; can be enabled per-route. The adaptor is reversible at runtime and metrics included to ensure safe rollouts (cooldown_events_total, admitted_by_affinity).

Operational notes and rollout plan: Start with small canary on Dedicated clusters for non-critical routes, monitor cooldown_events_total and p99 tail. Suggested alpha default 0.15, EWMA half-life 10s for HTTP workloads, and a global cap on admitted_by_affinity boost of 1.5x. The RFC contains recommended observability thresholds and rollback criteria.

Related work: builds on prior admissions and soft-credit ideas (see ENG-2145), but introduces KV-affinity as a first-class input to continuous batch admission. Also complements the prefetch warmup work in ENG-2189 by giving short lived prefetched requests a deterministic path to slots.
