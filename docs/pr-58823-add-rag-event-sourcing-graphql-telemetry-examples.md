# Add RAG event-sourcing examples with GraphQL connector and compact telemetry presets

Motivation: Teams building retrieval-augmented agents often need to integrate event streams (webhooks, change-feed) and GraphQL backends into tool-calling workflows. This PR adds a compact, opinionated example that demonstrates: an event-sourced RAG pattern (incremental index updates via webhooks), a lightweight GraphQL tool adapter for function-style tool calls, and a telemetry preset tuned for low-overhead dev tracing.
Summary of changes: added an examples/rag/event-sourced-graphql sample with runnable playground config, a GraphQL adapter (TS), webhook indexer stubs, a small smoke test suite, docs snippets for the devsite, and a telemetry preset JSON.
Checklist: - [x] Sample code and README - [x] Local playground config and Dockerfile for quick smoke runs - [x] Compact telemetry preset and docs snippet - [x] CI smoke workflow - [x] Internal design doc link in README (Linear ENG-9123)
What the sample demonstrates: - Event-sourced retrieval: documents are added/updated via an inbound webhook emulator and incrementally applied to a tiny in-memory index + optional persisted SQLite indexer. - GraphQL tool adapter: exposes a typesafe tool wrapper (graphqlTool) that performs queries/mutations against a GraphQL service and returns structured results usable by the agent. The adapter includes simple retry/backoff and schema-respecting output shaping. - Tool calling contract: minimal contract examples (input schema, expected output) and a contract linter config so authors can experiment with structured-tool workflows. - Telemetry: a compact telemetry preset (telemetry/presets/event-sourced-compact.json) that emits token-level cost and per-tool timing only at debug/dev level to avoid signal noise and billing delta in dev clusters.
How to run locally: 1) cd examples/rag/event-sourced-graphql 2) yarn install && yarn build 3) docker-compose up (the playground spins up a tiny GraphQL mock, webhook emulator, and the sample agent) 4) open http://localhost:3000/playground to run the example scenarios

Rationale and design notes: - We intentionally keep the example small (single-file adapter + short README) to lower maintenance and to act as a pattern for teams that need to stitch event-driven sources into RAG agents without adopting our full ingestion pipeline. - Telemetry preset demonstrates a conservative default for dev usage: it captures per-tool latency and token counts at debug level only, and redacts PII fields before emission. - The GraphQL adapter is intentionally minimal: it returns structured JSON matching tool contracts rather than a free-text answer, showing how to use the agent's structured output tooling.
