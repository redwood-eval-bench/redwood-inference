# geo-bound operator sealing and kms-consumption audit proofs

Adds region-bound operator sealing middleware, KMS consumption mirroring with evidence cache, and a compact audit proof envelope. No public API changes. Backward compatible rollout via feature flag.
Motivation: customers running Private deployments requested stronger guarantees that operator actions are tied to a geo-residency assertion and that KMS usage has a verifiable lightweight proof attached to audit logs. This PR implements a runtime middleware and support libraries that: (1) seal operator sessions with a geo-bound assertion (region-pin + operator fingerprint) that travels with requests; (2) mirror KMS consumption events into an ephemeral evidence cache that emits compact cryptographic proofs attached to audit entries; and (3) augment RBAC v2 decision logs with the sealed operator assertion so post-hoc policy reviews can correlate decisions to region-scoped operator claims. Checklist: - [x] Implement operator-seal middleware and header format - [x] Add KMS consumption mirror + evidence cache with TTL and signature envelope - [x] Extend audit writer to attach proof-envelopes and compacted metadata - [x] Add feature-flag gating and rollout configuration - [x] Unit + integration tests for middleware, cache eviction, and audit envelope generation - [x] Docs: design doc + console UI note for operators Design notes: operator seal is a short-lived signed assertion produced by the operator credential manager. It contains operator_id, asserted_region, session_nonce, and expires_at. The assertion is HMAC-signed by the operator credential signing key (rotated via KMS). The KMS consumption mirror listens for successful Encrypt/Decrypt/Sign calls and stores a trimmed consumption record (timestamp, key_id, operation, request_digest) into a local evidence cache. When an audit entry is flushed, the audit writer queries the evidence cache for recent records related to the request_digest and attaches an evidence-proof envelope: a concise JSON string that includes base64-encoded digest references plus a signature from the evidence cache key. The envelope is kept intentionally small (<= 2KB) to avoid high-cardinality audit bloat. Rollout plan: gated behind feature flag `geo_operator_seal_v1`. Start in Canary, route 5% of internal operator traffic, monitor: - audit envelope size distribution - evidence cache hit ratio - RBAC decision trace linking rate Documentation: design doc at docs/security/geo-operator-seal.md (added), and an operations runbook for key rotation. Backwards compatibility: middleware is opt-in and does not alter existing decision flow when flag is off. Security review: includes threat model section and mitigations for replay, operator impersonation, and key leakage. See linked_linear tickets for follow-up tasks.
Ravi Patel: Can you clarify the trust boundary for the evidence cache key? Who rotates it and how do we prevent it being used to forge envelopes?
Maya Chen: Evidence cache key is a service-scoped key stored in the operator service KMS envelope. Rotation is via standard key rotation job; we added checks so rotated keys are recorded in audit and old proofs remain verifiable via key-history metadata.
Liam O'Connor: Suggest adding a rate limit on mirror writes to avoid KMS event bursts during failover spikes.
Maya Chen: Added a leaky-bucket rate limiter with configurable burst; details in mirror.go and config helper. See commit b3d7e22.
Sofia Martinez: Audit envelope size looks fine in tests, but in a sample with large request digests it peaked at 3.1KB — can we enforce max size and fallback to digest-only reference?
Maya Chen: Implemented a truncation policy: if envelope > 2KB, we replace full evidence list with a 'proof_reference' which points to an archive job. Added tests and note in ops runbook.
