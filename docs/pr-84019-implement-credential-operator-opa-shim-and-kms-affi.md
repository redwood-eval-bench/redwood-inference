# Introduce credential-operator OPA policy shim and KMS-affinity gating with audit coordinator

Motivation: multi-tenant Private deployments require stronger operator credential controls and clear provenance for KMS usage. This PR adds a lightweight OPA-based policy shim consumed by the credential-operator to evaluate operator-scoped RBAC v2 assertions, and a KMS-affinity gating layer that ensures requests with tenant residency constraints prefer region-local keys. An audit coordinator service is introduced to canonicalize audit headers, attach KMS-origin assertions, and deduplicate noisy operator events before downstream storage. Key goals: (1) prevent accidental cross-region KMS usage when tenants are region-pinned, (2) provide a single policy surface for RBAC v2 expressiveness used by operator flows, and (3) ensure audit records include verifiable KMS provenance headers for compliance. Design summary: - credential-operator now queries a local OPA instance via HTTP rather than embedding policy logic. Policies are authored in Rego under policy/cred-operator/. This enables policy updates without restarting the operator. - KMS-affinity-gate consults the residency resolver and a per-tenant residency profile; if the request is not compliant, the gate attempts a controlled fallback to equivalent region-allowed keys (configurable), otherwise it returns a 403 with a clear remediation code. - audit-coordinator is a small service (Go) sitting in front of the audit sink in the Private control plane. It performs header normalization, attaches kms-origin-signature (generated from the key metadata service), and emits a compact audit fingerprint to allow efficient dedupe. Migration and rollout plan: shadow mode first. credential-operator will run with --policy-shim=shadow to evaluate decisions but not enforce. KMS-affinity-gate has a config flag residency.strict=false in initial deploy. audit-coordinator runs in passive dedupe mode (metrics only) for two weeks, then enabled to forward canonicalized events. We will run a 2-week canary in staging, then staged rollout by region. Backwards compatibility: if OPA shim is unreachable the operator falls back to built-in allowlists with an emergency fail-open config guarded by team ops. Audit coordinator is optional (feature-flagged) and only used by Private. Testing: unit tests for Rego policies (policy-tests/), e2e scenario harness that simulates operator credential requests across zones (eval-harness/cred-op-tests), and integration tests for audit-coordinator with a fake KMS metadata service. Security review: keys for signing KMS-origin headers are scoped to the audit-coordinator service and stored in the custodian KMS with automatic rotation.
