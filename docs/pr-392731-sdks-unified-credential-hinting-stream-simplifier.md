# tri-sdk: unify credential hinting, retry presets, and simplify streaming consumer ergonomics

Context: Several teams reported cognitive overhead when wiring credential refresh hints into streaming consumers and inconsistent retry presets across SDKs. This PR harmonizes a lightweight 'CredentialHint' surface across Python/TypeScript/Go, standardizes retry preset names and defaults, and eliminates an awkward streaming iterator pattern that caused frequent user codeworkaround. Motivation: reduce integration friction for customers moving between SDKs and improve production defaults for auth/retries. Changes in this PR: 1) Introduce CredentialHint (optional, minimal): transports can accept an opaque hint (e.g. {lease_window: "short"} or a token expiry timestamp) that SDKs forward to the runtime and credential mediators to prioritize refresh windows. Hints are optional and backward compatible. 2) Retry presets: rename and map presets (fast|balanced|stable) across all SDKs; unify default backoff floors and jitter bounds, and document recommended presets for streaming vs request/response. 3) Stream ergonomics: replace the previous callback-heavy streaming adapter in TS/Go with a thin async iterator/pullstream facade that mirrors the Python async iterator ergonomics; add a small 'with_stream' helper in Python for context-managed resource cleanup. 4) Telemetry hooks: attach a small 'retry_preset' tag to SDK-side telemetry to enable cross-SDK aggregation. 5) Version bumps: python -> 0.14.2, typescript -> 1.6.0, go -> v1.8.3 (patch bumps only). Backwards compatibility: credential hinting is additive; existing token rotation remains unchanged if no hint is supplied. Tests & CI: added unit + integration tests that run cross-language smoke scenarios in the internal micro-integration harness. CI initially failed due to flaky backoff unit test; adjusted timeline and increased jitter window to stabilize. All checks green on final run. Docs: added an SDK-agnostic credential-hinting doc and updated quickstarts with examples in all three languages. Rollout plan: merge to main and release coordinated patch versions for each SDK; monitor error/latency dashboards for the next 48 hours and revert the retry default if regressions observed.
