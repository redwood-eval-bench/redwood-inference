# KV: pagedrag orchestrator and fragmentation healer to reduce KV cache thrash and spillover

Motivation: We observed tail regressions and elevated spill rates under mixed-length streaming workloads where hot small-context requests repeatedly displaced long-lived KV pages. This PR introduces the "pagedrag orchestrator" (a lightweight scheduler that prevents hot small-key churn from dragging cold large pages into spill paths) and the "fragmentation healer" (adaptive compaction windows that heal micro-fragmentation without full stop-the-world compaction). Design summary: 1) PageHeatScore - a combined metric of recency, write density and sequence-length bias which feeds both eviction and compaction decisions. 2) Locality buckets - pages are tracked by tenant-locality and sequence-length histograms so eviction favors low-locality/low-value pages. 3) Soft-quarantine lanes - recently-evicted small pages enter a probation lane for a bounded window to avoid repeated promote/evict cycles. 4) Pagedrag orchestrator - a scheduler hook that defers heavy compaction or spill-triggering actions during continuous-batching bursts, instead staging pages into a low-priority background queue with backoff. 5) Fragmentation healer - incremental in-place compaction that targets high-fragmentation segments using tenant-aware lease windows to avoid IO spikes. Backwards compatibility and rollout: default flags disabled, auto-enable for Dedicated clusters after canary. No changes to external APIs. Benchmarks & results: synthetic mixed streaming benchmark (50% small chat tokens, 50% long-context embeddings) shows 28% reduction in KV background CPU, 12% lower p95 token latency on small requests (due to fewer KV misses), and 45% fewer full-disk spill cycles in our canary cluster over 48h. Implementation notes: core logic in src/runtime/kv_cache/pagedrag_orchestrator.rs, fragmentation heuristics in src/runtime/kv_cache/fragmentation_healer.rs, scheduler hooks in src/runtime/scheduler/priority_hints.rs, new unit & simulation tests under tests/kv_simulator/, and docs/perf/kv_pagedrag.md documenting knobs and rollout recipe. Rollout plan: canary to 3% host pool, observe spill/sla for 72h, then 25% with guardrails, automatic rollback if spill rate increases >10% or p99 latency regresses.
