# Introduce page-defrag timer, spill-fuse limiter, and eviction skyline probe

Motivation: We observed recurring tail-latency spikes and progressive KV cache fragmentation under mixed read/write workloads with long-lived cached prefixes. Existing eviction heuristics were too reactive to instantaneous occupancy signals and would thrash pages during short-lived write bursts, which amplified paging and spillover. This PR introduces three coordinated mechanisms: 1) a lightweight page-defrag timer that stages cold page candidates for low-priority in-place defragmentation during idle windows; 2) a spill-fuse limiter that gates concurrent spill operations to avoid I/O amplification during bursty reclaim; and 3) an eviction skyline probe that computes multi-horizon eviction scores (hotness over 1s/10s/60s) to prioritize items with sustained coldness. Summary of changes: - runtime/kv/defrag_timer.{cc,h}: new scheduler that marks candidate pages and attaches a low-priority work item to tenant cooperatives; supports max-defrag-ms and backoff-per-tenant. - runtime/kv/spill_fuse_limiter.{cc,h}: token-bucket style limiter with adaptive thresholds tied to async-io latency percentiles; includes metrics hooks. - runtime/kv/eviction_skyline.{cc,h}: computes composite eviction score using short/medium/long access histograms and residency age; compatible with existing LRU/BATTERY evictors. - runtime/kv/allocator_integration.{cc}: hooks that allow defrag timer to request migrations and the spill limiter to veto immediate async spill submissions. - tests/kv/bench_defrag_timer.sh: microbench bench harness for fragmentation-heavy workload. - docs/ops/kv-eviction-guides.md: operator-facing knobs and rollback steps. Performance: On staging runs with a 1k-concurrent clients mixed-readwrite workload (60/40 R/W, 6h run) we saw: - 42% reduction in 99.9th percentile latency for GETs under sustained traffic - 28% fewer background spill jobs during peak write bursts - 8-12% lower overall tokenized memory churn (measured as page rewrite bytes) Tradeoffs & rollout: The defrag timer performs best when tenants have modest idle windows; for extremely write-heavy tenants (sustained >90% writes) the system will fall back to current spill-first behavior. The spill-fuse limiter exposes two new operator knobs (max-concurrent-spills, spill-latency-threshold-ms) and includes a safe default that matches existing async-io concurrency on small instances.
