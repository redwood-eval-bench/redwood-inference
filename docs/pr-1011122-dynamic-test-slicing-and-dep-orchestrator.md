# dynamic-test-slicing-and-dependency-orchestrator-refactor

Motivation: feedback loops for CI were growing slow as test suites expanded and transitive dependency churn increased. This PR introduces a dynamic test-slicing runner that selects targeted integration and unit shards based on changed files, historical flakiness, and test runtime profiles, and pairs it with a dependency update orchestrator that stages dep bumps through a lightweight compatibility matrix. Goals: reduce CI average wall time, avoid wasting integration resources on unrelated changes, and provide safer incremental dependency rollouts. Changes: 1) new presubmit runner 'slice-runner' in infra/ci that computes affected test shards from git diff + historical telemetry; 2) a dep-orchestrator service (lightweight Go CLI + GitHub action) that applies batched dep upgrades to a staging branch, runs the minimal slice, and auto-reports compatibility results; 3) refactor of existing lint/test composite actions to expose a pluggable hook for slice-runner; 4) updated devcontainer and local-run scripts to mirror CI slice selection for contributors; 5) telemetry hooks to send per-shard runtimes and flakiness scores to the observability pipeline for future tuning. Checklist: - [x] design doc linked (ENG-5891) - [x] unit + integration tests for slice-runner - [x] actions integration smoke - [x] migration notes and developer docs - [x] rollout plan and feature flag gating Rollout plan: gate slice-runner behind feature flag CI_DYN_SLICE=false by default, enable for fast-feedback lanes first, monitor shard coverage and false-negatives for 2 weeks, then widen to presubmit lanes. The dep-orchestrator starts in 'dry-run' mode against a staging branch, then allowed to raise PRs when dry-run passes. Compatibility notes: the orchestrator includes a policy whitelist for critical deps; breaking upgrades will be automatically reverted and flagged to the oncall. Impact: expected median CI wall clock reduction ~28% for pull requests with small surface-area changes, peak resource savings on integration runners. Backward compatibility: existing runners will remain available; no required config changes for consumers unless they opt-in. Related work: references ENG-5891, ENG-5742 (test telemetry), SRE-120 (runner autoscaling).
