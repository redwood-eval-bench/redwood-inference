# chat.v1 param slimification + stream resiliency and tool-routing for OpenAI /v1 parity

Background: We continue to converge Redwood's chat API with the OpenAI /v1/chat.completions surface so customers can switch between backends with fewer surprises. This PR focuses on two pain points seen in recent toggles: 1) noisy/underdocumented parameter edge cases (stop arrays, role aliases, temperature/top_p interactions) that produced surprising token-level divergence, and 2) intermittent stream reassembly failures when tool/function calls are emitted alongside logprob fragments. Goals: canonicalize and slim the param mapping to a minimal, well-documented set that preserves intent; make stream framing robust to interleaved function-call envelopes and partial logprob deltas; and preserve tool metadata so that downstream toolchains (router/arbiter) can rely on stable fields. Changes: - Param slimification: introduce a canonicalizer that maps OpenAI-style params to Redwood runtime flags. Resolves ambiguities around stop arrays vs stop regex lists, merges role aliases (assistant/system/user) and rejects deprecated param combinations (e.g., presence_penalty + penalize_role simultaneously) with clear warnings. - Stop/logprob handling: normalize stop priority by length then explicit weighting; ensure logprob fragments emitted as part of framed JSON envelopes are re-anchored to the token index from the canonicalized request. We also add a fallback heuristic to emit a full token logprob snapshot when deltas are discontinuous. - Stream resiliency: make the framers idempotent for repeated fragments and add a lightweight heartbeat sentinel to prevent stalled consumer reads (configurable per-route). Partial frames that include fn_call/tool metadata are now buffered and merged deterministically. - Tool/function routing metadata: tool calls coming from model responses now include a stable routing key derived from tool_id + semantic_hash so platform routing can shard deterministically. The OpenAI-compat wrapper attaches this metadata in the outbound framed JSON without changing user-visible tool payloads. - Tests & docs: new integration tests that simulate interleaved toolcalls + logprob chunks, and docs example for the /v1/chat.completions compatibility matrix. Checklist: - [x] Add canonicalizer code and unit tests - [x] Stabilize stream framer and add heartbeat sentinel - [x] Preserve and attach routing metadata for tool calls - [x] Integration tests for interleaved fragments - [x] Update compat docs and changelog Rollout plan: merged to main behind a feature flag (compat.chatv1_stream_v2). We will enable route-by-route, monitor token-level regressions via Redwood Optimize evals, and roll forward full default only after 2 days of stable metrics on canary routes. Backcompat: default behavior unchanged until feature flag flip; warnings are emitted to logs for deprecated param combos. CI: initial run failed due to flaky integ test (stream reassembly) — fixed by adding a 10ms jitter coalescer on the test harness and re-ran. CI now green. Why this matters: customers switching between Redwood hosted models and OpenAI-compatible endpoints reported subtle differences in stop-handling and occasional truncated tool JSON blobs during streaming. This PR reduces those divergences and makes the stream protocol more fault-tolerant without exposing new surface area.
