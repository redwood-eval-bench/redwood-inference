# Prompt anchoring consensus fanout CI adapter with latency-aware soft-throttle

Context: We observed intermittent prompt-set regressions that only show up when a small fraction of traffic triggers a different prompt variant; existing cohort gates are too coarse and either over-block or miss subtle regressions. This PR introduces a CI adapter (Prompt Anchoring Consensus Fanout) that fans out a small, configurable fraction of CI-eval traffic to multiple anchoring strategies, aggregates a consensus signal across them, and applies a latency-aware soft-throttle when disagreement or latency drift exceed thresholds. Motivation: reduce noisy false-positives while catching low-signal regressions early, and avoid large-scale CI failures driven by transient latency spikes. Design summary: 1) Fanout layer: routes evaluation jobs to 3 anchoring strategies (lexical anchor, semantic shingle anchor, and recent-traffic replay) in parallel. 2) Consensus aggregator: computes a consensus score (weighted majority with tie-breaker using confidence) and emits a composite regression score. 3) Latency-aware soft-throttle: if regression score crosses the soft-fail threshold but median latency for the eval backends exceeds a configured SLO, the adapter returns a soft-throttle (CI warning) instead of a hard failure. 4) Canary and rollouts: adapter supports a phased rollout via config flags: enabled=false by default, canary=true to enable for 3% of CI runs, then ramp. Checklist: [x] design doc linked (Linear ENG-4721) [x] unit tests for aggregator logic [x] e2e smoke tests in local harness [x] CI integration tests (mocked backends) [x] metrics + tracing added [x] console toggles & feature flag gating [x] rollout plan in PR description Compatibility: adapter integrates with existing eval orchestration via a light extension point (EvalRunner::post_process_hooks). Backwards compatibility preserved when the adapter is disabled. Testing notes: - deterministic-unit tests for consensus weighting (seeded RNG) - synthetic noise experiments show false-positive rate drop ~45% compared to single-anchor gating on our sampled prompt-sets - latency soft-throttle prevented 3/4 of recent spurious hard blocks during 72h replay. Rollout plan: enable canary in CI for internal main branch builds (3% traffic) for 48h, monitor composite regression metric and alert on >2x false positive or >1.2x missed regression rate; escalate to roll back flag if needed. Related: Linear ENG-4721 (design), ENG-4890 (canary dashboard).
Devin Shaw: Nice approach. Two questions: 1) how do we pick the weights for each anchor? 2) can the soft-throttle leak a false 'pass' under heavy load?
Anika Patel (author): We pick initial weights from historical anchor fidelity (stored in eval metadata) and expose a config param for linear decay during canary. Soft-throttle design uses median latency and only downgrades hard failures to warnings; it will not convert a clear regression into a pass — it downgrades immediate CI blocking to a soft block and creates a follow-up probe job for longer-running verification.
