# scheduled attention fusion: slot-based coalescer for fused rope/rotary kernel and lazy-KV warming

Motivation: reduce p95 and unit-cost for mid-size generation workloads (seq_len 512-2048) by minimizing kernel launches, eliminating extra rotary + rope passes, and making continuous batching aware of KV warmup patterns. This PR implements a slot-based scheduling/coalescer and a new fused-attention kernel that merges rotary/rope multiply-add into a single pass while supporting quantized kernels. Key changes: 1) Kernel: add attn_coalescer.cu, a fused rotary+rope+QKV reduction microkernel that emits single-pass attention outputs and supports fp16/int8 fast paths; it includes alignment-friendly tiling and warp-shuffle reductions to avoid global synchronizations. 2) Scheduler: introduce a slot-based continuous-batcher (runtime/scheduler/slot_scheduler.cpp) that groups in-flight requests by sequence-shape buckets, enforces coalescing windows, and exposes a tunable prefetch-watermark to warm KV cache proactively. 3) KV cache: lazy-KV-aggregation and probabilistic warmup — warmup heuristics use recent prefix-hit ratios to prefetch KV into reserved slots and perform coalesced writes to avoid per-request eviction storms. 4) Compatibility & fallback: add a runtime capability check and fallback to prior rotary/separate-kernel path when model config or device lacks required features. 5) Tests & benchmarks: microbench harness for synthetic and realistic chat workloads (bench/slot_bench.py), end-to-end CI tests and a small perf report included. Performance summary (internal microbench, p95 across 1000 samples): - baseline (main): p95 = 112 ms, throughput = 175 tokens/s - this PR: p95 = 78 ms (-30%), throughput = 243 tokens/s (+39%) - unit cost estimate: ~22% reduction for mixed-length workloads. Design notes and trade-offs: the fused kernel slightly increases shared memory usage and registers; to avoid regression on small-batch low-latency requests we expose a runtime flag to disable coalescing for single-request fastpath. The slot scheduler introduces a modest scheduling jitter (median +2ms) but overall decreases tail latency under realistic bursty arrival patterns. Rollout plan: staged canary (5% traffic) with canary rollout metric checks (p95, error-rate, GPU utilization); automatic rollback if p95 regresses >5% or GPU OOMs observed. Related: ENG-1984 (slot scheduler prototype), ENG-2087 (kv warmup experiments).

Compatibility: automatic fallback to legacy kernel for models that opt-out or on unsupported devices.
