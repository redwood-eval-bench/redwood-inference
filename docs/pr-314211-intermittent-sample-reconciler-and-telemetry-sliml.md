# introduce-intermittent-sample-reconciler-and-telemetry-slimline

Added intermittent sample reconciler service and compact telemetry pipeline; new dashboard panels and tuned alerts to reduce noise from sparse sampling.
Motivation: we observed noisy alert churn and missing token-attribution in low-traffic tenants due to aggressive sampling and periodic exporter gaps. This PR adds an intermittent-sample reconciler service and a 'telemetry slimline' ingest path to stitch intermittent metric/tracing samples, reconstruct missing token-level attributions, and emit compact rollups for low-cardinality routes. Goals: reduce alert noise from sparse samples, provide better cost/latency attribution for long-tail invocations, and keep overhead sub-2% CPU for the observability pipeline. Summary of changes: 1) telemetry/reconciler: new service that consumes sampled traces and metric windows, applies a sliding reconciliation window to infer missing token-attribution events, and outputs compacted span anchors and delta-cost rollups. The reconciliation algorithm uses a best-effort prefix-matching heuristic with confidence weights and retains provenance tags for auditability. 2) telemetry/sidecar: lightweight sidecar that tags sampled logs with reconciler-correlation IDs and emits heartbeat markers so the reconciler can detect exporter gaps. 3) observability/dashboards: new Telemetry Reconciler dashboard with panels for "stitch rate", "reconciler confidence distribution", compacted token-cost per-route, and reconciler induced-suppressed-alerts. 4) alerts: introduced a noise-aware alert adapter that uses reconciler confidence and sample density to suppress low-confidence anomalies for the first N windows, reducing pager fatigue. 5) tests/docs: unit and integration tests for the reconciliation logic, loadbench results in docs showing <2% CPU overhead at production sampling rates. Backwards compatibility: reconciler emits both legacy and compact rollups; downstream consumers default to legacy until opt-in. Rollout plan: start with internal telemetry namespace for 48 hours, gated ramp to prod 20% tenants -> 50% -> 100% with feature flag. Why unique: this approach stitches sparse telemetry across exporter gaps rather than only downsampling or increasing sampling rate, preserving signal for long-tail token-level cost attribution without increasing sampling cost. Link to issue: SUP-7123.
