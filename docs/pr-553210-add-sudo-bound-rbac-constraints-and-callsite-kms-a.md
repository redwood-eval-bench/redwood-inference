# Add sudo-bound RBAC constraints and callsite KMS audit tracing

Motivation: Certain operator-style actions require temporary elevated privileges in a least-privilege manner while still providing deterministic audit evidence for compliance. This PR introduces two related features: 1) a new 'sudo-bound' constraint in RBACv2 that ties short-lived elevation to an operator lease and policy-bound scope; 2) per-callsite KMS audit tracing which attaches immutable callsite identifiers to KMS operations so audits can reconstruct the exact code path that requested a key operation. Changes are backwards compatible: existing RBAC policies continue to work; the sudo-bound constraint is opt-in and gated by feature flag. Key components: policy compiler changes to understand sudo-bound constraints, operator-lease integration, KMS trace propagation middleware, and a small additions to the console audit viewer to render callsite traces. Checklist: - [x] Implement RBAC policy syntax and compiler hook - [x] Integrate operator lease service for timebound elevation - [x] Add callsite-KMS propagation headers and signing - [x] Wire to audit log writer with tamper-evident envelope - [x] Add unit and integration tests for policy evaluation and KMS propagation - [x] Add console table and CSV export for callsite traces - [x] Documentation and migration notes (docs PR forthcoming) Security considerations: sudo-bound constraints require operator lease approval; elevation tokens are single-use and short TTL (default 60s). KMS callsite traces are signed with service-level attestation keys and do not contain customer plaintext key material. Related work: Linear ENG-11483 (RBAC sudo design), ENG-11802 (KMS tracing spec), Jira SUP-4521 (customer compliance inquiry).
Introduces 'sudo-bound' constraints in RBACv2 and per-callsite KMS audit tracing. Rolling upgrade compatible; no immediate customer action required. Admins can opt-in to tighten operator privileges and enable richer KMS callsite logs for compliance audits.
Evan Park: Can we clarify how replay protections work for callsite traces? If an attacker copies headers, do we have a mitigation?
Priya Nair (author): Trace headers are signed with per-service attestor keys and include a monotonically increasing nonce + lease id. The audit writer verifies signature + nonce uniqueness (dedupe cache) before accepting. Also TTL on callsite traces equals operator lease TTL; documented in security section.
