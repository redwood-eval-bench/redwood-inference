# Add Terraform plan guard and Helm airgap shim with migration simulator

Motivation: Private/on-prem customers running air-gapped or tightly controlled environments need deterministic upgrade outcomes. Two common failure modes we've seen in incidents are (1) unintended Terraform resource churn during apply and (2) missing chart artifacts or image references in airgapped clusters. This PR introduces three coordinated pieces: a Terraform plan guard (installer/terraform/modules/plan_guard) that enforces an allowlist and diff threshold before apply; a Helm airgap shim (installer/helm/airgap-shim) that stages and validates all chart assets and image digests ahead of rolling upgrades; and a migration simulator tool (installer/tools/migration_simulator) that can run DB/KV schema migrations in dry-run mode against a snapshot to detect incompatible changes before an in-place upgrade. Summary of changes: - installer/terraform/modules/plan_guard: new module that wraps terraform plan/apply with a preflight validator (configurable thresholds, allow/deny rules, and auto-approve gating). - installer/helm/airgap-shim: small utility and chart hooks to bundle required tarballs and image digests, validate registry replacement maps, and produce a signed asset manifest for offline clusters. - installer/tools/migration_simulator: Go binary that can replay migration SQL/transform logic against a detached DB snapshot and emit a regression report with row-level checks and schema diffs. - installer/docs/upgrade-playbook.md: updated step-by-step including how to run the plan guard, use the airgap shim, run the migration simulator, and perform the orchestrated rollback if needed. - ci: added tests for plan_guard logic and a unit test harness for migration simulator using SQLite snapshots. Backwards compatibility: Plan guard is opt-in via a top-level flag in the Terraform root (guard_enabled = false by default) so existing automation is unaffected. The Helm shim is additive; it exposes an alternate release flow for airgapped installs. Migration simulator does not change runtime migration code; it is strictly a preflight tool. Testing and verification: - Local integration tested against a reproducible example cluster and a synthetic DB snapshot (see installer/examples/airgap-smoke). - Terraform plan guard tested with scenarios: benign diff, resource rename, and unexpected deletion; guard thresholds behaved as expected, blocking destroy-heavy plans. - Helm shim validated on an offline KIND cluster (chart assets served from local registry) and through OCI tarball manifests. - CI: unit tests and a small integration job passed on re-run; one flaky test in early runs (migration_simulator/sql_parser_test) was stabilized by simplifying the parser and adding a fixture. Rollback/runbook: The playbook documents a staged rollback orchestrator that leverages the plan guard's dry-run mode to detect residual drift and the airgap shim's manifest to re-seed missing artifacts. Steps include: 1) mark tenant for maintenance (installer/scripts/quarantine.sh), 2) snapshot current DB and object storage, 3) run migration simulator to verify revert path, 4) apply rollback release using Helm shim with signed manifest, 5) validate with smoke prompts and metrics. Security notes: Signed manifests use the existing KMS/HSM integration; the migration simulator never ships snapshots off-cluster unless explicitly exported by an operator. Known limitations: - Simulator currently supports primary Postgres schemas and a subset of KV transforms; complex stored procedures are not simulated. - Plan guard thresholds require tuning per customer workload. See upgrade-playbook for mitigation. Links: Linear ENG-2124 for the feature epic; a follow-up is tracked under INF-403 to add Postgres stored procedure simulation.
Add an optional pre-upgrade Terraform plan guard that blocks apply when drift or unexpected resource churn is detected; introduce a Helm 'airgap shim' that stages chart artifacts for disconnected clusters; include a local migration simulator that runs schema migrations in dry-run mode against an exported DB snapshot; provide an updated upgrade playbook documenting safe dice-roll rollback steps and verification commands.
