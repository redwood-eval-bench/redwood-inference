# Control-plane slowpath quarantine and windowed SLO decoupler (hotfix)

Summary: Emergency hotfix that isolates a slow control-plane slowpath from dataplane routing decisions and introduces a windowed SLO decoupler to avoid global failover oscillation. This addresses production incidents where transient control-plane latency caused aggressive regional failover, tenant evictions, and repeated circuit flips. Motivation/Context: During a spike on 2025-07-12 we observed the control-plane healthcheck path occasionally taking 600-1200ms for a small subset of nodes. The serving plane treated those as degraded and triggered tenant-level evictions and cross-region reroutes. That cascade produced noisy failovers across customers. We need a short-term, low-risk mitigation that prevents control-plane slowpath flaps from causing global SLO enforcement actions until a follow-up runtime kernel fix lands. Implementation details: - Introduce a control-plane slowpath quarantine gate: when the control-plane probe latency exceeds the slowpath threshold, affected nodes are marked QUARANTINED for control-plane-derived signals only (not dataplane routing). Quarantined nodes keep serving traffic but are excluded from policy decisions that would trigger tenant eviction or aggressive regional failover. - Add a windowed SLO decoupler: we evaluate SLO violations over a sliding 90s window with tenant-weighted hysteresis. Short spikes (under 30s) are absorbed and do not trigger eviction. Repeated spikes that persist beyond the window escalate to the normal SLO enforcement path. - Provide an explicit emergency toggle (feature flag) per-region to enable/disable quarantine mode for rollback. - Conservative defaults: quarantine threshold = 300ms median control-plane probe, quarantine TTL = 2m, SLO-window = 90s, short-spike cap = 30s. Testing & QA: - Unit tests for quarantine state machine and decoupler hysteresis added. - Integration test simulating control-plane latency spike and verifying no tenant eviction, and that metrics reflect quarantined state. - Canary rollout in us-west-2 with 5% traffic for 2h prior to global rollout. Observability: - New metrics: controlplane_quarantined_nodes{region}, slo_decoupler_state{tenant,region}, slo_window_violation_count. - Traces add a new span for "quarantine-eval" for easier debugging. Rollout plan: 1) Deploy gate behind feature-flag; enable in canary region (us-west-2) at 5% traffic. 2) Monitor slo_decoupler_state and eviction_rate for 2h. 3) Ramp to all regions if canary stable. Rollback: Flip per-region feature-flag to OFF. The implementation is non-destructive and does not change persisted state; rollback is immediate. Related/Follow-up: - Follow-up ENG ticket to harden control-plane probe latency (ENG-1440). - Remove quarantine gate after control-plane kernel fix and adjust SLO-window default after postmortem.
