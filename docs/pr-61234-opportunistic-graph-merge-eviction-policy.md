# Opportunistic CUDA graph merge and eviction policy to reduce capture churn

Motivation: repeated CUDA graph captures for near-identical micro-batches were driving warmup churn and increased tail latency in multi-tenant workloads; KV-cache misalignment after eviction caused frequent replay rollbacks. This PR introduces an opportunistic graph-merge mechanism plus an eviction policy tied to the batch scheduler to reduce capture frequency and align KV state during replay. Summary of changes: 1) graph-merger: groups compatible captured graphs when their kernel maps and tensor layouts differ only in trailing pad/seqlen metadata; the merger maintains a remapping table used at replay to adjust kernel args without recapture; 2) scheduler-eviction: an LRU-like eviction that is aware of ongoing batching windows so we avoid evicting graphs likely to be re-used within the next N batching ticks; 3) kv-alignment: lightweight pre-replay probe that rehydrates or trims KV cache entries to the expected layout for merged graphs instead of forcing full rollback; 4) metrics and guards: added metrics for capture_rate, merge_rate, eviction_score and a probe_failure counter; 5) tests and benchmarks: unit tests for merging correctness and an end-to-end microbenchmark harness. How it works (high level): at capture time compatible graphs are considered for merge if kernel signature equivalence and trailing-dim variance are within configured thresholds; merged graphs store a small remap descriptor and a canonical kernel selection; at replay time the scheduler prefers merged graphs and runs a KV-alignment probe: if probe succeeds we proceed with replay using remapped args; on probe failure we fall back to capture or to a recorded compatible variant. Safety: remap descriptors include a checksum and compatibility version so older captures are not erroneously reused. Bench results: internal microbench on p4d-like nodes shows 12-18% reduction in capture count and 7-11% lower p99 token latency under mixed sequence workloads; cost model simulation predicts up to 14% lower per-token GPU time for chat-style workloads. Backwards compatibility: changes are opt-in via runtime flag cudagraph.opportunistic_merge and default to off for private installs older than the feature flag rollout; we added a runtime guard to disable merging for pinned model variants.
