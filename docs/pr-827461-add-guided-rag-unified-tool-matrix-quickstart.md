# Add guided RAG unified-tool-matrix quickstart

Motivation | This quickstart was created to give engineers a compact, opinionated example for building a RAG pipeline that calls multiple external tools (search, calendar, sheets) and uses a split-index retrieval strategy (short-term dense index + long-term sparse index) with adaptive routing and telemetry hooks. The motivating use-case was a customer ask to show how to: 1) route retrieval queries between a high-recall sparse index and a low-latency dense index, 2) surface tool-call traces for debugging, and 3) keep example infrastructure minimal for local runs. What this PR adds | A brand-new quickstart directory quickstarts/unified-tool-matrix with: README.md (guided walkthrough), example app (Node + Python microservices) illustrating tool-binding adapters, a compact dev docker-compose for local index + runtime, telemetry presets (otel config + example dashboards), and a docs site entry that explains the pattern and trade-offs. Key design choices | - Unified tool matrix: a simple manifest-driven way to register tool adapters and map them to intent categories. - Split-index retrieval: example code shows how to query both an FAISS-like dense vector store for recent context and a SQLite-backed sparse inverted index for older archival docs, and how to merge/rank results. - Adaptive routing policy: a lightweight policy that favors dense index for low-latency user-facing queries and falls back to sparse for broad recall. - Telemetry probes: token-level sampling, tool-call spans, and a small set of example alerts for retrieval regressions. Checklist | - [x] Quickstart tutorial and README - [x] Example app (Node worker + Python retriever) - [x] Dev docker-compose and Makefile commands - [x] Docs site page and sidebar entry - [x] Unit tests for the retrieval merge and tool adapters - [x] Telemetry presets and sample dashboards Local test instructions | 1) cd quickstarts/unified-tool-matrix 2) make dev-up (starts local vector index, fake external tool stubs, and example runtime) 3) curl -X POST localhost:8080/ask -d '{"query":"summarize recent product notes and add action items to my calendar"}' 4) Open http://localhost:9411/trace to inspect spans and tool calls Notes on productionization | This quickstart intentionally keeps components small; for production we recommend pinning model versions, replacing the in-memory vector store with a managed store, and using Dedicated or Private deployment for the retriever worker. The README includes a migration checklist. Impact and testing | Added unit tests and an integration smoke CI job that runs the dev-compose and runs two sample workflows. Perf impact is zero on the main runtime; all new code is behind a quickstart-only directory and not shipped in the core runtime. Rollout and docs | Docs entry added under docs/quickstarts/unified-tool-matrix.md, and the site sidebar updated to include the new quickstart.
