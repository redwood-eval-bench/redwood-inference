# Add repository-maintained release manager checklist (runtime + LTS patches)

Context: As part of the Runtime LTS initiative, we’ve had a lot of “tribal knowledge” in Slack threads and Confluence pages around what a release manager must verify before publishing a patch (CI gates, perf gates, artifact signing/provenance, SRE readiness, comms). This PR adds a repo-maintained checklist that release managers can use as the canonical “last-mile” preflight during patch week. Motivation: (1) reduce variance between release managers (2) avoid missing required sign-offs (SRE/Security/Runtime) (3) make it easy to link from PR templates, Linear, and incident retros. Scope: Adds a Markdown checklist under .github/ + wires it into the release PR template and docs index. Non-goals: Replace the full runbook in Confluence; the checklist is intentionally short and link-heavy. Notes: Checklist includes separate paths for (a) scheduled monthly LTS patches and (b) out-of-band security hotfixes. It also includes explicit “stop-ship” criteria and an escalation section (who to page). References: Confluence runbook "Cutting a runtime LTS patch release"; perf gates policy; reproducible builds + artifact signing; LTS SLO/escalation expectations; LTS release notes taxonomy.
