# Compact buildhook orchestration and dependency graph pruning to reduce CI time

Motivation: Our CI latency spikes are dominated by redundant build hook invocations and traversing a bloated dependency graph on monorepo changes. This PR introduces a compact buildhook orchestration layer and a lightweight dependency-graph pruning pass that skips irrelevant projects for a given change set. Goals: reduce median CI runtime for incremental builds by 30%, eliminate redundant environment setup in matrix jobs, and simplify release hooks to be deterministic. Changes: 1) buildhook router: replaces per-job shell wrapper with a single Rust-based orchestrator that caches environment done flags and serializes / parallelizes steps based on explicit dependencies; 2) dep-graph pruning: adds a fast file-change-to-target resolver using path globs and cached package metadata to avoid full graph walks; 3) release hooks: migrate from ad-hoc pre-release scripts to a release-hook registry with opt-in labels for heavyweight tasks; 4) preserve compatibility: fallbacks to legacy behavior via REDWOOD_CI_LEGACY env var. Rollout plan: deploy to quickci canary (nightly-quick) and monitor shard latency and cache hit metrics for two weeks before broad rollout.
