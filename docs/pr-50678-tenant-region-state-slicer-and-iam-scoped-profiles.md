# Introduce tenant-region state-slicer and IAM-scoped profile TF modules

Motivation: Private installs currently store a monolithic tfstate per VPC which prevents fine-grained tenant-region lifecycle operations, complicates GPU nodepool leases and IAM role scoping, and makes safe rollbacks cumbersome. This PR introduces a set of composable Terraform modules and a coordinated migration path to slice tfstate by tenant+region, add IAM-scoped profile modules, and provide explicit lifecycle/lease primitives for GPU node pools. Key changes: 1) New module tfmodules/tenant_state_slicer - encapsulates state partitioning and remote state backend wiring for tenant+region shards; supports optional state stitching for cross-tenant shared resources. 2) New module tfmodules/iam_profile_scoped - generates tenant-scoped IAM roles, service accounts, and minimal cross-account policies using a templated role factory (supports KMS/HSM bindings via variables). 3) New module tfmodules/gpu_lease_profile - declares lease resources, ephemeral pool annotation schema, and lifecycle hooks for graceful eviction and drain; integrates with private-installer's allocator via documented outputs. 4) Migration tooling under tools/tfstate_splitter.py and tools/plan-apply-orchestrator.sh - allow dry-run splits, state copies with validation (checksums + drift detection), and automated rollback hooks that create a tfstate-anchor file to allow atomic revert if downstream apply fails. 5) Backwards compatibility: existing monolithic stacks continue to work; the new modules are opt-in via workspace var enable_state_slicing=false by default. 6) Tests and CI: added e2e plan-only runs in staging CI for three sample tenant-region shards, unit tests for IAM role templates, and a chaos test verifying lease eviction path. Migration and rollout plan: - Phase 1: opt-in in a single non-prod tenant-region, run tfstate_splitter dry-run and manual validation. - Phase 2: automated split + apply with monitoring and canary traffic routing; rollback uses tfstate-anchor and the orchestrator script. - Phase 3: gradual rollout to other regions and tenants. Operational notes included in README with step-by-step commands, required IAM permissions for the migrator, and SRE runbook for emergency revert. This PR is intended to reduce blast radius of state changes, enable tenant-scoped IAM least-privilege, and improve the safety of GPU pool lifecycle operations.
