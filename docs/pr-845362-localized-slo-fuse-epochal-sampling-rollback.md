# Localized SLO Fuse: epochal sampling + rollback for noisy regional degradations

Context: in recent incidents we observed short-lived, noisy latency/500 spikes in individual availability zones and tenants that did not warrant full regional failover but repeatedly tripped global SLO circuits and caused large routing shifts. Motivation: provide a lightweight, localized circuit ("SLO fuse") that runs short epochal sampling windows, isolates noisy tenants/instances, and supports safe automatic rollback if the fuse caused undue capacity contraction. This PR introduces: 1) a SLO fuse controller that evaluates latency and error percentiles in fixed epochs (default 30s) with a bounded sample cap; 2) two-tier isolation actions: soft venting (token shedding, 5-20% progressive) and micro-quarantine (ephemeral request rejection for noisy tenants for up to 90s); 3) an epochal rollback detector that watches downstream capacity metrics and restores traffic progressively if recovery stalls or the action regresses SLOs; 4) runtime knobs and feature flags to scope to region/tenant/class-of-service; 5) telemetry: new metrics (slo_fuse_epoch, slo_fuse_action, slo_fuse_rollbacks, slo_fuse_sample_count) and a dashboard; 6) small API to annotate requests with fuse_reason for traceability. Design notes: - Fuse windows are deliberately short (30s-2m) and sampled (max N per epoch) to avoid over-reacting to bursty workloads. - Actions are conservative: we start with a soft vent (small percentage shed) and only escalate if subsequent epochs confirm degradation. - Rollback logic aims to detect overshoot: if node utilization or regional throughput drops >12% within 2 epochs after action AND percentile latencies worsen for unaffected tenants, we begin staged rollback. - All actions are bounded by tenant-level limits and opt-out via tenant config. Implementation summary (single-string body as required): added slo_fuse controller (pkg/slo/fuse_controller.go), a small policy DSL for action thresholds (internal/config/slo_fuse.yaml), telemetry hooks (pkg/telemetry/fuse_metrics.go), and e2e + unit tests (pkg/slo/fuse_controller_test.go, test/e2e/slo_fuse_scenarios/*). Runtime toggles: FEATURE_SLO_FUSE=on|off, SLO_FUSE_SCOPE=region|tenant|global, SLO_FUSE_EPOCH_MS=30000. Example policy excerpt: "thresholds: {p95_ms: 300, p99_ms: 900, error_rate: 0.025}; actions: [ {name: soft_vent, shed_pct: 0.05}, {name: micro_quarantine, duration_s: 90} ]". Backwards compatibility: defaults off. Rollout plan: staged rollout to canary region, 48h soak, incremental global enable for regional SREs. Related tickets: ENG-4128 (incidence analysis), ENG-4150 (operational runbook).
