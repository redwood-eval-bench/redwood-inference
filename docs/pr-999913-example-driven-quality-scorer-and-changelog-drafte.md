# Introduce example-driven quality scorer and autogen changelog drafter

Motivation: onboarding new model variants currently relies on manual sample selection and ad-hoc changelog prose. That leads to inconsistent quality signals and brittle release notes. This PR adds two pieces: 1) a lightweight example-driven quality scorer that ranks onboarding examples by semantic drift and outcome stability, and 2) an autogen changelog drafter that synthesizes concise release notes from the scorer output and curated prompt-set diffs. Goals: reduce time-to-publish for model intake, make changelogs actionable for downstream infra and SRE teams, and provide a reproducible artifact attached to each model version. Implementation summary: - example-driven scorer: Rust microservice + Python bindings that takes a delta of example sets and telemetry samples, computes embedding-based drift, per-slice failure rate deltas, and a tunable composite score (0-100). The scorer emits a compact CSV and a JSON lines summary used by the drafter. - changelog drafter: a Go utility that consumes scorer output, the model manifest, and an optional human note. It produces a short changelog blurb, a "what changed" bullet list, and suggested impact tags (e.g., latency-risk, semantics-regression). The drafter uses template-based heuristics plus a small set of deterministic rules to avoid hallucinated prose. Backwards compatibility: both components default to off for existing pipelines; the onboarding CLI gains a --autogen-changelog flag. Checklist: - [x] lightweight scorer prototype and service definition - [x] CLI wiring and integration tests - [x] deterministic drafter templates + unit tests - [x] end-to-end smoke with synthetic onboarding - [x] metrics emitters and docs for new manifest fields Links: design doc https://linear.app/redwood/notes/ENG-8472-example-scorer, example datasets folder: docs/onboard-examples/README.md, demo video in PR comment. Migration notes: operators can enable the scorer via the manifest key "example_scorer: enabled: true"; disabling reverts to previous behavior. Rollout: feature gated and staged for 2 weeks in canary before full default enablement.
