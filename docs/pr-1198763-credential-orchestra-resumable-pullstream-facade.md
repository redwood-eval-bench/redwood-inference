# credential-orchestra-and-resumable-pullstream-facade-across-py-ts-go

Motivation: Customers reported inconsistent reauth behavior and awkward stream resume APIs across SDKs leading to duplicated error-handling in app code. This PR introduces a lightweight cross-language 'credential-orchestra' component plus a resumable pullstream facade implemented in Python, TypeScript, and Go to provide a single mental model for credential fallback, prefetch, and graceful reauth while preserving per-SDK ergonomics. Goals: provide a compact orchestrator API surface that can run in-process or as a thin adapter; expose typed resume tokens for deterministic stream resume; add an adaptive reauth scheduler that prefers fast-path token exchange but falls back to queued refresh; ensure backward compatibility with older token providers via a compatibility shim; bump SDK versions to reflect the ergonomic surface changes. Changes: - Add credential-orchestra core (small state machine): discovery -> prefetch -> attach -> refresh -> fanout; - Implement adaptive-reauth scheduler with tunable backoff and preferred prefetch window; - Introduce resumable PullStream facade in py/ts/go that yields typed events and accepts resume tokens; - Provide compatibility shim for legacy credential providers and an opt-in migration helper for customers; - Add unit and integration tests that exercise cross-language resume semantics and corner cases (expired mid-chunk, refresh race, provider failure); - Update SDK docs and quickstart snippets; - Version bumps: py 2.11.0, ts 1.9.0, go 1.5.3; - Small perf optimization: avoid duplicated KV cache invalidation when orchestration is used; Migration notes: default behavior is backward compatible; to opt into orchestra you set ClientOptions.credentialMode="orchestra". Rolling out: staged feature gate behind env var REDWOOD_ORCHESTRA_ENABLE to allow gradual platform rollout and monitoring.
