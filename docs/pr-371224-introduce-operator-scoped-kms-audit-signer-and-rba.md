# Introduce operator-scoped KMS audit signer and RBACv2 policy mapper

Summary: Adds an operator-scoped KMS audit signer service and an RBACv2 policy mapper to ensure audit envelopes are signed with tenant-aware KMS leases while translating legacy operator roles into RBACv2 constraints. Motivation: We need stronger non-repudiation for audit events emitted by control-plane operators that act across tenant boundaries. Current audit logs can be indistinguishable when operators perform cross-tenant maintenance — this PR attaches KMS-backed origin proofs and maps operator identities to RBACv2 temporal/amphibious constraints to limit blast radius. Design: 1) kms-audit-signer: a lightweight service that requests ephemeral, operator-scoped KMS leases, signs an audit envelope (protobuf) with the lease-derived key handle, and attaches a signed provenance header (X-Redwood-Audit-Signature, X-Redwood-Audit-KMS-Ref). The signer validates that the operator principal is allowed to request the lease via a policy evaluator before signing. 2) rbacv2-policy-mapper: translation shim that reads existing operator roles and emits RBACv2 assertions (timebound, region-anchored, tenant-scoped) used by the policy enforcer. The mapper supports a simulation mode that logs proposed assertions for 7 days before enforcement. 3) Compatibility: signer falls back to current unsigned envelope when running in legacy mode controlled by feature-flag "operator_kms_audit_signing". Migration: Run mapper in simulation mode for 7 days, monitor policy_simulator metrics and audit_signed:percentage; then flip to enforce per-operator cohorts. Checklist: - [x] Implement KMS lease request flow and short-lived key handles - [x] Audit envelope signing and verification logic - [x] Policy evaluator integration for lease grants - [x] RBACv2 mapper with simulation mode and logging - [x] Unit + integration tests for signer and mapper - [x] End-to-end test against private-installer local cluster - [x] Feature-flag gating and canary rollout plan Testing: Unit tests added for lease lifecycle and envelope verification. Integration tests exercise signer against a fake-kms implementation and validate provenance header format. A small end-to-end smoke test was run in the staging dedicated cluster using 3 operator avatars. CI: One flaky test (pkg/serving/scheduler_test) failed on first run due to timing; rerun succeeded. Rollout plan: 1) Enable feature-flag in staging with mapper in simulation mode. 2) Canary: enable signer and enforce mode for 5% of operator traffic (dedicated canary cluster) and validate signed audit acceptance and policy gate metrics for 48 hours. 3) Ramp to 50% then 100% in 3-day windows. 4) Post-deployment: monitor audit-signature-verification-failures < 0.01% and policy-deny spikes. Security notes: - Lease TTL defaults to 10 minutes and is enforced by the KMS gateway. - Signed audit envelopes include a canonicalized provenance block; verification requires access to KMS public handles and the audit public key registry. - RBAC mapper emits explicit deny rules for cross-region/system-operator actions by default. Observability: New metrics: audit_sign_requests_total, audit_sign_success_total, audit_sign_failure_total, rbac_mapper_suggested_assertions_total, rbac_mapper_enforced_assertions_total. Logs include structured fields: operator_id, tenant_id (if applicable), region_hint, kms_ref, signature_id. Backward compatibility: When feature-flag disabled, behavior is unchanged. The mapper can be toggled between simulate and enforce. Rollback: Disable feature-flag and remove signer from routing; audit logs remain intact. Related: ENG-8420 (policy mapping), SEC-119 (audit non-repudiation), SUP-3321 (support request for operator audit tracing).
