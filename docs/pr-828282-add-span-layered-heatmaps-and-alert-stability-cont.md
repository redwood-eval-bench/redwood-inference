# Add span-layered heatmaps and alert-stability controller

This PR introduces a new span-layered heatmap generator and an alert-stability controller to reduce noisy alert churn for token-level cost/latency regressions. Motivation: long-tail token and span-level spikes produce high alert volume; teams need an aggregated, layer-aware view plus a controller that applies temporal smoothing and backoff before firing high-severity pagers. Changes are safe for gradual rollout: feature-flag guarded, dashboard-only by default, opt-in alert controller via SRE config. Key design goals: (1) surface bursty span clusters in a compact heatmap (per-model, per-route, per-tenant), (2) compute layer-aware density metrics (input tokens, KV cache hits/misses, kernel queue durations) so teams can quickly attribute costs, (3) introduce an alert-stability controller that implements hysteresis, minimum-sample windows, and a priority-aware backoff to avoid duplicate noisy incidents. Checklist: [x] heatmap generator + sampler, [x] dashboard panels and drilldowns, [x] alert controller binary + config, [x] unit + integration tests, [x] doc snippets and runbook updates. Rollout plan: stage behind feature flag > enable dashboard for internal SRE > enable controller for non-pager alerts with 24h ramp > expand to wider teams if metrics stable for 7d.
