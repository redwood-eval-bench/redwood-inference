# soft-throttle: reconcile tenant throttles, fast-retry escape, and degraded-standby routing

Motivation: We observed intermittent tenant SLO regressions during throttle-policy churn and brief regional capacity spikes. Two common pain points: 1) tenant throttles are applied asynchronously (policy API -> control-plane cache -> runtime) which leads to short windows where priority queues become unbalanced; 2) client retry storms amplify short throttles and cause knock-on latency spikes. This PR introduces a three-part mitigation: a background soft-throttle reconciler, a fast-retry escape backoff path, and a degraded-standby routing policy for exhausted-tenant cases. Summary of changes: - runtime/throttle: add soft_throttle_reconciler component (periodic reconcile, transient-window smoothing, per-tenant hysteresis) so policy changes converge gently instead of flipping queues instantly - gateway/retry: implement fast-retry-escape (short, jittered client-facing backoff + local token dampener to prevent retries from re-entering the same hot path) - router: degraded-standby route selection that prefers lower-cost model-variants when tenant budget is exhausted but region health is OK - observability: new metrics (soft_throttle_reconciliations_total, fast_retry_escapes, standby_route_falls) and tracing spans for reconcile runs - config/feature-flag: runtime toggle (soft_throttle_reconciler.enabled) and staged rollout parameters - tests: integration test suite (soft_throttle_integration_test) plus unit coverage for reconciler and backoff logic Rollout plan: feature disabled by default. Canary enable in 3 internal namespaces for 48h, verify throttle smoothing metrics and absence of retry amplification, then gradual enable across regions. If SLO regressions appear, toggle off and the reconciler will stop accepting new smoothing windows within 10s. Backwards compatibility: reconciler reads existing policy payloads; no schema changes to API. Related work: ENG-8421 (throttle observability), ENG-8443 (retry-safety), SUP-4467 (customer ticket reporting repeated transient 503s).
