# Length-gradient slot-merging: greedy slot merge to reduce padding and improve KV-cache locality

Motivation: Mixed-length inference workloads incur significant padding overhead and reduce KV-cache locality when the batcher naively groups by arrival time. This PR adds a greedy 'length-gradient slot-merger' batching heuristic that (1) opportunistically merges adjacent pending slots when a cost-gradient estimate predicts net token savings, (2) bias-merges to preserve KV cache locality for recently hot keys, and (3) respects soft-deadlines so latency SLOs are not violated. Design: We compute a small online cost gradient for each candidate merge: delta_cost = padding_cost_change + kv_locality_penalty + kernel-launch-amortization. The heuristic favors merges with negative delta_cost and a small predicted tail-latency impact. To avoid expensive global optimization, merging is done greedily inside a sliding window (configurable, default 150ms) and limited to merging up to 3 slots at once. This minimization targets critical paths: batch padding, kernel occupancy, and KV cache warmness. Changes include: runtime/batcher/slot_merger.rs — core algorithm and new configuration knobs; runtime/scheduler/slot_sim.rs — lightweight simulator used in local microbenchmarks; runtime/kv_cache/locality_tracker.rs — small refactor to expose recent-key hotness; bindings/python/experiments/batcher_tuner.py — script used to sweep heuristics in lab; docs/design/slot_merge.md — design doc and benchmark summary; tests/* — unit and integration tests for merge correctness and soft-deadline enforcement. Benchmarks: In mixed synthetic workloads (80% short <32, 15% mid 128-256, 5% long >1k): median padding tokens per request down 23%, p99 latency (inference tail) improved 12% under steady load, effective throughput +8% at 99% QoS target. KV cache hit rate on prefix-heavy workloads improved ~6pp. CI: a transient flaky test caused one rerun (see checks below) but the PR CI ultimately passed. Backwards compatibility: default behavior preserves current batching when the heuristic is disabled (config flag slot_merger.enabled=false). Follow-ups: (a) integrate with the autotuner to learn merge thresholds per-customer workload, (b) extend to multi-GPU slot placement to reduce cross-device padding, (c) add a lightweight online estimator of kernel occupancy to replace a few static heuristics. References: Linear ENG-7543 (batching roadmap), ENG-7620 (KV cache locality improvements).
