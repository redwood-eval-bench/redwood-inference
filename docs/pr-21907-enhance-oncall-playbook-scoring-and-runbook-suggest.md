# enhance oncall playbook scoring and runbook suggester

Introduce runbook suggester and playbook scoring engine for on-call workflows; safe default policy and feature flag; metrics and tracing added; no config migration required; rolls out to beta by default.
Motivation: on-call triage is noisy: runbooks drift, noisy pages lack clear playbooks, and on-call juniors often pick inappropriate remediation steps. This PR adds a lightweight scoring engine that ranks runbooks by a compound signal (recent pager frequency, SLO breach correlation, MTTA/MTTR history, and operator feedback) and a runbook suggester that surfaces candidate playbooks in Slack when an alert is paged. The goal is to reduce time-to-first-action and provide actionable, readable playbooks in the incident channel.

What this PR does (single string): - Add playbook scorer module (incident_bot.runbooks.scorer) implementing a weighted scoring model and small calibration table; weights are configurable via feature flags and defaults tuned on last-90-days incidents. - Add runbook suggester integration for Slack async actions: suggests 2–3 candidate runbooks with confidence score; supports 'apply' to populate incident template. - Add CLI tool incident-bot oncall-check to detect rotation conflicts and missing overrides; returns machine-readable JSON for infra pipelines. - Add SLO toolkit helpers used by scorer: burn-rate heuristics and incident-to-SLO attribution helpers. - Wire metrics (incident.runbook_suggestions, incident.playbook_score.{bucket}) and tracing spans for end-to-end latency. - Tests: unit tests for scorer, integration tests for Slack suggestion flow, e2e harness against test SLO store. - Docs: README and playbook guidance doc plus runbook-quality examples.

Checklist: - [x] Unit tests added and green - [x] Integration tests for Slack flow - [x] E2E harness run locally - [x] Feature-flag gated rollout implemented - [x] Docs updated with usage and tuning guidance

Backward compatibility and rollout: default policy is conservative (low-sensitivity) and disabled in orgs without SLO metadata. Feature gate: ff.runbook_suggester.v2. Rollout plan: beta -> opt-in on 2 pilot teams -> org-wide after 2 weeks and monitoring checks.

Monitoring and safety: suggestion acceptance rate, false-suggestion rate (manual rejection), and MTTA delta are instrumented. We added auto-fallback to a safe template when confidence < 0.15.

Notes: this PR intentionally keeps scoring simple (linear weights) to make tuning auditable; follow-ups will add a lightweight ML ranker in the slo-toolkit repo once we have stable labels.
