# Smooth-bucket regulator with kernel-affinity and KV-cache sticky scoring

Motivation: observed tail spikes when aggressive length bucketing created narrow bins that oscillated in occupancy across seconds, causing padding variability and kernel inefficiencies. This PR introduces a "smooth-bucket regulator" heuristic that (1) adds temporal smoothing to bucket boundaries to avoid rapid oscillation, (2) integrates a lightweight kernel-affinity estimator so cohorts favor kernels with better throughput for the predominant sequence lengths, and (3) biases placement for requests with warm KV cache to stay in the same cohort (sticky KV affinity) to reduce KV cache churn. The changes are implemented inside the continuous batch composer and scheduling layer; the feature is opt-in behind runtime config 'smooth_bucket_regulator=true' and a guardrail param 'max_boundary_shift_ms'. Implementation summary: we add a BucketRegulator object that maintains per-batcher histogram windows, computes smoothed boundary deltas with an exponential moving average, then rebalances requests into neighbor buckets only when smoothed benefit outweighs reallocation cost (estimated padding reduction minus kernel-switch overhead). Kernel affinity scores are derived from a mini cost-table populated by microbenchmarks run at boot and periodically updated; KV-stickiness adds a small positive score when request metadata indicates a populated KV handle. Benchmarks: internal perf run on c6g.4xlarge-equivalent with Llama2-7B-quantized profile; workloads: mixed chat (50%), short queries (30%), RAG retrieval+answer (20%) simulated from production traces. Results: median token throughput +3.8%, average token cost -6.7%, p95 latency improvement 12% on heavy RAG mixes, padding tokens reduced by ~18% overall for the trace set. Safety & fallbacks: when kernel-affinity table is stale or reports high variance we fallback to classic fixed bucketing; regulator exposes diagnostic metrics (regulator.bucket_shifts, regulator.kernel_mismatch_rate, regulator.kv_stick_hits) surfaced to the console. Tests and CI: unit tests for regulator boundary math and score composition, e2e smoke with continuous batch composer harness and a new micro-benchmark that asserts no regression in cold-start latency. Rolling strategy: merge to main with feature gate off by default; enable in canary pool #5 then progressively to Dedicated pools. Related: this complements ENG-6210 (KV cache eviction smoothing) and supersedes some ad-hoc heuristics introduced in earlier PRs.
