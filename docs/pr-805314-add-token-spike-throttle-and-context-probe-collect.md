# Introduce token-spike-throttle-alert and contextual probe collector

Motivation: We see frequent short-lived token-cost spikes driven by bursty client usage patterns (chatbots with long context resets and batched background jobs). These spikes create noisy alerting and reactive pager churn while not representing sustained customer-impacting regressions. This PR introduces two coordinated pieces: 1) a lightweight probe-collector sidecar service that captures contextual log excerpts, request metadata, and a compact token-delta histogram for a sampled subset of invocations; 2) an adaptive token-spike-throttle alert evaluator that suppresses transient spike alerts using a rate-aware governor and contextual scoring. The goals are: reduce noisy alert firing, preserve high-fidelity context for a representative sample of spikes, and provide operators with a clear explainer and remediation playbook.
What changed: Added a new probe-collector service (small Go microservice) that receives compact invocation probes over an internal protobuf API. Probes include invocation id, tenant id, prompt/response token deltas (aggregated into 4-slot histogram), backoff hints, sampling tags, and up to 3 contextual log excerpts sanitized by the SDK. The collector writes probe bundles to a compressed S3 prefix and emits rollup metrics for sampled spike frequency by tenant and route. The token-spike-throttle evaluator lives in observability/throttle, consumes aggregated token-rate metrics, and implements a leaky-bucket-style governor that: detects short spikes (windowed 1m/5m), estimates marginal cost delta per route, and silences alerts for transient bursts below an operator-configurable budget. We provision a Grafana dashboard (dashboards/grafana/token-spike-throttle.json) showing spike frequency, throttle budget utilization, top offending routes, and a small sampled probe viewer panel. A migration enumerates existing alert subscriptions to add the new throttle policy by default for observability alerts.
Unit tests added for token_throttle evaluation logic (edge cases around burst windows and tenant overrides). Integration harness simulates sampled probe ingestion and validates probe write/rotation to the S3 staging bucket. CI pipeline added a dedicated observability job that runs the probe-collector integration tests in parallel with existing telemetry tests. All checks passed in the last run (lint, unit, integration, e2e smoke).
