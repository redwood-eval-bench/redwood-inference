# Windowed tail-probe federation and rollback budgeting

Motivation: reduce noisy false positives for tail latency regressions during phased rollouts by federating multiple windowed tail probes and budgeting rollback capacity across rollout stages. This PR implements a probe federation controller that aggregates independent tail-probe signals across traffic cohorts, applies temporal windowing with exponential horizon weighting, and enforces a configurable rollback budget so gradual transient spikes don't trigger full rollbacks. The design prioritizes signal robustness for low-traffic cohorts and preserves fast reaction for high-confidence degradations. Changes include a new 'prober federation' service in the canary pipeline, a budget-aware rollback governor, and telemetry hooks for per-cohort probe health and budget consumption. Checklist: 1) implement federation controller and public config surface, 2) add budget accounting and enforcement in rollout engine, 3) add e2e test harness with synthetic traffic shapes, 4) integrate probe metrics into Console dashboards and alerting rules, 5) add unit tests and perf microbenchmarks, 6) update docs and rollout runbook. Testing: added deterministic unit tests for aggregation logic, property tests for budget accounting, and an integration test that runs the canary pipeline with three cohorts (control, alpha-5, beta-1) under injected latency patterns; local perf runs show federation aggregation adds <1.6% CPU on standard canary runner and median probe evaluation time is stable. Backwards compatibility: federation is opt-in via canary configuration and defaults to disabled. Migration: no data migration required; rollout budget is a new optional field on rollout policy. Related: ENG-2142 defines the product acceptance criteria for multi-cohort rollouts; SUP-7782 logs a customer incident where noisy tail spikes caused repeated rollbacks. Notes for reviewers: pay attention to the budget consumption semantics in rollout_controller.go and the edge-case in window weighting when cohort sample count is zero. Introduces an opt-in canary probe federation that aggregates windowed tail probes across cohorts and a rollout rollback budget to reduce noisy false-positive rollbacks. Admins can opt in by setting 'canary.federation.enabled: true' and configuring 'canary.federation.horizonFactor' and 'canary.rollback.budget'.
When enabling federation in production start with conservative settings: minSamples=20, horizonFactor=0.6, rollbackBudget=3. Monitor the new metrics 'canary_federation_score' and 'rollback_budget_remaining'. If you see budget exhaustion without clear degradations, increase minSamples or temporarily disable federation.
