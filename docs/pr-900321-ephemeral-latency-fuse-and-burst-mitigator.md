# Ephemeral latency fuse and burst mitigator

Motivation: recent incidents (SUP-4021) showed short, high-amplitude request bursts plus transient KV cache stalls can push downstream queues into cascading latency spikes. This PR implements a lightweight, ephemeral 'latency fuse' that trips on short-window p99 latency breaches and redirects non-critical/low-priority requests to a graceful fast-fail path while a short stabilization window elapses. Complementing the fuse is a burst mitigator admission controller: it smooths token bursts by granting micro-reservoir tickets per tenant and weights admission by recent success latencies, preventing synchronized retries from amplifying load. The changes are opt-in via runtime flags and can be toggled per-cluster.

What this PR does (single-string description): - Adds runtime/serving components: latency_fuse (ephemeral trip + decay), burst_mitigator (micro-reservoir admission, per-tenant weighted smoothing), integration hooks in SLO enforcer to lower priority for shed traffic and emit new telemetry. - Adds a short hotfix to KV cache eviction path to avoid a race that surfaced under the new admission patterns. - Adds unit + integration tests, e2e canary scenario harness for burst simulation, and docs for operators. - Exposes metrics: rlf_latency_fuse_trips, rlf_burst_tokens_used, rlf_shed_count, rlf_kv_race_workaround. - Adds a sample rollout plan and rollback notes.
