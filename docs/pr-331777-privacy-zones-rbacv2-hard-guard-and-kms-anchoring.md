# Privacy zones: RBACv2 hard-guard, KMS anchoring, and audit delta sink

Motivation: customers operating under strict data residency constraints asked for a first-class "privacy zone" concept that ties RBAC claims, KMS usage, and audit metadata together. This PR implements a zone-scoped RBACv2 hard-guard (policy enforcement instead of best-effort tagging), anchors KMS operations to region-pinned CMKs, and emits a compact "audit delta" sink with zone + key provenance so downstream compliance tooling can prove residency and key-origin. The change is intentionally surgical: the new enforcer is pluggable and gated behind a feature flag (feature.privacy_zones.enabled) and a rolling rollout can be performed per cluster via operator config. Checklist: - Implement zone-aware policy evaluator (RBACv2) that denies requests if zone claim/key mismatch. - Add KMS anchoring middleware to annotates decrypt/encrypt calls with cmk-region and enforcement mode. - Add audit-delta sink that tags audit events with zone, cmk_origin, and enforcement_decision. - Surface policy editor in Console (read-only for GA; edit via YAML for now). - Add unit and integration tests, plus a small e2e scenario using test-kms emulator. Related: ENG-4198 (design doc), SEC-1224 (compliance signoff). Rollout notes: enable feature flag in canary region first; RBAC policy migration includes a one-time background scan that annotates tenants with inferred zone where available. For tenants without a zone, the enforcer defaults to "opt-in" behavior until tenant metadata is set. If the feature is turned on in enforcement mode, mismatches will be rejected and will surface QC alerts. Implementation details: - Enforcer lives in authorization/zone_enforcer.go and plugs into the existing RBACv2 path as an additional policy step; it evaluates the request's tenant_claims.zone, service_region and the configured policy matrix. - KMS anchoring is implemented as a proxy shim (infra/kms/anchor_proxy.py) that consults the configured cmk registry and rejects operations if the requested cmk is out-of-region for the request zone; it emits a KMS_PROVENANCE header consumed by the audit delta sink. - Audit delta sink (observability/audit_delta_sink.go) batches lightweight audit deltas (event_id, zone, cmk_origin, decision, timestamp) which are forwarded to the compliance indexer. - Console adds a new read-only "Privacy Zones" page with a per-tenant summary and policy preview. - Helm/installer additions: new values.privacyZones.* keys and operator RBAC changes for the background annotator. Migration: background annotator will run as a job (k8s) that is idempotent; rollback is safe (feature flag off => enforcement disabled). Security review notes: added extra checks in the KMS proxy to ensure authorization context is preserved; a lint-level security scanner flagged a potential header propagation gap which has been fixed. Testing: unit tests for policy behavior, integration with test-kms emulator, e2e scenario using a synthetic tenant with zone=eu-west. Signoffs: security, compliance, and infra.
