# Introduce heatmap-based warmth curves and quantization fallback orchestrator

Context: Cold-prefill behavior and tenant burst characteristics vary widely across tenants. We introduce a compact heatmap-based "warmth curve" representation to capture tenant prefill affinity over time and request shape, plus a quantization fallback orchestrator that uses those warmth curves plus runtime latency signals to pick a safe quantization profile at inference time. Motivation: reduce per-token unit cost by applying aggressive quantization where safe, while avoiding user-visible latency or quality regressions during bursty or previously unseen traffic patterns. This PR implements the runtime orchestrator, a lightweight heatmap generator, Console + CLI knobs for rollout, and an e2e simulation harness for policy validation.
Adds tenant warmth heatmaps and a quantization fallback orchestrator that selects quant profiles based on prefill affinity and runtime latency signals. New Console controls for rollout and per-tenant opt-out. Telemetry: new prefills/heatmap histograms and quant-fallback events. Default rollout: feature-flagged and disabled for tenants with <30 days of traffic.
