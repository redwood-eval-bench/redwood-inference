# Introduce modular onboarding bundles, credentialed probe harness, and release snapshotter

Background: Onboarding teams frequently deliver model metadata and small auxiliary artifacts in ad-hoc ways (zip/tar plus README). That causes brittle ingestion, inconsistent provenance, and manual changelog drafting. This PR introduces a compact, opinionated 'onboarding bundle' format (manifest + content shards), a credentialed probe harness that signs lightweight acceptance probes for candidate bundles, and a release snapshotter that synthesizes draft changelog fragments to speed curator reviews. Motivation and goals: 1) make onboarding reproducible and reviewable by packaging model metadata, performance profiles, example inputs, and a deterministic manifest; 2) provide a credentialing step so intake prober outputs are integrity-signed and auditable; 3) auto-generate a changelog snapshot (draft) that curators can approve/augment instead of writing from scratch. What changed (high level): - Introduced bundle format: manifest.yaml (schema v1), shards/ (profiles, example_sets, provenance.jsonl), and a signed.meta (signature + public-key hint). Bundles are tarred with a .rwbundle extension. - intake service: bundle ingest endpoint and validation layer (lightweight schema validation, size limits, deterministic ordering). - credentialed probe harness: runs configured sample probes inside a sandbox, produces signed probe results (probe-record.json) and an integrity proof pushed alongside the bundle. The harness can operate in ephemeral mode (CI) or signature mode (trusted operator key). - release snapshotter: a service that takes an onboarded bundle and synthesizes CHANGELOG-draft.md with a short human-friendly blurb, perf delta bullets (if profiles present), and a machine-readable release-snippet.json for downstream release automation. - CLI helper: rwbundle pack/unpack/inspect and rwbundle sign --key <kms-ref>. Migration and rollout: - Backwards compatible: bundles are optional; existing intake paths continue to accept raw metadata. The intake API will emit a 'bundle_suggested' hint in the intake metadata to encourage adoption. - Stage rollout: feature flagged behind ONBOARD_BUNDLES for 10% of intake traffic for two weeks, then 50%, then wide. Tests and quality: - Unit tests for manifest schema, ordering, and signature verification. - Integration tests: end-to-end pack -> probe -> ingest -> snapshot generation in the eval-harness environment. - Added example bundles to examples/onboard-bundles/ for QA and docs. Checklist: - [x] manifest schema and validator - [x] tar packing/unpacking CLI - [x] probe harness + signer - [x] intake endpoint + acceptance tests - [x] snapshotter changelog drafts - [x] docs: quickstart + format spec - [x] basic telemetry (bundle accepted/rejected, probe pass/fail, snapshot generated)

Monitor telemetry: onboarding.bundle.accepted, onboarding.probe.signed, onboarding.snapshot.generated. Rollback: disable flag and delete scheduled async verifications.
This PR bundles three coordinated pieces: a formal .rwbundle format for onboarding artifacts, a probe harness that cryptographically signs probe results, and a snapshotter that drafts changelog snippets. It aims to reduce manual curator work and improve intake provenance while remaining backwards compatible.
