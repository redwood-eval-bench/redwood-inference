# Introduce RBACv2 temporal constraints, KMS consent queue and audit fidelity meter

Motivation: production incidents showed operators with long-lived elevated RBAC grants were able to make cross-region KMS requests outside configured residency windows; audit logs lacked a clear fidelity score for post-hoc forensics. This PR introduces three coordinated pieces: 1) temporal constraints on RBACv2 bindings (time-limited grants and enforceable lease windows), 2) a KMS consent queue that gates cross-region CMK usage for operator/scoped tokens (rate-limited, consent-evaluated requests with fallback), and 3) an audit fidelity meter — lightweight signal attached to audit events indicating completeness/confidence for downstream retention/forensics. Summary of changes: - rbac/api: added TemporalGrant type (+validation, TTL enforcement, and renewal endpoints). - auth/lease: implement per-binding lease lifecycle and automatic short-circuiting when operator session exceeds lease. - kms/consent-queue: new sidecar-like inbound queue that records consent decisions, enforces backpressure, and emits metrics when requests are deferred. - audit/annotator: attach fidelity score and provenance tags to audit events; wire into existing log-forwarder. - config: new operator_policy config sections, feature flags, and migration utility to convert long-lived grants to temporally bounded leases. Impact: non-breaking by default (feature gated), migration tool recommended for orgs with legacy long-lived operator bindings. Rollout plan: feature-flagged rollout -> staged canary on dedicated clusters -> widen to hosted after 2 weeks of metrics stability.
