# add-observability-multiplexor-and-token-context-anchors

Context and motivation: We see growing noise and duplication in telemetry pipelines as traces, metrics, and logs fan out to different consumers. This PR introduces a lightweight observability multiplexor (telemetry_mux) that centralizes routing of telemetry events to destination-specific enrichers and exporters and adds a compact token-context anchor enricher to attach precise per-invocation token cost/latency metadata to spans and metrics. Goals: 1) Reduce duplicate instrumentation across subsystems by providing a single ingestion entrypoint; 2) Enable contextual token-level anchors for cost/latency attribution without changing existing call sites; 3) Provide a dashboard-ready JSON panel that surfaces token-attributed timelines and dominant-kernel hotspots. Design summary: telemetry_mux receives events via the existing internal event bus, applies destination routing rules (observability.consistent hashing + priority overrides), and invokes registered enrichers in a deterministic order. The token-context anchor enricher attaches a small deterministic anchor payload to spans and metrics: {token_count, tail_percentile_marker, cost_est, kernel_hint}. Anchors are encoded as sparse labels to avoid cardinality explosion; downstream rollups and the new dashboard panel interpret anchors to show per-invocation token slices and cost allocation. Backwards compatibility: default routing mirrors previous behavior; enrichers are opt-in per-route via feature flags. Checklist: implement mux and enricher; add registry API to register enrichers; add dashboard panel; add e2e tests and playbook; document rollout and kill switch. Testing: unit tests for mux routing and enricher serialization; e2e test that verifies anchor roundtrip through exporter to dashboard; load test at 2x production to validate overhead (<2% p50 latency impact). Rollout plan: feature-flag behind ops toggle, staged rollout by region, monitor token-latency delta metric and revert if >5% increase. Related work: builds on ENG-1427 telemetry consolidation spike and references PM-319 observability UX ask.
