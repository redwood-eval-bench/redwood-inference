# Introduce telemetry-driven synthetic load generator and hyperops for batch profile autotuning

Problem: Production telemetry indicates wide variance in per-customer request shape (seq lengths, prompt/templates, temperature) which makes static batching defaults suboptimal. We need a way to synthesize representative load from existing traces, run lightweight microbenchmark passes, and generate conservative batch/cache/quantization profiles that are safe for rollout. This PR implements a telemetry-driven 'synthetic-econ-proxy' tool plus runtime hyperops that drive an autotuner. Goals: 1) generate reproducible synthetic streams from sampled traces, 2) run a fast hyperparameter sweep for batch sizes, microbatch windows, and cache TTLs in a sandbox mode, 3) attach a compact 'handoff' metadata blob to candidate profiles for safe staged rollout and automatic rollback. Key features: - synthetic-econ-proxy CLI: consumes sampled telemetry (p50/p95 seq distribution, client headers, model family) and emits a deterministic request stream for local or staged perf runs. - hyperops runner: lightweight orchestrator that runs short trials across candidate batch/microbatch/kv-cache policies and collects cost/latency metrics. - profile handoff format: single-line compact metadata (versioned tag, checksum, compatibility hints, suggested fallback) used by the runtime to decide compatible rollouts. - safety: candidate profiles are generated with conservative SLO buffers and include automatic fallback to prior profile on SLA regressions. - developer UX: preview command (redwoodctl perf preview --profile <file>) that replays the synthetic stream against a chosen model variant and prints unit economics estimates. Motivation and context: This is an engineering-first approach to reduce human iteration when choosing defaults for new customers or workloads. Rather than relying on a single scoring heuristic, we synthesize a workload closest to the customer's telemetry and run a controlled sweep to find economically sensible defaults. See linked Linear items and test harness in the commits.
