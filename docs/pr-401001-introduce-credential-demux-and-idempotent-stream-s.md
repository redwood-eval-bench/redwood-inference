# Introduce credential demultiplexer and idempotent stream shims across SDKs

Summary: Adds a credential demultiplexer (cred-demux) abstraction and idempotent stream shims to Python/TypeScript/Go SDKs so applications can declare multiple credential sources (env, file, delegated token provider, instance metadata) with ordered fallback and safe stream resume semantics. Motivation: teams frequently run into brittle auth wiring in hybrid environments (local dev + CI + k8s + dedicated hosts). This PR reduces onboarding friction by centralizing credential selection logic, exposing a compact DSL for fallback order, and making streaming consumer code more resilient to reauth/reconnect so retries are idempotent and safe for common server-side at-least-once behaviors. High level changes: - Introduce sdk-common/cred/demux: core demux implementation and a small policy language (priority lists + hintable time-to-live) - Python: sdk/python/redwood/auth/demux.py + adapters for AsyncStream and legacy callback streams; public API: RedwoodAuth.demux and AuthPolicy - TypeScript: sdk/typescript/src/cred/demux.ts and a StreamResumeShim that returns async iterators which replay idempotent markers - Go: sdk/go/cred/demux.go and stream middleware that implements ResumeToken + idempotent-write guards - Unified changes: updated examples, integration tests, doc pages (docs/sdk/auth.md), and changelog entries - Version bumps: python 1.12.0, typescript 2.5.0, go 1.8.3 Design notes: - The demux is intentionally minimal: it evaluates providers top-to-bottom until a valid credential is returned, supports soft-fail vs hard-fail modes, and emits telemetry hooks (cred.provider, cred.latency, cred.result) so platform teams can tune fallback order. - The stream shims add a small ResumeToken that SDK servers will echo as an idempotency marker. Consumers will keep last-committed token and attempt resume; the shim guarantees at-most-once client-surface semantics for common generator/resume patterns via small local buffering and sequence checks. - Backwards compatibility: existing credential providers continue to work; the demux is optional and can be enabled via a single constructor flag or environment variable. Tests and CI: added unit tests for each SDK (python: tests/auth/test_demux.py, ts: test/cred-demux.spec.ts, go: cred/demux_test.go) plus an end-to-end playground harness that spins up a minimal echo server and validates resume semantics under temporary token expiry. CI initially failed on TS lint (line-length) and an intermittent go test that relied on wall-clock-sensitive timing; fixed by tightening retries and adding a small test harness sleep. Review summary: see review_comments field for the conversation. Migration guidance: - For most apps: replace bespoke provider-chains with RedwoodAuth.demux([Env, File, DelegatedProvider]) and enable stream resume in the generator consumer. - For high-security environments: set demux to hard-fail mode so missing credentials surface immediately. Documentation: docs/sdk/auth.md includes code samples for Py/TS/Go, a troubleshooting section for credential ordering, and a note about telemetry keys. Related tickets: ENG-3859 (reduce SDK auth friction), SDK-1121 (stream resume parity). Merge: squash-merged into main on 2025-01-16 by Elena Park.
