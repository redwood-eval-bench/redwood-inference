# Introduce ensemble disagreement ledger and auto-suggest repair CI hook

Context and motivation: Production prompt sets occasionally regress not because a single model fails but due to growing disagreement across an ensemble of models or model variants. Existing eval gates report regressions but do not capture persistent cross-model divergence or provide actionable remediation suggestions.
What this PR does: 1) Ledger: adds a compact ledger schema (sharded by prompt fingerprint) to store timestamped model outputs, tokenized similarity metrics, and a normalized disagreement score. The ledger supports incremental writes and a TTL-based compaction policy. 2) Aggregator: implements a rolling-window disagreement aggregator that produces smoothed "semantic-slope" and spike detectors, with tunable sensitivity and cohort bucketing. 3) CI adapter: integrates a new ci/adapter that consumes ledger snapshots at CI time, computes per-prompt escalation level, and annotates PR checks with inline prompt-level diagnostics. 4) Auto-suggest repair: when disagreement passes the soft threshold, the hook computes minimal localized perturbations (paraphrase narrowing, guard tokens, or explicit instruction anchors) and posts suggested prompt edits as a machine-authored comment and as structured suggestions embedded in the CI artifact. Suggested fixes include paraphrase examples and a confidence score derived from ensemble consensus. 5) Soft-fail strategy: default CI behavior is to mark the check as 'soft-fail' (annotation-only) and include an auto-suggest badge; maintainers can opt into hard-fail escalation after N consecutive CI runs where suggestions were not applied. 6) Tests & docs: adds unit/integration tests and an ops doc describing config knobs and rollout plan.

Code style and architecture notes: The suggestor uses a lightweight constrained paraphrase sampler and a pairwise scoring model to rank repairs; it is intentionally conservative (prefers guard tokens and instruction anchors over aggressive rewriting).
Observability: CI annotations include per-prompt timeline sparklines, consensus delta, and suggested edit diffs.
Security and privacy: all stored outputs are configurable to be hashed or redacted; default ledger stores tokenized fingerprints rather than raw outputs.
Edge cases & limitations: will not attempt repair for prompts marked immutable by owners; suggestions are heuristics and should be reviewed by humans before broad rollout.
