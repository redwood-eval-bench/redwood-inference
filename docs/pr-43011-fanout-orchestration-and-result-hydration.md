# fanout orchestration and result hydration for multi-tool executions

Motivation: customers are composing multiple tools (search, exec, db-read) in a single turn and need predictable ordering of injected results in streaming mode, bounded latency under partial failures, and clear integration with the OpenAI-compatible call surface. Summary of changes: add a lightweight FanoutConductor in the runtime dispatcher that orchestrates parallel tool invocations, collects results, and performs deterministic hydration of tool outputs into the token stream or final structured payload; introduce a retry policy abstraction with idempotency hints for tools; extend the OpenAI-compat layer to accept concurrent tool call arrays and a new 'structured_output_mode' flag (loose|strict) for validating injected payloads; expose a small SDK ergonomic helper in TS/Python to declare multi-tool call graphs and per-tool retry semantics. Design notes: the conductor issues concurrent requests with a soft concurrency cap per-request, tracks tool-level idempotency tokens and causal ordering metadata, and can emit partial injection updates to the streaming wire when downstream clients opt into "hydration streaming". Retires the previous ad-hoc injection code paths in runtime/exec and replaces them with a single deterministic merge function that preserves declared call order unless explicit reordering is requested. Compatibility: OpenAI-compatible responses continue to work with single-tool call patterns; when callers submit multiple tool calls using the new array form, the compatibility shim will translate old fields to the new structure and set structured_output_mode=loose by default. Migration and rollout: feature gated behind runtime flag fanout_conductor (disabled by default for enterprise Private installs); gradual rollout to hosted fleet with canary on 10% traffic, monitor token-latency and injection-error-rate dashboards. Testing: added unit tests for conductor state machine, end-to-end integration tests exercising streaming hydration, and chaos tests that simulate partial tool failures and network flakiness; added doc examples and a migration note.
