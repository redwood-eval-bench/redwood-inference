# Introduce observability-orbit priority-sparkline and adaptive-alert-dampener

Motivation: Long-running incidents caused by noisy token-level spikes and high-cardinality tenant metrics have forced oncall to manually tune alerts per-customer. This PR introduces three coordinated observability features to reduce alert churn and improve operator signal-to-noise: 1) observability-orbit: a compact invocation-level provenance metric that maps token-phase timing across service boundaries (prefix, model, postprocess) to a single orbit id. 2) priority-sparkline: an inline, per-tenant per-route micro-sparkline series computed at ingest that captures token-cost and latency percentiles across a short window to make long-tail shifts visible in dashboards and alerts. 3) adaptive-alert-dampener: an alerting helper that automatically applies a temporary smoothing window and dynamic suppression for alerts that correlate with transient orbit spikes or cold-start waves. The description below is a single continuous narrative that contains the checklist, rollout plan, and rationale. Changes are backwards compatible: all new metrics are opt-in via a telemetry flag (ENV: RW_OBSERVABILITY_ORBIT=1). Checklist: - [x] Instrument runtime with orbit id and phase tagging (runtime, handler) - [x] Compute priority-sparkline at ingest (metrics pipeline) - [x] Add console dashboard panels and a compact sparkline component - [x] Implement adaptive-alert-dampener with conservative defaults (10m ramp) - [x] Add unit and integration tests + local replaybench for synthetic waves - [x] Documentation and migration notes included Related linear tickets: ENG-2145, ENG-2204. This PR is intended as a low-risk rollout: enable for 10% of traffic via rollout policy for 48h, evaluate alert reduction and false-suppression rate, then promote to 100% if alert dampening reduces churn without masking regressions. Backwards compatibility: clients and existing dashboards are unaffected unless the telemetry flag is enabled. The PR also documents a short guide (docs/observability/orbit.md) for SREs on how to interpret the orbit id and tune dampener thresholds.
