# Introduce load-stencil smoothing and degenerate-fallback coordination to prevent cascade reroutes

Context: During a regional KV pressure incident we observed a pathological interaction where the lightweight per-tenant load-shedder would aggressively trim inflight requests while the region-level circuit manager simultaneously flipped routes to a cold fallback path, causing amplified latency spikes and client-facing 5xxs. This PR introduces a small, conservative 'load stencil' window that smooths decision signals across the shedder and the circuit manager so they make coordinated, non-overlapping transitions; it also hardens the degenerate fallback path so requests routed there are replay-safe and don't trigger additional cross-region cold-path escalations. Changes include: 1) new load-stencil sampling + decay in runtime/shedder to avoid step changes under short spikes; 2) an explicit coordination handshake between shedder and circuit_manager via a transient token to avoid double-shedding; 3) safe-mode guards for the degenerate fallback route that force KV-drain-first semantics and short-circuit certain retries; 4) telemetry additions (metrics and tags) to track stencil window occupancy and handshake failures; 5) an opt-in canary gate and rollout script for Dedicated customers. Motivation: prevent cascade reroutes and reduce observed 5xxs during short-lived KV pressure events while preserving latency SLOs for best-effort tenants. Testing: unit + integration tests added; synthetic load test run in benchmark-lab reproduces previous failure and demonstrates >70% reduction in transient 5xxs and stable P95 latency under the same spike. Rollout plan: deploy to staging cluster behind feature flag, canary 5% in us-west, monitor the new metrics for 24h, then 25%/50%/100% over 3-6 hours with automatic rollback if handshake-failure-rate > 1% or P95 delta > 25ms. Related: SUP-4312 incident notes and postmortem fragment included. Notes: this is intentionally conservative (small stencil windows, handshake TTLs) to avoid long-lived tenant unfairness; future follow-ups will explore dynamic stencil sizing and per-tenant tuning.
