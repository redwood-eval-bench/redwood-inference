# Introduce temporal KMS lease and audit watermarking to strengthen residency guarantees

Motivation: Customers running Private/Dedicated deployments and enterprise accounts asked for stronger, provable controls that tie KMS usage to tenant+region with minimal operational overhead. This PR implements a time-bound KMS lease concept (short-lived wrapped keys provisioned per-request or per-session) and an audit "watermark" header model so downstream audit pipes can assert ordering and detect replay/dedup during cross-region forwarding. The change bundle includes: (1) a KMS lease manager (controller) that issues region-scoped ephemeral wrapping keys (lease TTLs configurable by tenant policy), (2) KMS selection policy updates to prefer same-region CMKs and fallback rules (with explicit audit reasons), (3) RBAC v2 policy hooks to gate issuing leases for service accounts and delegated roles, (4) audit watermark header additions (+ sanitizer) and an audit-normalizer service hook that attaches stable watermarks before forwarding to long-term retention, and (5) compatibility shims for Private installer so on-prem customers can opt into hardware-backed lease store (HSM/KMS) or use a soft-lease fallback. Design summary: - Temporal lease: lease_id, issued_at, expires_at, region_hint, tenant_id, signed by platform KMS. Leases are short-lived (default 5m) but configurable per-tenant via policy. - Lease enforcement: serving runtime requires a valid lease for any operation that requests a tenant-scoped CMK. When expired, the runtime attempts transparent rotation (new lease) and logs a lease-refresh audit event. - Audit watermark: deterministic monotonic watermark per-tenant per-region derived from a HMAC of (tenant, region, epoch, sequence) and sequence stored in the audit-normalizer; attached as X-Redwood-Audit-Watermark to outgoing audit events. Watermarks enable downstream receivers to perform order verification and detect duplicates in eventual-consistent multi-region pipelines. - RBAC changes: new RBAC v2 action 'kms:issue_lease' and principal constraints to limit which service accounts can request cross-region leases. The RBAC evaluator now supports temporal constraints (allow only if request_time within tenant-window) and attribute-driven policy checks. - Fallback rules: if same-region CMK unavailable, policy determines whether to: deny, use geo-fallback CMK with explicit audit reason, or encrypt with a tenant-scoped ephemeral wrapping key stored in soft-lease cache (encrypted with platform CMK). Rollout plan: staged rollout with feature flag 'temporal-kms-lease' and 'audit-watermarking' scoped by tenant. Start with internal tenants -> pilot customers -> gradual opt-in across regions. Backstop: if lease issuance fails, system falls back to existing (pre-PR) behavior and emits an alert (SLO-backed). Checklist: - [x] KMS lease controller implementation - [x] Serving runtime lease enforcement and transparent refresh - [x] RBAC v2 policy additions + evaluator tests - [x] Audit watermark header + normalizer hook - [x] Private installer compatibility shims - [x] Integration tests with mock KMS and audit-forwarder - [x] Documentation (security/compliance notes + migration guide) Testing notes: unit tests for lease lifecycle, end-to-end with local KMS emulator, integration tests for cross-region fallback. Load testing: brief perf pass showed ~1.8% median latency regression in cold-lease path; warm-cache path unchanged. Migration & compatibility: operator can configure tenant.policy.kmsLease.ttl and tenant.policy.kmsLease.allowCrossRegion; default behavior preserves current semantics until tenant opts-in. Related: ENG-4723 tracks policy UX for per-tenant TTLs; SUP-3421 captures a customer support case that motivated explicit audit reasons for cross-region fallback. See compliance/security docs for migration steps.")
